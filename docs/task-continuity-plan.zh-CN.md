# 多轮研究接续改进计划

[English](task-continuity-plan.md) | [简体中文](task-continuity-plan.zh-CN.md)

2026-10-21。范围是通用产品缺陷和执行接续，不收入私人研究的稿件、任务、反馈或其改写样本。测试使用独立构造的最小任务。实施阶段与发布分开；后续获准发布的内容见 [v1.4.0 发布说明](releases/v1.4.0.zh-CN.md)。

| 顺序 | 工作 | 验证与完成依据 |
| --- | --- | --- |
| 1 | 保存时校验阅读要求；区分导入审阅、自审和真实调用；统一文档 | 非法批次不部分写入；导入耗时不计作模型耗时；旧调用兼容 |
| 2 | 在现有保存接口中支持当前主稿和 brief 局部更新；状态返回实际实现身份与接续位置 | 新主稿不继承旧交付；章节稿不抢占主稿；恢复能够找到当前要求和未结事项；读取不修改历史 |
| 3 | 接续说明覆盖反馈落实、全文比较、局部修订和旧任务恢复 | 修改以正文为准；合法复用不篡改旧审阅绑定；旧任务不补造历史、不强制换模式 |
| 4 | 独立构造通用语义诊断和三种使用方式的比较协议 | 区分硬条件与语义质量；保留事实条件与决策机制；允许撤回批评和不修改；未运行的模型评测明确标记 |
| 5 | 审阅改动、执行受影响的契约检查、同步插件包 | 兼容旧接口；无平行台账、额外必填项和新增语义门槛；记录实际验证与限制 |

## 取舍

当前要求使用既有稳定 ID，已接受但未核验的修改保持开放。当前正文使用显式登记，不按目录时间推断。正文、输入与实际审阅继续使用原有绑定规则；不新增自动语义通过或后台监控。

项目约定仅覆盖恢复、实质修改和交付三个环节，放入通用文档供项目入口引用，不复制完整规范。不要求每次改字维护记录。方法模式仍然有效；不调用 CLI/MCP 不能单独认定为违规。

代码测试证明接口、保存与绑定行为；构造的语义诊断不等于已经测出质量收益。模型比较应在相同模型、资料和任务条件下分别运行原生执行、方法模式、方法配合工具，保留首次输出；测量要求遗漏、事实越界、修改落实、无必要返工和可取得的用量，不以文件数或 PASS 数代替收益。未用于调整提示的独立任务留作后续检查，不将公开开发样本称为盲测。

## 不做

不加入私人案例或脱敏副本，不新建反馈平台，不建立大禁词表，不固定多模型审阅，不自动整理所有历史目录，不复制旧凭证批准新文件，不为观察统计增加交付门槛。

## 执行记录

基线：1.3.3，开始时工作区干净。五阶段代码、文档和本地验证已执行，插件副本已同步；没有修改版本号或发布。具体结果见[验证记录](task-continuity-validation.zh-CN.md)，独立审阅与修复见[审阅记录](task-continuity-review.zh-CN.md)。

## 为什么会脱节，以及项目层面怎样约束

方法要求不会自动拦截直接写文件。任务转入连续写作后，Agent 可能只更新新稿和对话说明，已有规格和记录仍然可读却已过期；后保存的章节又可能被误作主稿。旧入口还会让已经实现的接续能力没有被采用。这些是不同层面的问题，不能都归为校验器故障，也不能靠再增加一张表解决。

本轮把常见修改接入原有保存操作，并使接续查询给出当前有效位置；项目入口只需引用短约定，在恢复、实质变化、交付三个环节执行。谁更新了正文，谁核对相关要求是否仍一致。代码能阻止已登记主稿误用旧交付、无效保存及部分写入，不能证明 Agent 已理解材料或落实意见。正文核对和语义审阅仍由执行者负责，项目约定也不能保证宿主一定执行。

旧入口的实际安装升级、私人历史任务迁移和长周期盲测不在本轮执行范围。保留原件的恢复方法和入口身份检查已经提供，不自动升级用户环境；新增通用诊断先验证结构。实际模型试跑覆盖三个简短任务，不把它当成长任务效果证明。

## 问题覆盖与具体落点

| 问题 | 本轮处理 |
| --- | --- |
| 实际入口与版本不明 | `task_context.runtime_identity` 返回本地实现和入口摘要，不冒认宿主加载情况；复用既有安装比较 |
| 主状态、正文与后续要求脱节 | `research_save.brief` 同步规格与进度；`draft.main` 显式登记；`status.current_work` 提供恢复位置 |
| 后保存的章节误作主稿 | `record_changes` 优先定位已登记主稿；未登记的旧任务维持原行为 |
| 旧交付被当成新稿通过 | 主稿变化转入修订；审阅与完成核对主稿路径；旧凭证不改写 |
| 接受反馈与实际落实混淆 | 沿用要求和 finding disposition；接续指南及评阅提示要求核对实际文本 |
| 评阅结束与被评稿修复混淆 | `draft.kind` 表明本任务对象；指南要求区分评阅交付与正文修复，未请求的修复不自动扩成任务 |
| 比较说明冒充全文比较、已提供附件被认定缺失 | 指南要求读取两份实际正文并检查已提供位置；独立诊断覆盖两种失误 |
| 新要求使旧的有效目标丢失 | 复用稳定要求 ID 和用户范围决定；诊断检验部分取消、保留其余目标 |
| 压缩、合并和改写削弱推理 | 独立诊断检查机制、事实限定、归属和决策理由；不用术语出现次数判质量 |
| 自审冒认独立审阅 | 保留已有独立契约；区分统计类别，不新增替代凭证 |
| 局部修订重复全量研究，或局部通过冒充全局 | 复用 `revision=true` 与完整冻结输入；明确有效基线和缺失基线的不同处理 |
| 重复旧批评、强迫统一表达、无必要重写 | 评阅提示和诊断保留 optional、撤回批评和有依据的 no-change |
| 虚构内部资源、以任务分派代替分析 | 通用语义诊断与写作接续约定，不固化具体报告结构 |
| 手工旧状态和分散材料 | 文档给出局部恢复方式；原件保留，不补历史、不另建迁移平台 |
| 写入和读取校验不一致 | 保存时验证阅读要求及来源 ID 配对，批次失败回退 |
| 导入耗时和次数冒作模型调用 | `run_observation` 分开导入、调用和自审，导入不计入调用重试和 token 合计 |
| 过时工具数及可选记录表述 | 双语 usage 和聊天入口同步 |
| 增益、减益缺乏实测 | 三种方式使用同一组独立构造任务；保留首轮输出、用量与限制，不宣称普遍收益 |

具体测试、模型观察、独立审阅及未验证项见[验证记录](task-continuity-validation.zh-CN.md)。
