# 版本与兼容性约定

[English](compatibility.md) | [简体中文](compatibility.zh-CN.md)

## v2 完成契约

v2 保留统一研究入口和现有 Skill、CLI、MCP、插件形态。实质变化在完成契约：基础内容视角分别独立审阅，独立审计和最终验收必需完成；作者自评或合并视角结果不能代替。这改变了早期的完成行为，因此使用主版本升级。

复用已有公开操作名称、来源、主张、要求与成果格式，宿主原生任务和交接扩展这些操作。继续支持 Python 3.10+、`research-toolkit` Skill 名称和软件包入口。

## 接续已有工作

继续研究前保留任务目录、原报告、评审回复、输入快照和回执。通过 `status` 读取当前工作，复用来源、分析、稳定编号和仍有效要求。旧完成稿保持原样，接续稿另存。

未修改的历史完成记录按当时契约查看，不追认成 v2 已验收。为新交付继续研究时，准备当前版本审阅，补齐独立角色和仍缺失的实质工作。不为复制记录重建任务，不将作者检查重新标成独立审阅，不补造未发生的执行。

历史 `lite`／`full` 值和旧返回字段继续作为兼容数据读取。新研究只有一个入口，旧参数不能选择较轻的完成契约。不再满足完成条件的旧请求形式，应得到明确说明，不静默通过或删除原数据。

## 公开兼容边界

文档记载的 CLI／MCP 操作名称、参数、返回字段及退出含义属于公开接口。可新增可选字段，客户端应容忍不认识的可选返回字段。删除受支持入口、改变字段类型或含义、收紧已经承诺的完成契约，均属不兼容变化。

内部辅助函数和诊断文案可以调整。工程修复可以拒绝文档契约原本不允许的输入。输入变化仍按来源和版本关联处理；只更新安装版本不会改写已完成研究或自动重跑历史对照。

## 版本号与更新

采用[语义化版本](https://semver.org/lang/zh-CN/)：

| 类型 | 用途 |
| --- | --- |
| 补丁，如 `2.0.1` | 兼容的问题修复、说明澄清和打包修正。 |
| 次版本，如 `2.1.0` | 兼容的新增能力。 |
| 主版本，如 `2.0.0` | 公开兼容承诺变化，同时说明受影响行为与接续方式。 |

更新完整安装包并保留任务数据。发布时根目录 `VERSION`、插件清单、打包版本及中英文发布材料一致。标签和历史评测记录保持原身份，数据集仓库使用各自的版本序列。

原 1.x 兼容基线始于 1.0.0，保留了 v0.2.7 的任务行为。既有 1.x 版本仍可从原标签取得；本页不改变这些历史运行实际发生的事情。
