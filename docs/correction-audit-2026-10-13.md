# October 13 project remediation and coverage

[English](correction-audit-2026-10-13.md) · [简体中文](correction-audit-2026-10-13.zh-CN.md)

Research Toolkit gives an existing agent research methods and executable support for keeping the brief, interpreting evidence, writing, reviewing and delivering a useful result. Its evaluations identify concrete failures to improve those methods and tools. A repaired report is one case of that work. **R01–R13 belong to the single pipeline report; they are not thirteen reports or project-wide acceptance.** The earlier v0.2.6 statement that the requested project corrections were closed was too broad. This page replaces it with the actual product changes and collection scope.

All existing and future user tasks, development tasks, reference tests and cases are real independent tasks; executed tests are real tests. Repeated runs keep their task identity. Source provenance and use are recorded directly. Astra in a context separate from the author can review independently, including when both roles use the same model. No outside person, vendor or material is required. Changed assignment, review input or acceptance requires targeted revalidation.

## Handling failed results

Locate the actual source, instruction, report or code defect; fix the reusable cause and the authorized deliverable; recheck the changed version on relevant old tasks and add a new task when it exercises an uncovered behavior. Retain the original failure. A reviewer’s unsupported suggestion gets a reasoned no-change decision. Repeatedly scoring unchanged work until it passes is not a repair.

Historical ZIPs retain original transcripts, code and execution outcomes. The current entrypoints state the policy above and map the exact archive contents. This correction concerns current methods, runtime, generated inputs, inventories and their affected verification; it does not reclassify every historical report as correct or establish a general effect size.
