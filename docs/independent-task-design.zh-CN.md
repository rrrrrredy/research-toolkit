# 独立任务与未来留出研究

[English](independent-task-design.md) · [简体中文](independent-task-design.zh-CN.md)

现有五个开发任务族和四个评审校准题族都是公开开发材料，方法修改后也不会变成未暴露数据。[任务准入契约](../evals/templates/heldout-intake.json)定义下一项研究的交接要求，当前**没有已准入任务**，不代表外部数据集已经完成。有界开发周期之后，正式效果研究须另行决定执行范围。

## 分工与访问

1. 先固定方法提交和指令哈希，再给独立任务编写者下达任务；只提供目标工作负荷、语言分层、来源权利要求和时间边界，不提供已观察到的工具箱胜负、候选报告、调参指令或开发参考答案。新的模型上下文是一项可声明的编写边界，不能证明思想或训练数据独立。
2. 指定保管者，将完整题面、来源、必要判断和合理替代答案与方法开发隔离。记录编写身份、日期、访问事件和每个被排除候选在结果出现前的理由。实现者不能把自己编写或已用于调参的题目重标为外部留出集。
3. 作者输出产生前，按来源充分性、真实需求约束、必要判断的清晰程度及可发布的来源记录准入。允许合理替代方案和明确不确定性，参考答案不是唯一可接受文风。领域重叠不必自动排除，但复用事实、翻译和改写继续沿用原任务族身份。
4. 封存已准入输入的哈希和队列顺序。方法冻结前被开发者看过的材料保留暴露记录，转入开发池；生成开始后发现题目错误，保留题目及原结果作为输入缺陷证据，不静默替换，也不把替换题当成同一个留出检验。

## 调用前冻结的设计

先明确要检验的是缺陷识别、读者实用性、实时来源研究，还是工具箱的因果效果。两组作者使用相同模型、来源／检索权限、输出协议、请求思考强度和上限；工具箱额外指令 token 是资源差异，应披露。固定来源、单次指令的 Lite 试验不检验检索能力、持久来源台账、Full 审阅或长流程。

根据期望精度和任务族层面的不一致率说明样本量依据，不能用看起来较大的模型—任务对数量代替。可用开发结果规划，但必须在看到留出结果前固定新样本量。语言、作者模型、重复和互换是分层或敏感性检查，不增加独立任务族。已准入执行失败保留在分母中，同时报告完整对结果与缺失情况，不给缺失稿件编造质量分。

若按[当前报告评测标准](report-evaluation-standard.zh-CN.md)提出效果主张，须预先声明其四评审面板及校准，排除各报告的作者模型。四家 API 作者模型与 Astra 可用时，每个作者层可将其余三家 API 加 Astra 作为候选面板，但仍须单独完成校准、预算及可用性检查。这些模型的判断仍可能相关，一致不等于真相。仅用 Astra 的开发诊断不等于正式四评审面板。

评审在新上下文中接收相同题面、来源、量表和原样 A/B 正文，看不到作者身份、条件、notes、清单、预期判断和执行元数据。结果出现前固定随机化、主顺序、互换、解码、失败处理及依来源裁定的方法。披露残留的条件线索，不在看到稿件后清理这些线索。

分别为作者、全部评审顺序和校准列出准确的请求／token／时间计划。固定停止规则：在已准入有界队列完成或有记录的运行中止时停止，保留部分运行；不自动付费重试，不按胜负追加样本，不挑选有利顺序。正式质量结论需要依据来源裁定，并在任务族层面报告不确定性。

## 验收与当前边界

分工、记录、冻结条件和验收规则可审查时，设计交付完成。只有实际具备独立编写、来源权利及访问记录，数据收集才算完成；只有保留并分析全部已准入首轮尝试及失败，执行才算完成。空白契约刻意不能交给仅支持暴露开发材料的 schema 2 执行器。当前文档不得将其计为额外任务或留出效果证据。
