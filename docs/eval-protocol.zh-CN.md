# 盲评配对试验协议

[English](eval-protocol.md) · [简体中文](eval-protocol.zh-CN.md)

**状态：[四模型、五个任务族的开发试验](../evals/studies/2026-10-10-lite-four-models/README.zh-CN.md)已有原始尝试及评审。** 它使用明确声明的原生 CLI 评审适配器，另行记录事后格式补充分析。历史 n=2 开发对照的效力判断仍未盲评，两题均先运行 Toolkit 组，公开记录未完整证明模型与 brief 匹配；普遍质量优势尚未得到证明。

## 问题与范围

针对 5–10 个不同任务族，在同一模型和预先声明的资源上限下，加入固定版本 Toolkit Lite 指令是否改变首份报告质量？本次小型试验仅使用可公开的固定来源文本，每个条件产生一次作者回复。它评估**仅指令模式的 Lite**，不提供 MCP、检索、持久 Agent 状态或内部独立评审，不验证 Full、完整 Agent 执行、开放网络研究，也不替代历史四评审研究。[当前标准](report-evaluation-standard.zh-CN.md)提供五个评分维度；本试验每对使用一名盲评 LLM，作为诊断起点，不构成普遍效果认证。

选题本身必须允许固定来源，不能把必须实时检索的任务改成离线材料题。两组均可正常自查。Toolkit 组收到固定版本的完整 `SKILL.md`、工作流、研究规范和写作参考，要求将提纲、判断、分节起草和 Lite checklist 留在单独 notes 中；公共评审只看到报告。基线组得到相同 brief、来源和输出格式，不提供 Toolkit 指令。提供指令不证明模型确实遵守流程；保留 notes，单独核对执行情况，不与质量评分混为一谈。

## 纳入并冻结样本

1. 选择 **5–10 个不同任务族**，运行前固定样本量，说明目标工作、选取方法、语言与题型构成、排除规则。目标用途包含中英文时，纳入原生中英文题目；翻译与重跑不增加独立任务族数。
2. 每题写完整需求：读者、用途、问题、范围／截止时间、语言／篇幅、来源要求与已知边界，不给预期答案。保留全文、出处与公开权利，只有网址不足够。
3. 登记此前暴露情况。既有校准、诊断和展示案例不能变成留出题。随附模板有意**不填任务**；填写模板属于前瞻选题，不是生成证据。没有足以支持未暴露的依据时，使用 `prospective_development`，不标记 `held_out`。
4. 生成前固定作者／评审模型及快照政策、Toolkit 文件、量表、预算、重试规则和分析方法。`prepare` 将 Git 提交、实际文件哈希、全部 brief／来源、种子、分配、Python 版本与脚本哈希写入 `coordinator/frozen.json`，由 `freeze-commitment.json` 绑定。预注册时，在执行前公开承诺哈希，分组密钥暂不向评审者公开；哈希不能证明题目从未被看过。

## 配置一次，一条命令运行

将[配置模板](../evals/templates/blinded-study.json)复制到独立目录，如 `study/study.json`。替换端点、模型和说明性占位内容，确认来源公开权利，并添加 5–10 条以下形式的任务。路径以配置文件目录为基准，不得指向目录之外：

```json
{
  "task_id": "product-comparison-en",
  "family_id": "product-comparison-01",
  "language": "en",
  "task_type": "product_comparison",
  "brief": "briefs/product-comparison-en.md",
  "sources": ["sources/product-a.md", "sources/product-b.md"]
}
```

使用支持 `/chat/completions`、JSON 输出、请求／用量元数据及固定返回模型 ID 的兼容服务。需认证时，在进程环境中设置 `RESEARCH_EVAL_API_KEY` 和 `RESEARCH_EVAL_JUDGE_API_KEY`，配置中只保存**环境变量名**。作者与评审可以使用不同端点／模型，但两个实验条件必须共用同一作者配置。脚本仅依赖 Python 标准库，不需安装 MCP。

完成任务纳入和凭据配置后，在仓库根目录运行：

```bash
python scripts/run_blinded_evals.py run --study study/study.json --seed 20261010 --output evals/runs/blinded-pilot-01
```

若所选服务收费，命令会产生**付费模型调用**：每个任务族两次作者调用，两份产出都可用时再进行一次评审。输出目录已存在则拒绝运行；保存请求、原始回复、用量／失败、隐藏条件的评审输入、锁定评审及逐题结果。脚本不附带虚构结果。

需要先检查／预注册且不调用模型时，将 `run` 换成 `prepare`。之后执行已冻结的原计划：

```bash
python scripts/run_blinded_evals.py execute --output evals/runs/blinded-pilot-01
```

空模板会因未完成纳入而报错，不自动编题。`prepare` 生成标注待运行的空结果表；`execute` 核对冻结哈希，已开始的运行不能静默重试，部分结果继续保留。补充运行使用新目录和身份，不替代首轮尝试。

## 匹配、随机化与隐藏条件

- **作者匹配：**两组使用同一模型 ID、brief、来源全文、一次全新请求、无历史对话，相同的最大输出 token、总 token 上限与请求时限。两组均无检索工具、修稿反馈或重试。记录返回模型、实际 token 与耗时。模型不匹配、缺少用量、输出截断或超预算均保留为未决失败，不能判另一组胜出。
- **预算边界：**将输出限制传给端点；总用量和耗时在返回后检查。该检查识别超限，不保证账单封顶或远端取消。Toolkit 输入更长，相同上限不等于实际成本相同；披露实际用量，不声称成本完全一致或模型快照必然稳定。
- **运行顺序：**按固定种子均衡分配先运行的条件，奇数任务时数量最多差一；打乱配对顺序，同题两次调用紧邻执行。保留精确顺序和种子；独立随机流分配评审的 A/B 展示位置。这是前瞻安排，不重构历史。
- **隐藏条件的评审：**全新请求只收到相同 brief／来源、量表及 A/B 报告，不提供分组、条件名称、作者 notes、模型元数据、种子或生成顺序。若另行开展人工研究，仅 `judge-inputs/` 适合提供给评审，评分期间不得访问 `coordinator/` 或仓库上下文。当前脚本实现 LLM 路径；人工方案需另行冻结身份与收集流程。
- **残余线索：**报告原样传入，不选择性修风格或删除缺陷。评审完成判断后记录可识别条件的线索；隐藏标签不保证盲法有效，要核查泄漏并披露。全新请求不等于模型错误在统计上独立，也不能排除服务提供方的共同影响。

## 固定量表、失败与解释

版本化[量表](../evals/rubrics/blinded-pairwise.v1.json)包含任务忠实度、事实与证据、解释与综合、反证与边界、读者用途五个维度。每维 0–4 或 `not_assessed`，给出可定位的报告引文、理由及来源依据。锚点从缺失／失败（0）、需实质修改（2）到充分展开且有具体支持（4）；不生成加权通过分。

主要观察是评审偏好：A、B、持平或未决，首轮评审及失败全部锁定后才解码条件。这是**未经独立裁决的 LLM 偏好**，不是已确认必要缺陷数。保留全部纳入任务及失败，执行完成与质量分开。保存原始回复、格式错误、分歧和关键理由；不把缺失产出计为零分，不在看到结果后删任务，不为改负评而重跑，也不用修订稿替换首稿。将偏好解释为真实缺陷前，核对重要意见与来源；[既有必要缺陷标签](necessary-defects.zh-CN.md)保持不变。

公开逐题结果、维度分、语言／题型、模型／版本、实际用量和缺失。5–10 题只是小型试验，不支持普遍优势或精确总体估计。更大效果估计、置信区间方法、增加评审或扩样都需另行预注册。软件测试只检查记录和传输行为。

## 原始材料与公开

```text
coordinator/frozen.json             # 配置、种子、分组、完整方法／brief／来源
coordinator/freeze-commitment.json
coordinator/author/<pair>/<arm>/     # 请求、原回复、执行／用量、解析或错误
judge-inputs/<pair>.json            # 只有 brief、来源、量表、A/B 报告
judgments/<pair>/                  # 请求、原评审、用量、解析或错误
judgments.lock.json                # 解码条件前锁定首轮尝试
results.json / results.md           # 全部纳入任务，包括未决
bundle-manifest.json                # 所有保留文件的哈希
```

`evals/runs/` 继续作为被 Git 忽略的本地输出目录。首轮评审全部锁定后，核对公开权利和敏感内容，把包含分组密钥、原始产出、评审及失败的**完整证据包**复制到新的 `evals/studies/<study-id>/`，使用 `git add evals/studies/<study-id>` 提交。不能只提交汇总，不覆盖日期档案。若材料必须脱敏，保留哈希并明确披露缺失范围，相应收窄公开可复现主张。不要提交 API key；公开前保留清单并核对文件哈希。

## 结果

[2026-10-10 固定来源 Lite 结果](../evals/studies/2026-10-10-lite-four-models/README.zh-CN.md)：四个作者模型重复同样五个任务族，保留 40 次原始作者请求及失败。研究页面将主结果与事后去除代码围栏的补充分析分开，链接全部原始评审、用量及哈希。每对可用报告使用一名原生 CLI 评审，是已声明的适配器扩展；计划本地冻结，未事先公开注册。不据此证明通用效果或验证 Full／MCP。新配置仍从标注待运行的空表开始。
