## 已执行设计与后续研究边界

先冻结协议，再锁定题目和调用配置，最后运行。本轮采用四家 API 作为作者模型，Codex 中请求 `gpt-6-astra` 作为开发阶段评审；实际可用模型和返回名称以接入结果为准。接入测试不计入报告质量结果。Astra 可在与作者分开的新上下文中评审；不要求不同供应商或不同模型，盲评上下文不接收分组映射。

任务从五类需求开始设计：数值口径与单位核对、冲突证据下的选择、因果与相关区分、受约束方案比较、随时间变化的证据综合。可复用相关已有任务；中英文分层记录，翻译或同题换模型不增加独立任务族数量。任务中的材料按原有来源和时间边界使用；现有及以后的用户题、开发题与参考案例均为真实独立任务，实际执行的测试都是真实测试。直接记录来源性质与任务复用。模型实际执行和参与评测同样提供用户视角：根据上下文使用、额外阅读、耗时、返工和研究结果判断收益，不以真人参与为前提；说明实际观察到的作用及其任务范围。

盲法采用预先固定的报告／notes 分离规则。两组均把执行和独立审阅状态放在 notes；评审包只含题目、来源、量表及 A/B 正文。不得看见结果后删句、改写报告或更换标签；残留工具、模型或流程线索单独登记并报告盲法局限。次序互换用于观察位置敏感性，不当成新增任务。评审先用长度匹配、含具体证据的有效／缺陷对照校准；不同模型的一致意见不等于事实。

原接入阶段按五次首轮尝试设计；失败保留后另行冻结补测，最终五次生成完成、合计六次网络请求和一次本地预检失败，无自动付费重试。四题族校准包每模型另需 12 次评审调用，须独立冻结配置及预算，不包含在五次接入生成中；Astra 的这一轮已完成并单列证据。批量开发试验已在开始前另存机器可读计划，列出模型、请求数、token／时间上限、重试规则、两组资源、评审面板、来源哈希与结果指标。后续修复遵循[当前标准](report-evaluation-standard.zh-CN.md)，由 Astra 完成评审即可；是否另做使用效果比较按具体需要决定，不阻塞修复或合并。

## 取舍与更新规则

暂不实施强制更多确认、用最小字数或“未读”等词判断研究真伪、强制维度加总等于整体偏好，也不未经引用检查迁移或删除资源。安装命令按支持的平台核对，不把所有 `python` 简单替换为 `python3`。包目录重组和大型素材迁移排在可靠性与方法改进之后。

每次合并更新本页的状态、PR 和验收证据。分别报告流程完成、机械合规、稿件质量和工具效果；不能把其中一项通过写成另一项通过。API 密钥仅在本地调用进程中使用，研究配置只保存环境变量名；公开前检查请求、响应、错误和来源中的敏感信息。
