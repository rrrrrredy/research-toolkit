国内办公 Agent：从生成文件到接续工作

信息截止：2026 年 11 月 5 日。面向 AI 产品与企业办公负责人。

国内办公 Agent 的比较，已经需要从“能生成什么”推进到“能否围绕同一个对象继续工作”。Kimi Work 的选区修改、Office 历史版本与在线文档双写，灵犀的文字／表格双写和项目云模式，WorkBuddy 的资料库与企业套件，都在处理初次生成之后的修改、保存和交接。扣子把不同 Agent 放进项目协作，豆包工作连接飞书身份与资料，悟空把本地或云电脑执行接到钉钉组织操作上。这些路径说明，独立工作台、桌面执行和办公套件正在相互连接，已不适合分成互不重叠的产品阵营。Kimi 发布日志、灵犀产品文档、WorkBuddy 资料库

对采用范围最有用的区分，是生成新文件、修改既有对象和改变业务状态。第一类主要看内容与文件能否使用；第二类还要看原有公式、格式、权限和协作关系能否延续；第三类必须确认消息、审批、记录或发布页面的实际状态。三类动作经常发生在同一个任务里，但完成和恢复的依据不同。模型回答“已完成”，不能替代这些对象上的结果。

由此，企业能够先确定一批适合采用的具体工作：输入可取得、工具能操作、身份有权限、结束状态可检查。是否扩大使用，则取决于整项工作中资料准备、人工核对、纠错与交接还剩多少。当前公开资料足以解释这些机制差异，尚不足以给六组产品的成功率、稳定性或净人效作统一排序。

本文依据官方帮助、更新、权限和计费文档，以及具有输入与过程描述的公开使用记录。官方功能说明用于确认产品提供的路径；使用记录用于观察特定场景；实际效果需要相应任务、分母和方法支持。本文不含产品安装实测，也未独立复算外部作者的全部配套文件。无明确更新日期的动态页面，只按截止日可见说明使用。

一、先确认比较的是哪个产品、哪个入口

六组对象包含同品牌下的多个入口、产品沿革和不同执行环境。品牌相同，不能保证账号、数据与权益相同；能够下载客户端，也不能保证能够读取组织资料。

这里的“国内”指中国大陆用户可以接触的公开入口与国内服务资料。Kimi 明确列出国内套餐，WorkBuddy 明确列出国内个人版；其他产品的中国官网和中文服务文档证明入口存在，不能单独证明每个地区、设备和组织账号都拥有相同资格。对没有统一地区开放清单的产品，逐地区与逐账号可用范围仍未确认；这一缺口不应被改写成某种已知地区限制。

价格表也不能直接变成每项工作的成本表。扣子的模型用量与云设备资源、悟空的会员算粒与云电脑、灵犀的模式与智点、WorkBuddy 的个人积分和企业套件，对应不同计费对象。相同月费可能覆盖不同资料范围和执行资源；长任务使用更强模型、持续云设备或多轮返工后，实际消耗还会变化。对办公负责人而言，先确定需要购买哪一层能力，才有比较费用的基础。

二、按工作对象定义“完成”

以销售月报为例，Agent 可以先读取销售表、生成分析与演示文稿，再把修正写回团队台账，最后把汇报发到群里。表面上是一条自然语言任务，实际上跨越三种结果。

工作对象 具体结果 能够支持完成判断的依据 修改或失败后的问题
新文件 新建报告、表格、PPT、页面 实际文件可以打开；数字、公式、图表和内容符合输入与用途 可以另存或重做，但必须检查输出，生成成功不等于内容正确
既有对象 修改原销售表、现有文档、共享知识条目 指定位置已改变，未指定的内容与必要属性保留；保存后能继续编辑与协作 要辨别写入的是原对象还是副本，谁的修改被保留，版本能否恢复
业务状态 发送通知、提交审批、更新记录、公开发布 接收方或业务系统显示目标状态；动作由适当身份完成 重新运行可能遇到已经生效的部分动作；文件回滚不能自然撤回消息或审批

这种划分服务于任务判断，不是产品等级。支持浏览器操作的工作台也可能改变业务状态；办公套件中的 Agent 也可能只生成一个新文件。关键是具体入口、工具和权限能否走到要求的结束位置。

它也解释了为什么“可编辑”值得细看。表格中的数字可以看起来正确，但若公式被静态值替代，下次改输入就不再自动更新；图表若变成图片，下一位同事就不能修改数据。对于持续使用的文件，保留对象结构，可能比缩短首次生成时间更有意义。这是工作对象带来的要求，当前公开材料并未证明任何产品能够无损处理任意复杂文件。

三、六组产品分别接住了哪一段工作

Kimi Work：从本地执行向持续修改延伸

Kimi Work 的基本路径，是在电脑客户端读取本地目录、运行代码、使用浏览器并产出办公文件。9 月的更新进一步处理了生成后的工作：9 月 22 日允许选中 PPT、Excel、Word 或 Markdown 内容后提出修改；9 月 24 日增加 Office 文件历史版本；9 月 30 日加入飞书、Notion 文档双写、产物卡片和页面编辑。这些具体变化使它不再只能按“本地生成器”理解，也让工作台能够围绕已交付对象持续互动。产品介绍、发布日志

这里的价值条件是用户能指出改动位置、看到结果，并把新的修改继续作为输入。在线文档双写扩大了可处理对象，却不能由此推断所有业务系统的写入权限都已具备。同样，手机可以发指令或查看结果，不会自动改变本地任务的运行位置：官方 FAQ 明确，Work 桌面定时任务需要电脑与应用运行，休眠、关机或关闭应用期间错过的触发不会在下次启动时补跑。夜间整理本机文件与云端生成简报，需要分别判断运行条件。常见问题

模型描述也要跟随具体更新。介绍页仍有 K3 表述，而 K3.1 Pro 发布说明已明确支持 Work 3.1.0+。这能确认产品里的模型可用性，不能把模型基准成绩直接换算成办公任务完成率。K3.1 Pro 发布说明

扣子：统一协作入口，保留不同执行资源

扣子的区别在于把多种 Agent 组织进同一项目与对话入口。其原生、三方精选和本地接入的能力表不同；平台工作台里的“文件”能力标记，不能当成本地 Agent 一律不能读取本机文件的证据。本地接入说明明确，任务仍由用户电脑执行，扣子负责对话与协作管理。Agent 类型、本地 Agent

当本地 Agent 加入项目，项目成员可以共同下达指令，但执行资源仍是那台机器。coze-bridge 必须在线，本地终端原有对话也不会自动同步到扣子会话。这意味着，统一入口可以减少调度分散，却没有自动统一机器可达性、资料上下文和本地工具权限。已有技术人员维护的执行环境，可以被更多同事使用；相应的连接、账号和资源维护仍需要有人承担。

三方精选 Agent 则运行在扣子云电脑中，不依赖本地电脑在线。官方特别说明，其中 Claude Code、Codex CLI 使用相应框架并搭配扣子提供的模型，没有绑定原厂账号或模型。因而不能由框架名推断模型表现，也不能把云端接入的费用、工具和权限套用于本地 Agent。对于已有本地资料与工具的团队，本地接入有延续既有环境的意义；对于需要离开个人设备持续运行的任务，云端路径更相关，前提是所需输入与系统在云端可达。三方精选 Agent

飞书／豆包工作：组织身份能否贯穿输入与成果

豆包工作同时提供办公文件创作、局部编辑、浏览器／电脑操作和飞书原生技能。审批、日历、文档、多维表格等是平台内置技能；外部连接器又受连接账号与资源权限约束。功能列表说明产品提供这些路径，并不证明某项审批已经提交，更不能把提交写成获得批准。产品与工具说明

其更有区别的机制，是飞书企业身份能够同时限定输入资料与成果协作。官方说明，豆包工作沿用本人在飞书中的身份和对象权限，组织架构、文档、群聊、会议等可以在允许范围内成为工作上下文；成果回到飞书后，继续受原有协作权限约束。若任务本来就依赖这些资料和同事关系，这条路径有减少重复导出、重新组织材料与分享映射的可能。权限与数据说明

这种便利依赖选对身份。独立 PC 端用豆包账号登录时主要进入个人空间，用飞书账号登录才对应企业身份；同一个人拥有两种账号，不会自动合并资料、权限和权益。飞书内入口与 PC 入口的功能也不完全相同。企业已有大量飞书资料，只能说明存在有用的上下文基础，不能保证发起人有权读取所需文件、当前任务已取得正确版本，或所有员工都已开放入口。

此外，飞书 aily 更名“豆包工作伙伴”是具体产品沿革，不能扩写成飞书整体更名。工作伙伴的主动工作计费和历史会员续订规则，也不宜覆盖豆包工作的所有入口。工作伙伴计费与更名说明

悟空：电脑执行与组织动作之间仍有几道条件

悟空把文件处理、日程、文档、审批等动作放进钉钉工作平台，但会员、组织数据授权和执行设备分别发挥作用。企业买了会员后，管理员仍需分配席位；允许成员通过悟空操作钉钉，需要主管理员开启相应授权；敏感动作又要求员工再次确认。购买算力资源不会直接取得组织操作资格，组织开放入口也不会让每个员工获得业务批准权。企业会员 FAQ、权限说明

云电脑解决的是另一层问题。官方说明其可承担长时任务，但须另购，目前只支持个人购买与使用，设备只能在购买组织中选择。它可以减少对个人电脑持续在线的依赖，却不能被理解为企业统一采购后即可跨组织调度的一池资源。涉及不同分子公司或多组织身份的工作，需要分别核对设备和授权。云电脑说明

对治理成熟度也应读具体功能状态。历史更新曾写企业技能中心新增，而当前企业 FAQ 对集中管理仍有开发中、申请体验的表述。能确认的是产品正在提供相关管理路径，不能仅由更新标题宣布所有企业技能管理已经普遍开放。更新日志、企业 FAQ

WPS／灵犀：文档结构与入口条件同样重要

灵犀独立端处理 Word、Excel、PPT、PDF，也提供代码执行和网页操作。10 月 22 日的文字／表格双写、团队功能和项目云模式，使持续编辑与跨设备使用成为更明确的产品路径。对于已有办公文档，值得关注的是它如何保留可编辑结构，而不只是产出预览效果。灵犀产品文档

6 月 WPS 文字 Agent 内测帖提供了更具体的结构说明：可更新的目录域、原生图表、可修改公式，以及可接受或拒绝的修订与批注。这些是面向文档内部对象的产品设计证据，但对应专用安装包与内测资格。当前灵犀文档仍写 Office 插件即将上线，因此不能把历史侧栏能力、独立端双写和所有 WPS 客户端的普遍开放合并成一句“已全面内置”。文字 Agent 内测帖

执行环境会进一步决定对象范围。灵犀本地环境可访问授权目录和本地服务；云端环境可访问 WPS 云盘，却不能直接读取本机文件，也不支持本机系统操作。项目可以固化指令与资料，但配置变更只影响后续新任务，已有任务不会自动更新。换到云端或更换项目配置后，仍要确认任务实际拿到了哪份材料。

专业数据源也需按细则判断：简介概括了多类数据，专节却把金融、政府及部分垂直数据列为计划接入。当前已开放的检索不能由宣传概述扩大到所有专业数据。这样的限定会直接影响研究或分析任务需要用户补充什么输入。灵犀模式、项目与数据源说明

WorkBuddy：把结果保存、修订与发布分开

WorkBuddy 的资料库把产物接入后续工作：MD 承担文字叙事，CSV 保存数据，HTML 负责展示；任务可以读取资料再保存回去。其 MD 修订以待确认状态呈现，接受后才写入正文。这种安排把“Agent 提出修改”和“修改成为正式内容”分开，能让人继续参与同一对象的维护。资料库说明

保存与公开发布同样有不同后果。个人文档、团队空间和网站链接对应不同可见范围；“发布为网站”默认关闭，开启后获得链接的人即可访问。一个任务把结果存入资料库，不代表已经公开发布；发布成功也不能仅由文件生成推断。选择工作入口时，成果准备由谁继续修改、向谁交付，应和文件格式一起确定。

企业旗舰版的两种套件进一步说明，产品名与价格都不足以定义采用范围。Buddy One 套件包含 CodeBuddy 及腾讯文档、知识库、网盘等办公协同产品；企业微信联合套件使用企业微信登录与上下文，但不包含前述整套协同产品。两者同价，选择后不能切换。这里需要判断的是团队已有资产与登录、协作方式的匹配，而非把两个套件加总成所有 WorkBuddy 企业用户都拥有的能力。企业版版本说明

四、模型、上下文、权限和人的工作怎样配合

公司提供产品、服务和商业安排，产品提供工具、状态与交互，模型在可见资料和允许动作内理解要求、选择步骤。三者不能互相替代。模型理解“更新报价”，不代表产品接通报价系统；工具能够写记录，不代表发起人有批准权；身份具备权限，也不保证读到的是最新成本表。

六组产品也并非单一模型路线。Kimi Work 将自研模型与工作台结合；豆包工作介绍了 Seed、Seedream、Seedance 等能力；扣子云端框架与所配模型可以分离；灵犀、WorkBuddy 支持自定义模型，悟空高级会员的自定义模型又有资格与组织控制条件。产品能力应按实际配置理解，不能把某公司模型名当作整条工作流程的解释。豆包工作说明、WorkBuddy 模型配置、悟空会员 FAQ

上下文是否有效，也取决于它何时、以什么范围进入任务。灵犀项目之间隔离，配置更新只影响新任务；扣子本地终端会话与平台会话不同步；WorkBuddy 资料库需要把相应空间或文档添加到任务。长期保存资料解决了重复提供背景的一部分问题，却不能证明当前执行已读到最新输入。旧预算与新预算同时存在时，计算正确仍可能使用错版本；所需资料无权限时，扩大上下文窗口也不能补齐。

人的工作因此也有不同性质。管理员决定谁能用什么；业务人员补充口径和版本；使用者定位修改、接受修订与核对结果；有批准权的人决定对外动作。其中一些是正常业务责任，一些才是错误造成的重复劳动。把它们全部计作“人工兜底”，会误判产品收益；只记录第一次生成耗时，又会漏掉后续检查与恢复。现有材料没有固定输入、模型、工具和权限的对照，不能给各层分配节时贡献比例。

五、失败后恢复的是什么

连接恢复、重新运行任务、恢复文件版本和撤销业务动作，是不同操作。一个中断任务可能已经写入了部分记录；再次运行不自动意味着从正确位置继续，也不自动意味着必然重复写入。现有资料没有提供适用于六组产品的共同去重或事务回滚保证，应按具体对象看恢复语义。

六、公开使用记录已经说明什么

公开使用材料可以把功能介绍落到具体路径，但来源身份和输入条件会改变其证明范围。

花叔的豆包工作教学实录提供了人修改后由 Agent 接续的场景。 9 月记录中，Agent 为虚构销量表填入公式，作者在内置编辑器修改 B2、保存并重新打开，再让 Agent 重读；后续 PPT 使用修改后的数据。另一条记录通过原生选区指定 H4，只改变该格加粗属性；网页案例则使用文字定位，并保留排序出错后通过具体反馈修复的过程。它们支持讨论保存、重读、选区和纠错如何连接成工作，不能混称为同一种网页框选能力。《豆包工作从入门到精通》§05–06

这份记录明确区分虚构销量、模拟缺数表、真实历史视频数据及未逐条重测的教学模板。其账号与版本上的公开观察有参考价值，但本文未下载重算配套文件，也未复现运行。实录本身未验证真实同事参与的多人协作，因此人机交替编辑不能被扩展为组织协作已完成验证。

光子星球 7 月 30 日的 WorkBuddy 体验展示了局部编辑，也限定了测试对象。 作者先让产品生成半成品，再修改自己的 PPT、Word、Excel、Markdown，表格中包含 50 行模拟销售数据。文章描述了选区编辑与跨格式转换，同时指出 Word 编辑框位置异常、PPT 文字偏多。这能够支持相应交互曾在公开体验中出现，但自生成素材不能代表企业积累多年的复杂文件；文章所称标注准确，也不能推出真实脏数据的总体准确率，更不能直接当作 11 月版本的测量。光子星球体验，新浪转载

WPS 生态教程提供了“给出步骤”与“完成操作”之间的反例。 5 月教程作者自报金山 KVP，使用灵犀 Claw 读取订单系统多维表格后，取得权限设置步骤，再由人手动配置高级权限。作者称当时接入的云文档技能包没有直接设置的权限。原文未给出工具定义、授权配置或失败响应，无法判断限制来自功能实现、接口开放还是账号授权；不能把这件事写成确定的技术根因。它也不是无关联的独立测评，更不能限定当前灵犀全部入口的能力。其有效启发是，理解对象并提供清晰指导，仍可能与实际改变对象状态相隔一步。订单表权限教程

厂商采用数字的含义又不同。WorkBuddy 产品介绍称已成为超过 12,000 名腾讯员工常态使用的工作台；这属于厂商披露，未提供足够的活跃定义、任务分母、人工耗时和对照。它能说明官方所称的内部使用规模，不能转换成市场占有率或净生产率。WorkBuddy 产品介绍

因此，这批资料中最具体的外部使用证据仍是有条件的操作叙述，而非同输入、同权限、同完成标准的独立跨产品效果比较。它们足以帮助理解交互和返工位置，不能承担总体排名。

七、怎样据此确定采用范围

对企业办公负责人，起点可以落在三个现成事实：材料现在在哪里，最终需要改变哪个对象，谁能确认工作结束。下表给出按这些事实缩小范围的判断，不替代具体采购选型。

当前工作条件 值得优先考察的路径 会改变判断的观察
资料散在本机目录，最终交付可检查的文件 有授权目录与相应文件工具的桌面工作台；确认输出能继续编辑 若准备目录、维护设备和修复连接占去更多人工，本地读取便利可能不足以支撑采用
资料与协作者主要在飞书、钉钉、WPS 或腾讯协作产品中 能延续原身份、原对象与分享关系的入口；确认具体套餐和管理员开放条件 若独立工作台在同输入、权限与质量条件下所需整理、核对和返工更少，套件上下文优势就会缩小
需要无人值守的周期任务 输入在执行环境可达的云端路径，或能够持续在线的本地路径；核对触发与恢复说明 若错过触发、长时等待或中断后人工接续不能满足工作节奏，单次成功仍不足以扩大使用
任务规则固定、已有公式、脚本或自动化 先保留现有路径，辨别 Agent 是否解决新增的理解或交互需求 若现有确定性流程更稳定、更易维护，就没有必要只为统一 Agent 入口迁移

对于 AI 产品负责人，已有证据指向的具体机会是让后续工作更容易接续：把选区和对象身份准确传入任务，让人看见改动，让已保存修改成为下一轮输入，明确区分生成、接受修订、分享和发布。这些交互让修改目标、保存状态和交付方式更清楚，有望减少误解和交接错误；其收益仍应由整项任务的准备、检查、纠错和恢复来验证，而非只看首次生成速度。

更强模型能够改善理解、计算和工具选择，但不能直接补上缺失连接、未取得的最新资料或不存在的组织授权。遇到阻断时，先辨别究竟缺输入、缺工具、缺权限还是结果错误，才能判断该升级模型、改变环境、补充资料，还是把最后一步保留给有责任的人。产品之间的差异，由这些条件共同形成。

当前六组产品已经提供多条进入真实工作的路径。扩大采用的理由，应来自同一文件能够持续修改、同一身份能够继续协作、任务中断后能够按需要恢复，以及这些过程中剩余人工劳动的实际变化。哪一种路径值得采用，取决于工作对象与组织现状；公开功能的增加为选择提供了依据，完整工作结果才决定选择是否成立。
