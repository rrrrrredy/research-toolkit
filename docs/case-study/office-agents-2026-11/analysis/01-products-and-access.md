# U1：产品身份、运行入口与可用条件

研究者：`/root/case_cn_author`。形成时间：2026-11-05；原件抓取时间逐条见 `../sources/fetch-log.jsonl`。来源编号仅用于内部交接。以下是待独立证据／领域核查的完整单元分析，尚未作为终稿前提。

## 研究判断

截至 11 月 5 日，六组对象已经不适合按“聊天产品、办公套件、桌面 Agent”划成互斥阵营。Kimi Work、灵犀和 WorkBuddy 都把文件执行与持续修改放在工作台中；扣子把不同 Agent 及运行位置组合为项目协作；豆包工作连接飞书身份和资产；悟空同时提供本地电脑、云电脑与钉钉组织操作。产品边界应按入口、执行位置、身份和具体权益逐项确认。

“国内产品”在这里指中国大陆用户可接触的公开入口和国内服务文件，不表示每个大陆账号都已开通全部功能。Kimi 明确列国内套餐，WorkBuddy 明确列国内个人版；其余产品的中国官网和中文文档证明入口存在，不能单独证明所有地区、设备或组织账号资格相同。没有找到统一地区清单的对象保留未知，也不据此暗示存在某种已知地区限制。

## 为后续分析提出的前提与反例

1. 产品名称不能当模型名。Kimi Work 提供 K3.1 Pro，而介绍页仍有 K3 旧描述；扣子云端 Claude Code／Codex CLI 用其框架配扣子模型，未绑定原厂模型或账号（S08.txt:47–52）。WorkBuddy 支持多个国内模型及自定义模型（S30.txt:106–162）。因此后续只讨论已确认产品配置，不以公司标签给整项工作归因。
2. 云端能力不能从“远程调度”推定。扣子本地 Agent 依赖 coze-bridge 和设备在线，终端旧对话不同步（S07.txt:34–56）。悟空云电脑有单独购买和组织边界（S27.txt:97–120）。灵犀云端可读 WPS 云盘但不能直接读本机或做系统操作（S16.txt:304–330）。
3. 当前版本进一步连接团队资产，削弱“独立桌面只能个人使用”的分类。WPS 10 月团队更新、Kimi 9 月飞书／Notion 双写、WorkBuddy 企业套件都是反例（S16.txt:524–529；S02.txt:161–176；S22）。这些是官方功能／更新事实，不证明企业实际大规模采用。
4. 文档内部存在不能抹平的差异。悟空 4 月更新称企业技能中心新增，而当前企业 FAQ 仍写集中管理开发中；最终稿不能以更新标题宣布组织治理全部成熟。灵犀简介宣称专业数据源丰富，但专节把金融和政府数据仍列计划接入；最终稿按专节限定。S28.txt:98–100 对照 S14.txt:161–162；S16.txt:50 对照 259–263。
