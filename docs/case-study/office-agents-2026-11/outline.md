# 国内办公 Agent 研究工作提纲

创建时间：2026-11-05 04:03 UTC（北京时间 12:03）。唯一主稿作者：原生 Agent `/root/case_cn_author`。信息截止日：2026-11-05。此文件是待独立检查的工作提纲，不是报告。

## 有效范围与读者

面向 AI 产品与企业办公负责人，重做历史首页中文研究。研究对象是中国大陆用户能够接触的办公 Agent；逐产品核对地区可用性，未确认时保留未知，不暗示已存在具体地区限制。覆盖 Kimi Work、扣子、飞书／豆包工作、悟空、WPS、WorkBuddy；核查名称、整合和并存关系，不由相似功能推断承继。交付充分展开的中文报告与有用的对比表；不做产品排名、安装实测、采购代办或总体净人效推算。旧 brief 与报告只用于恢复原问题，不作为当前事实证据。

## 核心研究问题

1. 产品在什么环境运行、处理哪些对象，分别能生成文件、修改已有对象或改变业务状态？同一个任务在哪一步仍需要人处理？
2. 截止日能够确认的产品名称、发布与测试阶段、中国大陆用户的地区可用性、账号和组织授权、套餐及部署条件是什么？未知项是否影响采用范围？
3. 公司／组织、产品、模型分别承担什么职责？工具、可见上下文和权限怎样限制交付，即使模型能力提高仍留下什么问题？
4. 修改、失败重试、版本恢复、协作交接和设备在线条件怎样改变可用范围？公开使用案例实际观察了什么？
5. 读者可以在哪些工作对象上开始采用，哪些反证会推翻“套件上下文或桌面访问有优势”等解释？

## 报告拟定结构

开篇直接回答当前产品差异及其实际意义。随后用一张身份／入口／可用条件表定位六组产品，用工作对象说明三类交付差异，再展开六组产品各自有区别的机制。跨产品部分解释模型、上下文、权限和人工参与的关系，最后回到失败恢复、协作交接和采用范围。来源链接贴近重要判断；来源说明页保留自行解释的证据边界与 URL，不发布受版权保护的全文。

## 证据与时间规则

- 优先官方产品、帮助、权限、更新和计费文档；原件保存在 `sources/raw/`，公开说明保存为 `sources.md`。
- 搜索摘要仅作线索；抓取失败与部分读取分别记录，不伪称原文已读。
- 页面发布时间／更新时间与抓取时间分开。晚于 2026-11-05 的资料不作截止日事实；无版本日期的动态页面只描述本次截止日可见状态，不倒推早期版本。
- 原始使用记录必须有具体输入、过程或产出，才能支持对应场景的观察；没有分母与方法不计算成功率、节时或市场排名。
- 公司说法、公开体验与作者解释区分。公开资料不能回答的开放资格或恢复语义明确保持未知。
