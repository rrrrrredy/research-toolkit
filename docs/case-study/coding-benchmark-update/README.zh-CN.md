## 实际复用、返工与简化

原任务 50 个文件保持原样；从副本接续。原有 10 个来源文本和编号、16 个主张编号、6 项要求编号全部保留。只更新 4 个来源记录、5 条主张，增加 S11 与本次更新要求。6 个未受影响的来源不再在线获取，相关已保存内容按需核对；用户未填写 CSV 或重新回答需求。

首次自查发现改写 V2 段落时漏掉了原稿已有的“跨版本分数不能直接解释为模型进步”，据 S9/S10 恢复；同时把 529/214/38 的 S10 引用移到对应数字旁边。只修正相关段落，再核对完整当前稿。保留[首评 needs_revision](first-self-review.json)、[终评 pass](final-self-review.json)及对应版本，不重复评审未变稿件求通过。原始任务的独立盲评仍属于历史记录，本次没有新增独立评分。

两个真实摩擦也保留：首份更新稿 3,803 字符已达标，但 R-length 尚待确认，核对约定范围后更新该项再检查；S10 因首次工具输出截断而重复打开。另一次 S11 原文获取用于保留材料。因此不能称为“零重复读取”。

本次把可避免的自评材料搬运转成产品改进：本地 self 调用可传 `include_assignment: false`，返回冻结输入文件的位置与哈希。针对同一实际评审输入，返回体从 **210,018 降至 6,444 个 UTF-8 字节，减少 96.9%**。完整输入、版本绑定和检查不变，默认仍返回完整材料。计量方法是对返回对象执行 `json.dumps(parsed_response, ensure_ascii=False)`，使用默认分隔符，再计算 UTF-8 字节数；不包含 MCP 传输封装或缩进文件格式。这个比例只量化序列化返回对象，不代表整项研究的 token、时间或费用降幅。

## 实际时间与消耗

从收到本次请求到保存首份完整更新稿 **5 分 23 秒**，到完成报告交付检查 **11 分 28 秒**。这是当前执行过程的实际墙钟时间，期间交错进行了来源核对、正文更新、自查及小范围代码修复／回归；不能当成隔离的纯写作耗时，也不能与历史从零写作直接相减来计算节省。

可确认的收益是保留既有研究、补齐具体解释和条件、避免重建未变记录，以及缩小一次工具返回。未做“更新 vs 重写”配对，不能量化究竟节省了多少总时间或返工，也不据此声称 Full 普遍提质或省钱。
