# 未达标检查与稿件的处理

[English](failure-handling.md) | [简体中文](failure-handling.zh-CN.md)

保留失败、定位原因、做具体修改，再验证修改。对未改变的样本反复生成或评分直到通过，不算修复。普通报告交付与冻结评测证据需要分别处理。

## 按问题分流

| 发现的问题 | 处理与责任人 | 验收证据 |
| --- | --- | --- |
| 可复现的执行、解析、状态或检查器缺陷 | 维护者：最小复现、提 PR 修复、保留有效对照，相关回归与 CI 通过后合并。 | 负例被正确拦截或修正，有效对照仍可通过，并记录合并提交。 |
| 稿件不满足已声明篇幅 | 作者：实测稿件，兼顾约定覆盖范围与篇幅修稿，再检查。 | 当前文件满足原规则，必要内容仍在；短而错误的稿件仍需内容修正。 |
| 推荐、计算、归属或因果判断错误 | 作者及适用评审者：逐段对照来源，修正决策及相关论断／引用，再评审新版本。 | 可定位的来源与有根据的判断；模型 PASS 或多模型一致本身不够。 |
| 评审错误或标签／顺序分歧 | 由独立审阅者／审计者对照原文与来源；普通交付保留原判断及有证据的处置，评测保留原判断及分歧。 | 记录理由和实质证据，不能因负面意见不方便就弃用。 |
| 超时、配额、访问失败或输出格式无效 | 保留原始输出与执行状态，先诊断再尝试。 | 后续尝试单列并处理已观察到的原因，不替换原失败。 |

## 交付前检查

工具管理的稿件需要机械检查时，可调用 `research_check_draft(task, artifact="final.md")`；或将 `{"task":"comparison","artifact":"final.md"}` 保存为请求文件并执行：

```bash
python scripts/research_workflow.py check-draft --workspace ../research-work --request check-draft.json
```

本地命令检查 brief 字段、来源／论断记录的前提、可读非空稿件及显式 `length_constraint`。返回整份文件的词数／字符数、`length_checks`、错误与警告。CLI 退出码 1 表示这些检查失败。`ok: true` 仅表示这些检查通过；`semantic_quality` 与 `delivery_status` 仍为 `not_assessed`。其他要求、来源真假与实际阅读仍需正常核对。不从自然语言猜测篇幅；没有声明范围会返回警告。只登记真实约定，正文限定等其他口径需另行适当测量，见[计数契约](delivery-verification.zh-CN.md#显式篇幅要求)。

检查使用共用任务锁，不改写进度、稿件、评审或凭证；旧任务可能创建常规空锁文件。它不调用模型、不自动修文、不将待办要求改为已满足，也不授权交付。结果只覆盖检查时的版本，后续修改后 `finish` 会重新检查。

普通报告按以下步骤处理：

1. 保留原评审，在现有任务记录中定位缺陷、稿件版本、段落、要求／来源、影响及拟修正内容。原稿尚未留存时，编辑前另存一份草稿。
2. 修正受影响的文本与论断，涉及机械检查内容时使用 `check-draft`。按证据处理未完成的需求记录；不能为通过计数而改动原约定范围。
3. 将最终推荐与比较部分的同一组数字和条件逐项核对。没有观测的事项保持未知，缩稿后再查必要内容是否齐全。
4. 对修改版本调用 `research_review`，设置 `revision: true`，处理必要问题后再 `finish`。已授权的修正无需另行批准；当前交付完成独立内容视角、审计和最终验收。

## 解决原因后接续

定位实际缺陷、受影响输入和稿件版本，在已有任务与审阅记录中保留原判断、拟修正内容及依据，不另设修复流程。

定向修改后仍有同一必要问题时，直接检查来源和改后正文，调整处理方式。重复同一未改提示或负评不能解决问题。继续任务必需的实质研究与独立审阅，不设默认耗时、token 或调用次数上限；只有无法由 Agent 决定的重要范围或访问事项才询问用户。

冻结评测的原稿、首个有效判断和执行记录保持不变；修订稿或明确标注的示范另存。验证针对发生变化的行为和实际任务，不自动新增对照或重跑全部旧案例。
