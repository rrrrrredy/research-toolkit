# Research Toolkit v2.5.2

[English](v2.5.2.md) · [简体中文](v2.5.2.zh-CN.md)

This compatible patch repairs report-sharing authorization and the executable MCP example.

- After a report-sharing invitation, explicitly authorizing a containing project clears stale invitation markers along that task’s path to the selected project. The next report can use the grant. Explicit refusal, one-time sharing and pending renewed-invitation choices are retained. The existing settings and content queue are reused.
- The README example now registers sources, claims and `main=true` through `research_save`, using the actual calling agent task/session ID supplied with `--host-task`. It no longer checks current inputs against an unused historical self-review hash. Original inputs, hashes and responses are preserved together under `examples/mcp/history/`.
- The existing MCP contract check executes `examples/mcp/capture.py`, covering the README command as well as the lower-level interfaces. The first example command prepares independent assignments; actual reviews, audit and acceptance still require their own completed results.
- The former Lite teaching inputs are clearly archived. Grok reuse guidance explains refreshing a saved private skill from the current Toolkit version. Old records, archived evaluation runners and legacy parameter compatibility remain; new tasks use the unified research entry.

Offline sharing checks reproduced the v2.5.1 failure and confirmed the repaired natural sequence, deduplication and preservation of explicit choices. With the real calling agent ID, the corrected example made five successful MCP calls and prepared eight independent content-review assignments. These checks used fictional files with uploads disabled. They did not run model reviews or repeat research tasks. A dead Lite-specific guidance import was removed, and bilingual usage notes and plugin files were synchronized.

Install the complete v2.5.2 package to receive the sharing fix. If an earlier version already left an invitation hiding a parent grant, confirm that same project grant again from the affected task; the obsolete marker is cleared then. Existing task data, review duties and delivery contracts are unchanged. The Release contains the plugin ZIP and `SHA256SUMS`.
