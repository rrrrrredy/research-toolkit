# Research Toolkit v2.4.2

[English](v2.4.2.md) | [简体中文](v2.4.2.zh-CN.md)

This patch repairs the final batch of automatic usage upload. Previously, the first event triggered an immediate upload, while later events within the 30-second window did not schedule another send. If work stopped then, those events waited for a later use.

The existing sender now waits about 30 seconds and uploads the accumulated events in the background. Concurrent calls share the reserved send; remaining batches continue through the same sender. Turning recording off before sending is respected. Manual `flush` remains immediate, and network failures retain the existing queued-retry behavior.

Verification used the actual installer and CLI. In a five-event local reproduction, the original implementation sent one event and left four queued; the repaired implementation sent all five and emptied the queue. In GitHub Actions Ubuntu, the default background sender delivered 14 events, and every original payload matched the private repository export. A batch disabled before sending was absent from that export. Neither manual upload nor an administrative database write was used for this online check. Native event inputs were controlled inputs passed through the installed hook commands, without a new model run.

Update the complete installed copy or plugin to v2.4.2. Codex, Claude Code and OpenCode retain their own configuration-loading and trust requirements; recording starts once that setup is active. The patch adds no research step, dependency or background service. Usage fields and content-sharing permissions are unchanged.
