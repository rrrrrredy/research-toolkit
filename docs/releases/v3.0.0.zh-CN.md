# Research Toolkit v3.0.0

[English](v3.0.0.md) · [简体中文](v3.0.0.zh-CN.md)

把草稿交给 Toolkit 后，派工、审计、改稿和复查都由 Agent 完成。最后交到你手上的是通过复查的成稿。

## 本版改了什么

- **同时只能跑两个 Agent，也能做完整审阅。** 七个内容视角分给三个独立小组，领域问题按需加专审。另有独立 Agent 用原始资料审计意见，再由另一位 Agent 检查最终稿。两个名额都占用时，剩下的任务先排队，空出一个就接着派。宿主需要能在名额释放后启动或接续下一项任务。
- **几个人提同一个问题，查一次就够。** Toolkit 根据原始评审回复自动列出待查项。如果四路都指出同一个问题，审计者只核对一次原始资料，四条意见共用一个结论。每条原意见都还能追溯。如果原文证明四路都说错了，审计可以把四条一起驳回。
- **最终复查通过就交付。** 独立 Agent 阅读当前全文，核对该改的地方有没有改到位。有问题就由 Agent 改好再查。通过后 Toolkit 直接返回最终报告和交付回执，任务到此结束。

原 Agent 接着评审时，已读过、没变化且不受修订影响的原件可以复用。仍要阅读当前全文并核查受影响的证据。Toolkit 在一次检查中也只计算一次相同输入的哈希。

CLI 的 `review --summary` 和 MCP `research_review` 的 `summary: true` 可以简短显示「收到没有、还差几项、下一步做什么」。带 UTF-8 BOM 的请求、交接文件和备用评审响应现在都能读取。CLI 和 MCP 的交付说明可用 `delivery_message`，原有的 `message` 也可使用。新安装默认关闭基础使用记录，主动开启才会记录。分享报告需要另外同意。

## 怎么验证的

用 Codex 宿主把 DeepSeek 的真实原稿跑到了最终交付，同时最多运行两个原生 Agent 任务。首轮 39 条意见归并成 17 项审计裁定。另用同一份原稿注入四路测试意见，每路都包含一个真缺陷和一个误报。独立审计 Agent 核对官方原文后，确认真缺陷、驳回误报，各写一份裁定。它也认出了四路意见是测试数据，任务依然处于未完成状态。研究质量、成本和耗时的大规模对照留待后续。

## 怎么升级

从 Release 下载 `research-toolkit-plugin-v3.0.0.zip` 和 `SHA256SUMS`。先核对 ZIP 的哈希值，再解包并替换整个插件。已经按 v2 审阅协议保存的任务可沿用原有分工继续做。[安装说明](../installation-versioning.zh-CN.md#install-a-version-pinned-skill) · [兼容性说明](../compatibility.zh-CN.md)
