# Research Toolkit v1.4.1

[English](v1.4.1.md) | [简体中文](v1.4.1.zh-CN.md)

This patch delivers the default-entry and on-demand method-loading changes from [PR #91](https://github.com/rrrrrredy/research-toolkit/pull/91) to installed-plugin users. The v1.4.0 ZIP contains the previous guidance. Public tools, arguments and saved task formats are unchanged.

## Changes

- **Start with the research need.** The default Skill entry centers on understanding requirements, following instructions and developing a useful answer. The ChatGPT guide no longer asks users to remind or dispatch the Agent; the Agent organizes methods, records and execution within the user's request.
- **Read methods when they help the task.** Existing method links cover the brief, evidence, analysis, writing and continuation. Review configuration lives in `docs/review-completion.md`, record details in `docs/usage-modes.md`, and completion details in `docs/delivery-verification.md`. No new workflow, mandatory reading sequence or fixed report structure is introduced.
- **Keep the published copies aligned.** English and Chinese Skill entries, ChatGPT guidance, reference documents, Framework pages and plugin copies are synchronized. The existing documentation-contract check reads the status vocabulary from its new location; its assertions are unchanged.

## Validation and limits

PR #91 passed the existing CI and the implementation-stage documentation, static-build, plugin-consistency and targeted documentation-contract checks. Release preparation reuses those results and checks only the changed version metadata and generated package locally; the repository's existing CI runs on the release commit. No research task, model evaluation or previously passed local implementation check is rerun.

The standalone Skill `quick_validate.py` check remains **incomplete**: its earlier invocation stopped with `ModuleNotFoundError: No module named 'yaml'` because PyYAML was unavailable. Other successful checks do not substitute for it. To complete this check later, use an environment with PyYAML and run the existing Skill validator against the repository root; the expected result is `Skill is valid!`. This checks Skill format, not research quality.

Improvements in instruction following, user effort and research quality remain **unverified**. Shorter guidance and synchronized files demonstrate the documentation change, not a better research outcome.

## Update

Download the [v1.4.1 plugin ZIP](https://github.com/rrrrrredy/research-toolkit/releases/download/v1.4.1/research-toolkit-plugin-v1.4.1.zip) and [SHA256SUMS](https://github.com/rrrrrredy/research-toolkit/releases/download/v1.4.1/SHA256SUMS), or update the complete checkout to `v1.4.1`. Preserve local tasks and intentional edits, replace the plugin package and reload the updated Skill in the host. Existing tasks need no migration.
