# Research Toolkit v2.0.2

[English](v2.0.2.md) | [简体中文](v2.0.2.zh-CN.md)

Release date: 2026-11-02.

Fix two continuity gaps: required findings first raised by audit or final acceptance could be lost from the next revision's mandatory disposition set, and prepared research inputs could be omitted when saving the resulting analysis.

- Content review, audit and final acceptance now feed the same required-findings path. Their original replies, inputs and execution references remain available and version-bound. The existing independent audit must account for these earlier findings.
- Preparing a named research unit through `status.work` records its selected input versions, question and dependencies in the existing activity history. Saving that unit inherits the preparation when no explicit `based_on` is supplied. Separate units retain their own preparations, including when saved in a different order. Ordinary status queries remain read-only.
- Changed input selection, question or dependencies clear the affected unit's cached approval; original plans and replies remain intact. Existing readiness and version checks continue to apply.
- Global requirements belong in the task specification; local outlines belong with their analysis and enter other work through selected files or actual unit dependencies. This uses existing capabilities. Older specifications mixing global and local content keep whole-file bindings and are not automatically split or migrated.
- English and Chinese guidance, tool descriptions and the plugin package are synchronized. Public operation names, existing explicit bindings and saved materials remain compatible. Independent review responsibilities are unchanged.

Controlled state replays observed missing historical-finding dispositions being rejected, valid dispositions being accepted, separate preparations surviving reverse-order saves, and changed selected sources reaching the affected work. Local outline changes affected their actual dependants while unrelated work stayed ready; global specification changes still affected both branches. The original task files were unchanged.

Affected compilation, existing workflow/record/continuity checks, the packaged MCP end-to-end check, and plugin/document synchronization passed. One Windows path-length failure was resolved by rerunning only that failed check with a shorter temporary path. Replay responses were synthetic protocol fixtures; no research task or model run was repeated. Original outputs and corrections are retained locally, separate from the release package.

These observations establish the exercised continuity behavior. They do not establish improved research quality or reduced user rework.
