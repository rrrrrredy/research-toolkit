# Research Toolkit v3.1.2

[English](v3.1.2.md) · [简体中文](v3.1.2.zh-CN.md)

- Plain `status` can inspect a read-only archive without creating a lock file. Concurrent readers can share a task. If a write overlaps the read, the query reports the conflict.
- Stored HTML with a `gb2312` label can contain GBK characters such as 镕. Extraction now reads these pages and records the declared label and actual decoder. If a declaration is unknown or its decoder rejects the bytes, the extractor tries strict UTF-8.
- Draft checks report the original line numbers of private chat citations in nested Markdown lists. Indented and fenced code examples remain examples.
- Release-log comparisons skip page-level navigation and footers. Edits to a footer inside a release article or section still appear in the comparison.
- The MCP interface uses the same task locks as the CLI. The Codex adapter closes its logs when cleanup fails and reports malformed turn completions.
- Optional usage hooks exit quietly when the plugin directory is unavailable. OpenCode can locate Python under its platform command name. Usage recording keeps child sessions scoped to their host, and sharing checks recognize explicitly labelled field requirements and working directories in Markdown reports.

### Upgrading the plugin

Install the package’s `requirements-mcp.txt` in the Python environment used by your agent tool, including when upgrading from the base MCP SDK. The plugin starts `mcp run` from that environment, so its `mcp` executable must be on the agent tool’s PATH. The SDK is pinned to 2.2.0. Clients configured with an absolute Python executable can continue to run `scripts/research_mcp.py` directly. [MCP setup](../usage-modes.md)

Download `research-toolkit-plugin-v3.1.2.zip` and `SHA256SUMS` from the release. [Installation guide](https://rrrrrredy.github.io/research-toolkit/quickstart.html)
