# Research Toolkit v1.4.0

[English](v1.4.0.md) | [简体中文](v1.4.0.zh-CN.md)

This release adds optional task-continuity features to the existing save and status interfaces. Agents can update the effective scope, explicitly select the current manuscript and find unfinished work without treating an old delivery receipt as approval of a revised report. The nine tools, existing required arguments, Python 3.10 support and saved task formats remain compatible.

## Changes

- **Update the brief without losing custom instructions.** `research_save.brief` patches supplied fields and writes the specification and progress together. Manually added sections remain. If an edited field conflicts with its saved value, the batch fails without partially writing the draft or progress.
- **Identify the current work.** `draft.main=true` selects the main file; optional `draft.kind` identifies a report, comparison or review. Later chapter/reference saves do not replace it. `save/status.current_work` returns its observed state and open requirements; status keeps the historical delivery reference separate. Review and finish must use the registered main path. `complete=true` still means a complete draft, not delivery approval.
- **Expose implementation identity.** Start/status return the local implementation and entry hashes. The host-loaded Skill remains explicitly unobserved; this is not an automatic installation upgrade or a semantic check.
- **Validate and count accurately.** Active reading requirements are checked at save; explicit scope decisions can retire legacy obligations. Malformed historical status becomes a warning in the resume view. Imported reviews are separated from model invocations, self submissions and observed usage; import duration is not model duration.
- **Continue research with fewer ambiguous records.** Bilingual guidance covers current requirements, actual-text comparison, accepted versus applied feedback, bounded revision with a valid baseline, manual recovery and justified no-change. No parallel ledger, fixed report structure or extra semantic acceptance gate is added.

## Validation and limits

The [validation record](../task-continuity-validation.md) covers 14 continuity tests, 12 record tests, 79 workflow tests, 35 profile/reviewer tests, the packaged MCP contract, existing semantic-diagnostic checks and package/site validation. Seven Windows symlink tests were skipped locally; environment-restricted checks were rerun with the appropriate local execution conditions. The [independent review](../task-continuity-review.md) identified three defects; all were fixed and covered by targeted tests.

The new 12-case diagnostic catalog is independently constructed, author-labelled and not held out. Its schema was checked; it was not presented as a completed model-quality evaluation. A separate three-mode run on three short synthetic tasks found no answer-quality advantage. Managed execution also persisted task state and used more time and tokens; the arms did not perform identical persistence work. Long-task reliability and reduced user reminders remain unverified.

Release preparation reuses completed implementation checks, synchronizes metadata and generated files, and runs the existing CI. It adds no new model runs or release gates. Runtime references do not prove comprehension or guarantee that an agent follows the workflow.

## Update

Download the [v1.4.0 plugin ZIP](https://github.com/rrrrrredy/research-toolkit/releases/download/v1.4.0/research-toolkit-plugin-v1.4.0.zip) and [SHA256SUMS](https://github.com/rrrrrredy/research-toolkit/releases/download/v1.4.0/SHA256SUMS), or update the complete checkout to `v1.4.0`. Preserve local tasks and intentional edits, reload the updated methods and restart the local MCP service. Existing tasks need no migration; explicit main-artifact selection is optional.
