# Research Toolkit v1.4.2

[English](v1.4.2.md) | [简体中文](v1.4.2.zh-CN.md)

This patch delivers [PR #94](https://github.com/rrrrrredy/research-toolkit/pull/94)'s save-parameter and collect guidance to installed-plugin users. The v1.4.1 ZIP does not contain these clarifications. Public interfaces, executable logic, validation rules and saved task formats are unchanged.

## Changes

- **Explain required reading at the call site.** `research_save`, the CLI save guide and collect guidance distinguish source `read_scope` from requirement `reading_requirement`. An active mandatory-reading requirement uses `full_text` or `relevant_sections` with a nonempty list of distinct `required_source_ids`. The pair is checked after merging with the saved row; partial updates can omit unchanged fields. Requirements without mandatory reading need neither field.
- **Separate paths from reading notes.** For local `read_evidence`, recommend a task-relative path to an existing nonempty file. Put page/section locations and notes in the existing `locator` field. Supported URL, page and local-reference forms remain valid; optional `evidence_path` cannot repair an invalid `read_evidence`. `locator` has not become mandatory.
- **Keep the distributed guidance aligned.** English and Chinese save examples, Lite collect and Full guidance, and plugin copies are synchronized. No new fields, calls, workflow steps, delivery gates or task migrations are introduced.

## Validation and limits

The archived Codex requests show the two errors addressed by these clarifications: R3 used `read_scope` and omitted `reading_requirement`; six source records appended reading notes to file paths. The saved corrections supplied `reading_requirement: relevant_sections`, retained the source IDs, and later separated the paths from `locator`; both corrected saves returned success. The original records were preserved and were read, not replayed.

PR #94 passed Framework checks and the bilingual documentation check. Its completed implementation checks covered compilation, unchanged executable AST after excluding the docstring, bilingual examples, collect guidance and plugin consistency. Release preparation reuses those results and checks only changed version metadata and the generated package locally; the repository's existing CI runs on the release commit. No research task, model evaluation or previously passed local implementation check is rerun.

**Reduced rework remains unverified.** The saved corrections demonstrate existing error handling, not an observed benefit from the new wording. The earlier v1.4.1 standalone Skill validation remains incomplete because PyYAML was unavailable; this release does not change the Skill entry or rerun that validation. Its status and completion command remain in the [v1.4.1 notes](v1.4.1.md).
