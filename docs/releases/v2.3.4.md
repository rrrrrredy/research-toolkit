# Research Toolkit v2.3.4

[English](v2.3.4.md) | [简体中文](v2.3.4.zh-CN.md)

Released on 2026-11-09.

This patch corrects mechanical evaluation decisions and clarifies the guidance shipped with the Skill and plugin.

## Changes

- `scripts/run_evals.py` drops vocabulary/entity rewards and the reward for absence of generic process phrases. Generic process and strong-claim matches become contextual reading warnings, not automatic defects, penalties or completion blockers.
- Required and forbidden headings use actual ATX/Setext Markdown headings, excluding code and HTML comments. The seven existing cases retain topic coverage without imposing headings their briefs never required.
- Bilingual guidance distinguishes Toolkit users, report target readers and independent review agents. The optional comparison template, which is not consumed by an executor, no longer requires matched resource ceilings. Actual time, cost and calls remain execution context, not quality or stopping criteria; runtime limits and frozen protocols are unchanged.

Scores are renormalized over the remaining mechanical checks and are not directly comparable across checker versions. Historical reports, source packs and archived evaluation inputs/results retain their hashes.

## Validation and compatibility

Twelve CLI input groups, written before the changes, were each run once per implementation with requests, outputs and logs retained. They show local decision repairs, not improved research quality: a vocabulary-complete draft with fabricated sales figures still mechanically passes both versions. No new research tasks were run; `research_quality_status` remains `not_evaluated`, and overall research-quality benefit was not measured.

Affected Python compilation, existing checks, website/plugin build checks and synchronization passed locally. CI for the release commit is verified in the current PR.

Existing response fields, the completion contract and independent review duties remain unchanged. Pure Skill use gains no CLI/MCP record requirements.

## Updating

Merging makes the fixes available on `main` even without a Release; old download ZIPs and fixed tags do not change. A new Release still requires updating the complete installed copy while retaining task data.

Assets remain ZIP + `SHA256SUMS`. The plugin includes the Skill and `research_guidance`, not `scripts/run_evals.py`; the automatic whole-repository source archive serves CLI/evaluator users and maintainers.
