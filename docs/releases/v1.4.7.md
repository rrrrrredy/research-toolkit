# Research Toolkit v1.4.7

[English](v1.4.7.md) | [简体中文](v1.4.7.zh-CN.md)

This patch distributes the merged changes in [PR #105](https://github.com/rrrrrredy/research-toolkit/pull/105) and [PR #106](https://github.com/rrrrrredy/research-toolkit/pull/106). The v1.4.6 package does not contain the draft-protection fix; upgrading delivers it to installed-plugin users.

## Changes

- **Protect the actual draft destination.** Previously, protection checked the supplied path while writes used the resolved link target. A pre-existing task-local link could therefore redirect a draft save into a protected task record. The fix reuses the existing path resolution and checks both locations before staging or writing the batch. Errors identify `draft.path`, explain that resolved link targets are protected, and suggest a report path such as `reports/draft.md`.
- **Keep request meaning when planning.** Retain the request's purpose, key constraints and original wording or context needed to understand it. If a summary or outline diverges from the original request or later applicable instructions, correct the plan using that input. This extends the existing task specification without new fields or steps.
- **Correct the Cursor setup links.** Both quickstarts now point to the existing virtual-environment setup and MCP JSON configuration in the usage guide. English, Chinese and generated plugin copies are synchronized.

## Verification and limits

The Framework checks and bilingual documentation workflows for PR #105 and PR #106 passed. Completed local verification covered affected-code compilation, the existing 12 record-save checks, plugin synchronization across 49 shared files, bilingual content and link destinations, and `git diff --check`.

A synthetic CLI task with a real Windows directory junction reproduced the defect: before the fix, saving through `drafts → state` overwrote `state/task_spec.md` and returned success. After the fix, the save was rejected and the task specification and source records submitted in the same batch retained their hashes. Ordinary report saves and a directory junction targeting an ordinary report directory succeeded.

**File symlinks remain unverified in this environment.** Windows refused their creation with `WinError 1314`. The directory-junction result is not a file-symlink execution result. Minimal follow-up: in an environment that permits file symlinks, create a fresh synthetic task with `draft.md → state/task_spec.md`, then submit a CLI draft save through `draft.md`. Expect `ok: false`, a `draft.path` error, and unchanged hashes for the task specification and any records in the same batch. Use only synthetic files.

Release preparation reuses these results and checks only changed version metadata and package generation locally. Existing repository CI checks the release commit. No research tasks or previously passed local checks for unchanged behavior are rerun. **The planning guidance's research-quality and reduced-omission benefits remain unverified.**
