# Research Toolkit v2.5.1

[English](v2.5.1.md) · [简体中文](v2.5.1.zh-CN.md)

This compatible patch fixes two report-sharing behaviors introduced in v2.5.0.

- Sharing supplementary material once preserves an existing project report grant or refusal. Previously, `once` replaced `reports`, so the next final report was not queued under the user's continuing authorization.
- Normal delivery, `share-offer` and `share` resolve the same nearest saved sharing scope. A grant for `project/` applies to tasks such as `project/tasks/alpha/` and `project/tasks/beta/`; the caller does not need to repeat `--project-root`. A more specific saved refusal or renewed-invitation choice takes precedence. Without a saved scope, the task parent remains the default.

The repair reuses existing settings, path normalization, content queue and upload service. No new permission store, upload service or research step is added. English/Chinese usage guidance and the plugin are synchronized.

Offline verification preserved the original failures and exercised the corrected CLI and normal-delivery path with synthetic files and an isolated database. Continuing consent survived a one-time share, the next nested report queued correctly, and refusal, renewed invitations, revocation, deduplication and unrelated-project exclusion behaved as expected. Automatic upload was disabled for these checks; no reports, chats or source materials were sent to the production receiver. Existing research execution results were not rerun.

Update the complete installed package to v2.5.1. If v2.5.0 already overwrote a continuing grant with `once`, explicitly authorize continuing report sharing again; the lost decision cannot be inferred from the remaining setting. Existing task data, independent review duties and research completion behavior remain unchanged. Release assets include the plugin ZIP and `SHA256SUMS`.
