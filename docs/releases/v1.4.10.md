# Research Toolkit v1.4.10

[English](v1.4.10.md) | [简体中文](v1.4.10.zh-CN.md)

This patch distributes the changes merged in [PR #112](https://github.com/rrrrrredy/research-toolkit/pull/112). The v1.4.9 package still contains unconditional length counting, a fixed per-unit review cycle, and full workflow or writing references in stage responses. Installed users need an updated package to receive these changes. Public interfaces and saved-task formats remain compatible; no task-data migration is required.

## Changes

- **Count length when the task needs it.** Count and record the convention only when the task has a length constraint or delivery requires a count. Explicit length requirements still apply.
- **Remove the fixed per-unit review cycle.** Correct confirmed defects, check affected content and follow the task's declared review requirements. Necessary revisions and existing completion conditions remain.
- **Return guidance for the current stage.** Planning retains the brief, task specification, analysis units and depth planning; collection retains source intake and claim guidance; drafting and revision retain writing guidance and links to examples. `start`, `status` and `guide` share the existing logic, with no new tools, required fields or call steps.

The full serving argument example, three research-choice examples and state-field reference remain available in their original documents for optional reading. English, Chinese and plugin copies are synchronized. Example prose, original reports and historical records remain unchanged.

## Observations and verification

Actual responses for the four affected stages were inspected in both languages, confirming less reference content in default responses. **This is a change in loaded content, not evidence of improved research quality, reduced rework or overall speedup; those benefits remain unverified.** No research tasks or new model comparisons are run for this release, and earlier comparisons' local additions and omissions are retained.

PR #112 passed Linux, Python 3.10, Windows, plugin-synchronization and MCP CI. CI exposed an encoding error when a new diagnostic log printed Chinese directly to the default Windows console. Only that line was changed to JSON's default character escaping, after which Windows MCP passed. Product responses are unchanged by this logging fix.

The PR preserves the initial local long-path, HTTP and MCP verification limitations and records the corresponding scripts' later CI success, rather than claiming all local checks passed. Release preparation reuses those results and checks only changed version metadata and the new package; existing CI checks the release commit. Already-passed local checks for unchanged behavior are not rerun.
