# Research Toolkit v2.4.3

The shared CLI/MCP usage wrapper now records a terminal result when a Python call raises an exception outside the earlier short exception list, or is interrupted. It re-raises the original exception; it does not convert an unsuccessful call into success.

Selected-file sharing uses explicit consent in the conversation. There is no automatic popup, and `--confirm-content` confirms consent already obtained. Default basic events still exclude report and chat contents.

A bounded CLI/process reproduction retained normal start/save/status, a malformed-state failure, and a Python interruption. Before the fix, five starts had three terminal events; afterward, all five had terminal events. Normal status succeeded, the error still failed, and interruption still exited 130. No research task was rerun. Plugin copies match the shared implementation.

Abrupt process termination cannot execute Python cleanup; no missing historical return has been manufactured.
