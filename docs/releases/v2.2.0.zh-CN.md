# Research Toolkit v2.2.0

[English](v2.2.0.md) | [简体中文](v2.2.0.zh-CN.md)

发布日期：2026-11-03。

新增可选的 Agent 执行适配器（该版仅接入 Codex），把已经准备好的研究工作交给原生持久会话，并将原始结果接回同一份 Toolkit 任务。沿用已安装 Codex 的登录与模型设置，无需另配 API。

- `scripts/research_host.py` 接受已有的 `work`、`draft` 和 `review` 参数选择。研究规划、来源获取和实质判断仍由研究者承担。用法见[执行示例](../usage-modes.zh-CN.md#agent-host-execution)。
- 适配器读取完整的已准备输入，等待实际就绪的上游，按送达的输入保存原始成果；要求或材料变化时，送回已登记的原生产者。正在执行的轮次通过宿主追加消息接口取得变化。
- 独立内容审阅、审计和验收使用相互独立的原生上下文。修订续接原审阅者，保留原始提示、回复、执行事件及失败。负面意见交回协调者，不自动循环改到通过。
- 同时分发 PR #129 已合并的审阅接续改动：当前原件与原独立上下文、前次输入及具体修订差异一起提供。
- 原有 Skill、CLI、MCP 接口、已保存任务和完成要求保持兼容。新增的是可选执行命令，不增加研究入口或常驻服务。本批执行结束不代表任务完成，交付继续使用现有 `finish` 契约。这次增加兼容能力，采用次版本升级。

## 实际执行与验证

一项任务使用构造的设备选型材料，实际调用 `gpt-6-astra`：三个生产者、两个单元审阅者、八个全文审阅者、一个审计者和一个最终验收上下文。新增要求送达原生产者，运行中的统稿收到补充指令，最终正文落实了这些变化。独立意见促使原作者改正三个引用链接和一句歧义表达，最终交付返回 `completed: true`。

运行也暴露了集成问题与协调者操作错误，原始输出和失败保留在独立的本地运行档案，研究数据不放入插件。一次下游过早启动在原生运行后修正，使用保存的现场状态回放核对，没有再调用模型。明确保存阶段性贡献的停止分支完成代码核对和编译，未单独执行。这些记录支持上述执行路径，不代表已测得研究质量、速度或返工减少的增益。

受影响代码编译及插件同步通过。现有本地插件检查十项通过，七项文件符号链接控制因 Windows 权限跳过；仓库 CI 执行现有 Linux 和 Windows 检查。中英文、版本元数据及插件内容同步。
