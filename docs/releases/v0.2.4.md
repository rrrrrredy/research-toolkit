# Research Toolkit v0.2.4

[English](v0.2.4.md) | [简体中文](v0.2.4.zh-CN.md)

This release brings the merged reliability fixes, draft checks and simpler review workflow to installed copies. It updates v0.2.3 without changing existing task profiles or rewriting historical results.

## What changed

- Check a draft before review or delivery with `research_check_draft` through CLI or MCP. It reports actual word/character counts, explicit range failures and record errors without calling a model or changing task state. The package now exposes seven MCP tools.
- Use Astra in a fresh context separate from the author, including when both roles use the same model. Existing real user and development tasks remain valid for repair and verification; no outside reviewer, outside task contribution or fixed reviewer panel is required.
- Fix confirmed report defects directly, preserve the original, and recheck the revised version. Authorized improvement does not require a separate repair study or repeated permission. Optional comparisons of Toolkit and baseline results do not block ordinary repairs.
- Keep concurrent task writes under a shared lock, preserve invalid reviewer responses, and stop timed-out local reviewer processes. Pending reviews retain their original instructions across unrelated toolkit updates.
- Bind new Lite delivery receipts to the task, sources, claims, requirements and optional checklist evidence. Check explicit length bounds in Lite and Full; edited inputs invalidate affected receipts. Existing historical receipts retain their documented compatibility behavior.
- Give Lite its own stage guidance and improve missing-argument, source-record and claim-record errors. Synchronize English/Chinese instructions, web copy, installation pages and the packaged plugin.
- Preserve provider thinking/format settings, frozen request limits and original failures in evaluation runs; support the native Astra reviewer adapter and same-model author/reviewer requests in separate contexts.

## Completed checks and report repairs

The repository retains the October 12 four-model run (72 actual requests) and Astra calibration (12 first-pass reviews). The October 13 recheck used two existing tasks and two new tasks across four author models, with 31 new requests. First drafts met length requirements in 7 of 16 cases; the first Astra review accepted 6 of 16. After ten maintainer repairs, all 16 final versions meet their length requirements and have corresponding Astra acceptance. These repaired results are not first-draft model scores. Original failures and the correction of one source-masking error remain available in the [recheck record](https://github.com/rrrrrredy/research-toolkit/blob/v0.2.4/evals/diagnostics/2026-10-13-targeted-recheck/README.md).

Release checks cover Linux, Windows, Python 3.10, version and plugin consistency, installation contents, and the packaged MCP workflow. They do not add paid model requests or replace the recorded content reviews.

## Install or update

Use tag `v0.2.4` or its resolved commit. The release source archive includes the self-contained plugin under `plugins/research-toolkit/`; keep that directory intact. Python 3.10 or newer is required for the local tools. Install `requirements-mcp.txt` only when using MCP. Keep task data outside the installation and preserve local customizations when updating.

The [installation and update guide](https://github.com/rrrrrredy/research-toolkit/blob/v0.2.4/docs/installation-versioning.md) explains content comparison. Existing tasks keep their saved profiles and review requirements; original evaluations keep their original versions. See the [full changelog](https://github.com/rrrrrredy/research-toolkit/blob/v0.2.4/CHANGELOG.md) for the complete change list.
