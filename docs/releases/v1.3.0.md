# Research Toolkit v1.3.0

[English](v1.3.0.md) · [简体中文](v1.3.0.zh-CN.md)

This release lets versioned installations receive the supplemental-requirement fix and the other changes already merged since v1.2.0. It is a minor release under the [1.x compatibility policy](../compatibility.md), because that range also adds the optional public-release-log query.

## Changes available to installed users

- **Requirements reach analysis and drafting.** Explicit `research_status(task, stage="analyze")` or `stage="draft"` calls return nonempty saved requirements as JSONL, including their status and evidence. Agents no longer need to copy this ledger into the brief. Ordinary status calls do not append it, and returning a requirement does not mark it satisfied. [PR #68](https://github.com/rrrrrredy/research-toolkit/pull/68).
- **Query a registered public release log.** CLI `check-updates` and MCP `research_check_updates(task, source_id)` return added or revised entries, source dates and related locations in the existing report. No change returns `unchanged`; reading or comparison failures return `failed` with a reason. The operation does not overwrite evidence, schedule monitoring or decide that a report conclusion is invalid. [PR #67](https://github.com/rrrrrredy/research-toolkit/pull/67).
- **Catch the same local-path error before delivery.** Draft and delivery checks share validation for source `url`, `read_evidence` and `evidence_path`, identifying the field and a valid task-relative path. [PR #65](https://github.com/rrrrrredy/research-toolkit/pull/65).
- The release also includes the already-merged bilingual reading pages, report-update case, external run records and optional links to Research Review and the AI industry corpus. The corpus remains separately delivered and is not a new core dependency or a measured Toolkit quality improvement.

## Validation and remaining limits

The implementation PRs passed their existing CI and targeted regressions. This release changes version metadata, changelogs and release notes, then regenerates the existing plugin; it adds no runtime code or tests and does not rerun the completed local regressions or model evaluations.

For the release-log feature, the actual Qwen Work online request returned `unchanged`. The added-version result was a replay using the real fetched page and its older entry, not a second observed online change. Other vendors and a live MCP-client end-to-end invocation remain unverified. The minimal client check is to reload the updated MCP service and call `research_check_updates` for an existing task and registered supported log: expect `unchanged`, or `changed` if the public page has actually changed; a read failure must remain `failed`. Preserve the saved baseline. See PR #67 for the recorded task, inputs and limits. User time savings and improved research quality have not been measured.

## Update

Update the complete installation to v1.3.0 while retaining local task data and intentional local edits. Restart the local MCP service if running. No task migration or new required configuration is introduced. Review and data repositories retain their own versions.
