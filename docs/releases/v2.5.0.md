# Research Toolkit v2.5.0

[English](v2.5.0.md) · [简体中文](v2.5.0.zh-CN.md)

This compatible feature release adds explicit report-sharing choices after delivery and expands the existing agent execution adapter's research capabilities.

## Sharing after delivery

After the first complete delivery in a project, the agent shows an invitation after the report link in the current conversation. It names the selected file, the maintainer's private `rrrrrredy/research-toolkit-usage` repository, the purpose and the project directory. Choices are: share this report once, allow future final reports in this project, or decline and stop asking. No reply queues no content. Chat and raw materials require a separate file selection and confirmation; report permission does not include them.

Managed tasks receive the invitation in `finish.content_sharing` only after `completed=true`. Skill-only work uses the same sharing instructions and `share-offer` command when commands are available. Refusal is remembered; revocation clears the project's pending content. Unchanged reports are not queued again. Existing disabled settings remain respected. Windows ordinary and extended paths now share the same project permission. The existing queue, receiver, UTF-8 file limits and basic-event settings are reused.

## Research through the existing agent tools

The adapter uses the configured Claude Code, OpenCode or Codex tools and permissions for source acquisition, calculations and research files. Each execution has its own directory; earlier outputs remain available. The existing `records.json` save fields register new sources and claims alongside the full contribution, binding original evidence, extracted text, scripts and results to the work used by downstream agents.

Existing record validation rejects conflicting writes. Incomplete contributions and rejected saves retain their original replies for correction. The same producer can continue after an input change; independent reviewers can recompute in their own directories. The adapter does not add permission-bypass flags or change account/model configuration. Research entry points, saved-task compatibility and required independent review, audit and acceptance remain unchanged.

## Verification and distribution

Retained checks cover compilation, workflow and record/continuity contracts, delivery/review contracts, MCP, bilingual pages and plugin synchronization. Local sharing scenarios cover consent, refusal, no reply, project permission, deduplication, revocation and disabled settings, including a before/after Windows path case. One native Codex execution obtained official material, ran calculations, resumed changed input and handed full artifacts to an assembler; the report completed the existing independent roles and `finish`. Original failures and corrections remain in the development records. Claude Code and OpenCode were not separately run with a model in this round. These observations concern execution and sharing behavior, not a research-quality comparison.

Update the complete installed copy to v2.5.0. The release includes the synchronized plugin ZIP and `SHA256SUMS`; Skill, CLI and MCP files are also available in the tagged repository/source archives. Existing downloads do not update themselves. No receiver deployment or task-data migration is required. Personal developer hooks and local research records are not part of the package.
