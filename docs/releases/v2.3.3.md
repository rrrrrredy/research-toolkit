# Research Toolkit v2.3.3

[English](v2.3.3.md) | [简体中文](v2.3.3.zh-CN.md)

Released on 2026-11-05.

This patch fixes an ambiguous completion result: CLI `finish` previously exited 0 when it returned `completed: false` together with `action_required`. It now exits 0 only for `completed: true`, while retaining the specific gaps and next actions in JSON. MCP retains the same business result; successful transport does not mean completed research. CLI `review` still exits 0 when it successfully prepares independent assignments.

## Checking retained completion

```bash
python scripts/check_delivery.py <task-directory> --require-complete --json
```

The read-only mode requires `stage: final`, `status: complete` and passing existing delivery, requirement, independent review, audit, acceptance and version checks. It does not call `finish`, launch reviews, modify task files or generate a receipt. Incomplete or stale delivery exits 1 with specific flags and findings. Completion checking uses the current delivery contract; historical `--contract-version 1/2` diagnostics remain available without this flag.

Default consistency checking can still pass valid in-progress records. First delivery can reuse the successful `finish.delivery_check`, without immediately repeating the same checks. Pure Skill use requires no new CLI/MCP records. English, Chinese and plugin copies are synchronized. The release also includes the already-merged removal of obsolete no-review wording from research examples (#137).

## Validation and compatibility

The existing CLI/packaged-MCP end-to-end control covers valid in-progress records, unfinished `finish`, pending `review`, completed current-version acceptance and later changes to prose or counterevidence. Completion checks leave task files unchanged. The repaired CLI and MCP return the same unfinished business result.

Affected Python compilation, delivery and review contracts, workflow and compatibility checks, documentation synchronization and plugin checks passed locally. Seven existing plugin symlink checks were skipped because the local Windows account lacks symlink privileges; CI checks the supported Linux and Windows environments. The PR retains the exact check results.

This is a completion-status and exit-code repair, not evidence of improved research quality. Existing saved tasks, response fields, independent review duties and default checking remain supported. Update the complete installed package to receive the repair; previous downloaded packages do not change automatically.
