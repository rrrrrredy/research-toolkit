# Research Toolkit v1.4.12

[English](v1.4.12.md) | [简体中文](v1.4.12.zh-CN.md)

This patch distributes [PR #116](https://github.com/rrrrrredy/research-toolkit/pull/116). In v1.4.11, review inputs include explicitly registered counter-evidence sources, but update hints can still omit claims whose source association appears only in `counter_evidence`. Updating the installed package delivers this fix. It is a compatible bug fix under the [version policy](https://github.com/rrrrrredy/research-toolkit/blob/main/docs/compatibility.md), so the version advances to **1.4.12**. No task-data migration is required.

## Changes

- Reuse one source-ID selection helper for review inputs and update hints. `save`, `status` and registered release-log queries continue to share the existing `impact_view` path, including both supporting and counter-evidence associations.
- Preserve literal claim/source-link locations, headings, line numbers, adjacent original text and `context_ref` deduplication. Free-text counter-evidence remains supported; only exact registered IDs separated by whitespace, semicolons, commas or `|` form counter-source associations.
- Synchronize English, Chinese and plugin copies. Add no tools, fields, calls, review steps or completion requirements. Preserve original reports, requests, responses and historical records.

## Observed results and verification

A controlled copy of the saved synthetic supplier task returned only supporting claim C4 before the fix; afterward it also returned counter-evidence claims C1 and C2. All three located the paraphrased passage through its citation on line 7, with original context on lines 5–9. Identical context was returned once. Partial/unregistered IDs did not create associations. Removing literal anchors kept the related claims as `not_located`, without inventing report positions.

**Release-log verification replayed saved synthetic material; it did not read a live endpoint.** The before/after runs each used four CLI calls and one offline release-log call, with zero model calls. Original records remained unchanged. This verifies the returned associations, not general semantic retrieval, better research quality, reduced rework or time savings; those benefits remain unverified.

Affected Python compilation, plugin synchronization and diff checks passed, along with 18 relevant existing checks: 12 record-workflow checks, five release-log checks and one counter-source input/version-binding check. Three checks initially encountered local SSL-log/temporary-directory permission failures; only those checks were retried after adjusting the check process environment, and both the original failures and successful retry were retained. PR #116's Linux, minimum-Python, Windows and static-site CI passed.

Release preparation reuses those results, checks the changed version metadata and new installation package, and relies on existing CI for the release commit. No research tasks or already-passed local behavior checks are rerun.
