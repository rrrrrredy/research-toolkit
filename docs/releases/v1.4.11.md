# Research Toolkit v1.4.11

[English](v1.4.11.md) | [简体中文](v1.4.11.zh-CN.md)

This patch distributes the fix merged in [PR #114](https://github.com/rrrrrredy/research-toolkit/pull/114). The v1.4.10 package can omit a counter-source's original text when its registered ID appears only in `counter_evidence` and the caller does not separately supply its file. Updating the package delivers the fix to installed users. This is a compatible bug fix under the [version policy](https://github.com/rrrrrredy/research-toolkit/blob/main/docs/compatibility.md), so the version advances to **1.4.11**, not 1.5.0. No task-data migration is required.

## Changes

- Include explicitly referenced counter-sources in the existing review input and version binding. Reuse local source reading, deduplication and revision handling.
- Keep `counter_evidence` as free text. Only exact registered source IDs separated by whitespace, semicolons, commas or `|` select files; the tool does not infer references from prose. Existing local-evidence requirements still apply.
- Synchronize English, Chinese and plugin copies without adding fields, calls or review steps. Preserve original reports, requests, responses and historical inputs. A changed source uses the existing explicit revision path rather than silently reusing an old input.

## Observations and verification

In the constructed before/after case, the old input included `offer.md` but omitted the counter-source `schedule.md`. After the fix, both originals are present, the counter-source text matches exactly, and the input version changes. The old frozen input and report remain unchanged. No model calls were made.

The targeted save → review-input → source-revision check failed before the fix and passed afterward. Six related existing checks, affected Python compilation, plugin synchronization and bilingual documentation checks passed. PR #114's Linux, minimum-Python, Windows and static-site CI passed. Initial local temporary-directory and long-path failures remain in the records; only previously failed checks were resumed after adjusting the environment.

Release preparation reuses those results and checks the changed version metadata and new package; existing CI checks the release commit. No research tasks or already-passed local behavior checks are rerun. **The observed result is corrected material delivery and version binding. Improved research quality, fewer report errors, reduced rework and time savings remain unverified.**
