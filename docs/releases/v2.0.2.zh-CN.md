# Research Toolkit v2.0.2

[English](v2.0.2.md) | [简体中文](v2.0.2.zh-CN.md)

发布日期：2026-11-02。

修复两处接续缺口：审计或最终验收首次提出的必要问题，可能没有进入下一版必须处置的集合；准备好的研究输入，可能没有随分析成果保存。

- 内容审阅、审计和最终验收共同使用必要问题承接路径。原始回复、输入和执行引用继续可读并绑定版本，沿用已有独立审计逐项处理历史问题。
- 通过 `status.work` 准备具名研究单元时，将选定输入版本、问题和依赖保存在已有活动历史中。保存该单元未显式提供 `based_on` 时，自动承接这次准备。不同单元各自保存，即使倒序保存也不会串用。普通状态查询保持只读。
- 输入选择、问题或依赖变化时，清除关联单元的缓存通过状态；原计划与回复保留，继续使用已有就绪与版本校验。
- 全局要求保存在任务规格中；局部提纲随对应分析保存，通过选定文件或实际单元依赖进入其他工作。这复用已有能力。旧规格若混合了全局与局部内容，仍保留整文件绑定，不自动拆分或迁移。
- 同步中英文指导、工具说明和插件安装包。公开操作名称、既有显式绑定和已保存材料继续兼容，独立审阅职责不变。

受控状态回放观察到：省略历史必要问题处置会被拒绝，正常处置可以继续；不同单元倒序保存仍保留各自准备；选定来源变化传到关联工作。局部提纲变化影响实际依赖它的分支，无关工作保持就绪；全局规格变化仍影响两个分支。原任务文件未改。

受影响代码编译、现有工作流／记录／接续检查、打包后 MCP 端到端检查及插件／文档同步检查已通过。一项 Windows 路径长度失败改用短临时目录后，只补跑该失败项并通过。回放响应使用合成协议夹具，没有重跑研究任务或模型调用。原始输出和更正记录保存在本地，与发布包分开。

上述结果确认已执行的接续行为，不据此宣称研究质量提升或用户返工减少。
