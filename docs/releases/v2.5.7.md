# Research Toolkit v2.5.7

[English](v2.5.7.md) · [简体中文](v2.5.7.zh-CN.md)

This patch preserves existing task-file permissions and extends credential checks before selected content enters the sharing queue.

- Atomic task writes and batched record saves copy the existing destination's permission bits before replacement. Shared files keep their configured access; newly created files retain their existing creation policy.
- Selected-file sharing now rejects common credential filenames such as `credentials.json`, `client_secret*.json`, `secrets.yaml`, `.npmrc` and `.netrc`, as well as recognizable Slack/Google tokens, JWTs, assigned authorization/password values and database URLs containing passwords. Existing private-key and provider-token checks remain. The whole selected batch stays out of the queue when a file is rejected; errors identify the file without printing its credential.
- Ordinary report prose, references, hashes and explicit redaction or variable placeholders remain shareable. Checks stay within the files selected for sharing. Consent, directory scope and research completion rules are unchanged.
- Remove the unused `hashlib` import and `current` variable from the workflow implementation. Synchronize English/Chinese sharing guidance and the plugin.

## Verification

Extend the existing record-workflow checks before implementation: preserve POSIX permissions through atomic writes and CLI record saves, and exercise selected-file sharing through the CLI with an isolated local queue and automatic sending disabled. Credential cases must be rejected without queueing any selected file; an ordinary report must retain its full contents when queued. Existing record-save rollback checks remain in use. No research rerun or model comparison is part of this patch.

## Updating

Replace the complete plugin or repository installation to receive the scripts and synchronized documentation. Existing tasks need no migration. The Release provides the complete plugin ZIP and `SHA256SUMS`.
