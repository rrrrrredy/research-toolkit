# Research Toolkit v1.3.1

[English](v1.3.1.md) · [简体中文](v1.3.1.zh-CN.md)

This patch delivers the public release-log address fix and the report-context improvements already merged since v1.3.0. It introduces no new tools, required inputs or task migration.

## Changes

- **Public-address filtering follows the actual connection.** Trailing-dot hostnames are normalized, every DNS result must be public, and the connection uses an already-checked numeric address without a second lookup. Host, SNI and certificate verification still use the original normalized hostname. Redirects remain disabled. [PR #77](https://github.com/rrrrrredy/research-toolkit/pull/77).
- **Report locations include usable context.** `save`, `status` and registered release-log queries return the matched paragraph and adjacent original text, retaining headings and line numbers. Identical context within one response is returned once; subsequent locations use `context_ref` pointing to its first occurrence. Claims, sources and match reasons remain on their own entries; equal text at different locations remains separate. [PR #75](https://github.com/rrrrrredy/research-toolkit/pull/75), [PR #76](https://github.com/rrrrrredy/research-toolkit/pull/76).
- The package also includes the merged guidance on model evaluation as a user perspective and bounded verification, removal of public corpus pages and entry points, and synchronized bilingual descriptions of the nine tools. Data repositories keep their own release versions.

## Network behavior

Registered release-log reads now connect directly, ignoring environment and system proxies so the destination checked locally is the one actually contacted. Networks that require a proxy may return the existing `failed` result with a reason. Other operations and TLS verification are unchanged.

## Validation

PR #77 passed its Linux, Windows, minimum-Python and static-site CI checks. Its two targeted offline checks covered rejected local/private addresses, one-time DNS resolution, the pinned connection, hostname-based TLS and ignored proxy settings. Compilation and plugin/site consistency checks also passed. These implementation checks were not manually rerun for this release; release preparation checks the changed version metadata and generated package.

The new transport has not been verified by a live request or on a proxy-only network. An optional environment check is to reload the updated MCP service and query an existing registered supported log: expect `unchanged` or `changed`, or an explicit `failed` result if the direct connection is unavailable. Preserve the saved baseline. No new time-saving or general research-quality claim is made by this release.

## Update

Download the [v1.3.1 plugin ZIP](https://github.com/rrrrrredy/research-toolkit/releases/download/v1.3.1/research-toolkit-plugin-v1.3.1.zip), or update the complete checkout to `v1.3.1`. The ZIP contains the plugin directory, including both manifests, bilingual instructions, shared runtime and methods. Install it using your host's existing plugin mechanism; Python 3.10+ and MCP dependencies still apply. Preserve local tasks and intentional local edits, and restart the local MCP service after updating.
