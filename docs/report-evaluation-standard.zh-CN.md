# 报告评测现行标准

[English](report-evaluation-standard.md) | [简体中文](report-evaluation-standard.zh-CN.md)

本页是项目的评测设计，不是所有研究工具箱用户的额外要求，也不替代 [SKILL.md](../SKILL.md) 的研究方法。新报告研究按此执行，旧冻结实验保留原量表和原评审人数。

## 统一量表，分别回答问题

当前报告评测使用五个维度，每项 **0–4 分**或 `not_assessed`：

1. 任务忠实度；
2. 事实与证据；
3. 解释与综合；
4. 反证与边界；
5. 读者可用性。

深度仍在实质分析和用户要求的成果中判断；可读性包括有用开篇、连贯结构、具体表达和不混入工作日志。

统一分值：0 为关键要求缺失或失败；1 为重大缺陷导致该方面不可用；2 为部分满足但需实质修改；3 为满足任务且问题有界；4 为展开充分且支持具体。缺乏评估上下文使用 `not_assessed`，不算零分或批准。每项分数附理由和可定位摘录。不计算加权总通过分，也不将旧 1–5 分结果换算合并。

| 结果 | 能说明什么 |
|---|---|
| 执行记录 | 实际使用的方法、来源、工具、阶段和干预；文件存在不证明发生顺序或实际阅读。 |
| 首次提交质量 | 执行分配工作流内部检查后、接触共同外部反馈前的第一份完整成果；失败也保留。 |
| 修复与交付 | 有效反馈带来的改动、新版质量、回归和达到可用所需工作。 |
| 产品效果 | 独立且条件匹配的任务中，基线与工具箱的比较；不是反复修改的展示稿质量。 |

## 完整评测流程

1. **任务准入**：保存来历、读者、截止日、范围、来源访问、权利及题族暴露；写作前冻结特定覆盖和证据要求，不提供希望得到的研究结论。
2. **冻结配置**：工具箱版本、作者与环境设置、正常工具、评审条件及终点。基线关闭待测工具箱，保留正常搜索和普通自查；隔离上下文并随机安排配对顺序。资源、停止和重试规则在批次前确定，不在本标准中暗设 15 或 60 分钟时限。
3. **执行工作流**：工具箱条件包括提纲、研究、分析、分节写作与审查，以及实际全稿阅读。起稿前核对提纲是否回答实际问题，章节层级是否支撑论证；证据改变论点时调整。遵守任务明确要求的独立结构审查，不默认再加四模型提纲面板。捕获真实事件，不补造历史。
4. **锁定首稿**：保存首份完整稿，不覆盖。四名非作者评审独立获得同一完整任务、正文和证据。当前研究由 Codex 内 Astra 写作；新 Codex 上下文的 GPT-5.6 Sol high、DeepSeek、Kimi 和 GLM-5.3 high 评审。这是研究配置，不是工具箱依赖。
5. **锁定评审**：分享反馈前保存原意见。记录每条发现、分歧和失败调用。作者或执行者查看实际段落及来源，再决定采纳，不能以投票代替证据。
6. **保留结果**：冻结报告、原评审、证据标签、失败及未决结果进入评测集。样稿不必修到可用才算评测完成。传输或格式失败不是报告质量零分，重试不能静默替换。当前面板须每路取得完整、有实质内容且对应版本的有效评审；达到重试批次上限时诊断和恢复，不据此关闭缺失席位。历史失败不追溯改成当时已完成。补齐缺失评审不授权改稿或重做已有有效评审。
7. **改进产品**：将原始结果汇成产品反馈，决定采纳内容和理由，修改工具箱并验证受影响行为。修好报告不是前提；已知严重产品缺陷可以先修，但版本组分别保存。最终项目验收包括这部分产品工作。

修订稿及评审与首次提交数据、主要比较分开；它们记录额外反馈、干预、回归和工作量，不自动成为参考答案或改进证明。保留可观察时间、token、已知费用、未知收费和未决限制。

## 评审有效性、独立裁定与抽查

按照[角色规范](../references/subagents-and-review-loop.zh-CN.md)和[完成记录接口](review-completion.zh-CN.md)，分别记录调用状态、实质有效性、报告判断和最终验收。每名模型覆盖共同量表，专业侧重不能删减维度。保留第一份有效回复，不挑选最有利的重试结果。

每份评审核对真实覆盖及证据。严重或重大发现、决定性来源争议和关键不采纳决定须独立裁定。按声明的总体和方法抽查通过项、未报问题段落及已报缺陷。实质差错触发受影响范围的检查，不自动授权全体模型重评。个别误报可以逐项裁定，不废弃整份有效评审。

## 缺陷、修复与停止

评测任务保留已证缺陷，用于产品迭代；样稿失败不启动修稿循环。必需材料缺失仍是未决发现，不成为通过报告。评测完成不认证报告可交付。

任务另外包含正式报告交付或返工效果研究时，才单独集中修改、核读受影响分析及全稿，并取得研究要求的同版四路评审。旧评审不能批准新正文。以下要求用于这一交付工作：

| 核对后的发现 | 处理 |
|---|---|
| 严重 | 编造或足以翻转结论的事实、主要成果缺失、隐瞒决定性限制、来源指令取得控制、虚假完成：记录并修复，未解决不能正式交付。 |
| 重大 | 必答问题、关键机制、比较或证据链实质不足，或须重组才能使用：记录并修复。 |
| 轻微但已证实 | 事实不精确、误导句、坏引用等局部问题集中修复，不能只因标为 minor 就忽略。 |
| 可选偏好或无依据指控 | 记录不采纳或不修改理由；多一列、重复提示或喜欢某种标题，不自动要求重跑。 |

未完成的必读或必做任务不能靠披露限制关闭，放弃须有相应用户决定。允许有界研究的任务则如实说明证据未知及影响，不编造答案或删掉问题。

正式交付须满足原任务，重要判断有依据，分析和深度充分，当前全文实际读过，四份当前评审完整且逐条裁定，无未解决的严重、实质或其他已证缺陷；适用记录与正文一致。四票通过、高总分或脚本 PASS 不能替代这些要求。

重要要求和用户明确纠正须定位到当前稿实际满足的段落、表格或其他成果，并核读内容是否成立。填满映射表、获得 PASS 或旧稿曾满足，都不能销账。标题、开篇和章节结构也对照任务核查，不能只看上轮列出的修改。哈希可识别旧版审查，但不证明认真或正确。

达到要求后停止润色，不要求模型再也提不出意见。新实质缺陷应处理，重复可选建议不是新进展。遵守事先声明的返工机会与停止规则；一般修复授权不会将全部样稿可用变成评测终点。

## 公平对照与工具箱改进

首稿对首稿。若比较返工，两组预先获得相同反馈、返工机会和停止规则，初始与修后结果分别报告；不能把九轮修好的报告与一次生成基线直接比较。额外辅导、用户纠正和环境变化单列。

用户报告、补充开发题、评审控制和正式独立题分别计数。用于改规则的题不能再算留出；换标题、翻译或同题重跑不增加独立样本。12 题族是筛查设计，不是统计保证，抽样与分析在运行前锁定。本研究使用四路 LLM 替代人工评测，人工审阅、标注或校准不是验收前提；事实争议仍按原文裁定，原分数、意见和失败保留。

每个产品问题交付：失败样例、影响、原因、采纳／拒绝／暂缓理由、实际修改、相关回归结果及剩余边界。区分方法欠缺、已有规则未执行、检查器缺陷、资料读取错误和模型误报，不把一切都变成新提示词。

工具箱未改、只是根据反馈修好报告，只能说明输出修复。项目修改做相关验证；只在新更改、失败或具体未决问题出现时重复或扩大检查。更广泛效果验证使用未参与开发的任务，不自动开启新一轮。

旧七维人工量表及双／三模型开发样例是历史记录，不是现行标准，也不换算合并。兼容说明不改原数据。
