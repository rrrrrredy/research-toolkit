# 评测路线与可声明的结论

[English](evaluation-roadmap.md) | [简体中文](evaluation-roadmap.zh-CN.md)

研究工具箱需要不同类型的证据。把它们合为一个总分，会掩盖每类证据实际能支持什么。

新报告研究使用[现行评测标准](report-evaluation-standard.zh-CN.md)：五维 0–4 量表、四名非作者评审、基于证据的处置、冻结首稿结果、单独界定的报告交付及评测后的产品改进。旧冻结量表和评审人数保留为历史，不是另一套现行要求。

## 证据层次

| 路线 | 问题 | 当前证据 | 可声明 | 不能声明 |
|---|---|---|---|---|
| A：确定性符合性 | 成果是否符合配置的流程与交付规则？ | 已有正常控制、22 个负例、来源完整性检查 | 对已测试样例能识别已知结构与追溯问题 | 报告事实正确、有洞察或有用 |
| B：真实任务效果 | 与普通 Agent 行为相比，工具箱是否改善有决策价值的研究？ | 历史首评已完成；结果与失败见[评测现状](evaluation-status.zh-CN.md)，不声明当前版本有普遍效果优势 | 在预先登记、留出任务及独立评审下得到的有界处理效应 | 对所有模型、任务和组织普遍更好 |

## A：确定性符合性

保持快速、离线且在无效记录上拒绝通过。新增机械规则同时需要：此前被接受或可能回归的已知负例，以及证明规则不会靠拒绝全部输入来改善表现的正常对照。

结果使用 `result_schema_version: 2`、`conformance_status`、`conformance_score` 和 `conformance_flags`。`research_quality_status` 保持 `not_evaluated`。100 分只说明配置的机械检查没有发现问题。

虚假完成、最终审查记录格式错误、配置的来源指令违规等高风险标志会阻断；`review` 默认也以非零退出。

## 开发报告与评审诊断

[2026-09-07 证据包](../evals/diagnostics/2026-09-07/)保留实际开发报告、失败、编辑修复与三模型文本诊断，不属于留出研究。模型与供应商、上下文暴露、检索权限、请求及返回身份、未完成响应和裁定分别说明。不同供应商有助于提供不同观察，其一致意见不是真实答案，也不是人工校准。

台账维护间隔、停滞触发和审查轮次等数字是执行启发式参数，没有消融结果证明它们最优。澄清不规定问题数量，只询问缺失的关键信息，相关工作须等关键选择明确后再推进；只有观察到过早停止、漏掉停滞、重复搜索或维护负担时，才据此设计有范围的比较，不能把数字精确当作有效性。

| 停滞信号 | 观察单位 | 动作 |
|---|---|---|
| 两个完整单元循环没有进展 | 从证据到论证的循环没有新增分析价值，即使找到了来源 | 调整结构视角 |
| 三次搜索或来源读取没有收获 | 同一收集方向没有新证据 | 停止该收集方向 |

这只是既有规则解释，不新增状态 schema 或阶段文件。自行生成非空门槛文件不证明阶段发生顺序。当前凭证绑定最终成果与审查，完整中间过程仍只能部分观察。

## 当前报告与评审安排

开始新的报告写作或模型评审前，完成并验证已采纳的方法、执行、检查器、数据和文档更正。离线回归是准备工作，不是效果研究；CI 通过不自行授权启动研究。

| 历史研究后端（保留原记录，非默认依赖） |
| --- |
| 当前开发配置由 Codex 中的 Astra 担任唯一作者，实际加载固定工具箱并采用其工作流。每份首稿接受四路独立评审；报告交付或返工研究在范围内时，修订稿也按该研究配置执行：新 Codex 上下文的 GPT-5.6 Sol（`gpt-5.6-sol`，`high`）、DeepSeek、Kimi 和 GLM-5.3（请求 `high`）。后三者是评审者，不替代作者。这是研究配置，不是工具箱依赖 Codex 或四模型的要求。 |

失败报告和未决发现保留为评测结果。冻结首稿结果进入数据集及产品反馈，不要求样稿全部修到可用才迭代工具箱。返工记录单列，不构成工具箱效果证明。

四路收到同一完整版本的任务、报告与提供证据，并绑定版本哈希。各自锁定回复前不接触其他当轮意见。记录实际上下文、工具、来源权限、可见身份、截断和失败。三份回复不能算四路完成；作者自查不算独立评审，不同模型也不保证统计独立。

部分三评审开发运行开始后才加入 GLM，原冻结和意见保留；同输入补充评审标明后来加入，不能称为最初已预登记四路。GLM 使用受支持的 Coding Plan 客户端，参见[官方接入说明](https://docs.bigmodel.cn/cn/coding-plan/tool/others)；不能任意以 HTTP 消耗订阅额度。记录客户端与直接 API 的上下文差异；返回 token 和客户端估价不等于已认证的订阅费用或剩余额度。

完整评测链包括任务准入、冻结配置、提纲、研究、分节写作、锁定首稿、必需评审和证据裁定。缺陷与失败保留，用于诊断工具箱并验证相关修改。尚未完成且仍属必需的评审应补齐，各次尝试单列，不改原稿、原失败或发生顺序。有效评审发现问题不触发再评。

修稿属于另行界定的正式交付或返工研究；旧评审不能批准新正文。评测中的已证缺陷即使始终没有修复，也仍是结果，好评票数或均分不能抹掉。无依据的模型纠错不能抄入报告或缺陷标签。

本路线不要求人工评审。冻结新研究前用已知错误及有效控制核查量表，结果明确标为 LLM 判断并保留证据核查边界，不称为人工校准的真值。确定性评测器不会因此自动给出研究质量 PASS；旧实验原评审人数和数据不倒填。

## 下一项研究：先冻结设计，再产生新证据

重点是研究决策质量的配对比较，而不是继续增加连接器工具。公开的 2 组校准对照、7 个流程任务和 23 组合成诊断属于开发材料；原生英文展示案例增加的是可读案例，不是留出覆盖。历史研究的事后剔除和配额失败，也使补跑视图不能作为干净的效力估计。

下一批可使用[研究模板](../evals/templates/paired-study.json)。它尚未填入具体研究：**模板不代表新增留出任务已经冻结，也不代表已有模型结果**。12 个任务族的提议只是筛查方案，不是最终样本量要求。任何作者运行前，完成以下约定：

1. 从明确的目标工作负载选择彼此独立、使用权清楚的任务族。根据目标人群纳入原生中英文，以及产品、公司、技术、政策等问题，事先固定分层数量；翻译、改名和重跑仍属同一任务族。校准任务单列。
2. 固定每份 brief、任务特定要求、来源访问规则和暴露记录。留出 brief 不进入开发调试或作者调参上下文；执行前提交哈希与时间，意见锁定后在权利允许时公开原文。哈希只能绑定文件，不能证明无人看过。无法排除暴露时，称为前瞻开发数据，不称为留出数据。
3. 固定一个作者模型快照、运行环境、工具箱 commit 和 profile。两组使用同一 brief、正常工具和总资源上限；工具箱内部评审计入处理组 token／时间预算，共用的评测评审另计。记录实际用量与配额失败；重要资源无法同口径计量或限制时，披露并收窄“同预算”声明。
4. 在语言与任务类型块内平衡随机安排两组先后，尽量在相邻时间运行；使用新上下文，隔离实验生成记忆。另行随机安排盲化报告的评审顺序，所有意见锁定前保留条件映射。记录可识别的条件线索，不能仅因有台账或来源 ID 就加质量分。
5. 固定五维量表、四路评审配置、证据裁定和[必要缺陷标签](necessary-defects.zh-CN.md)。除每份报告自身证据外，评审输入和访问权限一致；评分后再记录评审猜测到的条件线索。这能检查泄漏，不保证盲化绝对成功。
6. 冻结样本量、排除、重试与失败规则、主要终点和区间方法。公开全部准入任务、失败、干预与逐题结果；后来排除的任务仍保留在最初分母中。新版本或配额恢复补跑单列，不能替换首次结果。

### 结果与不确定性

主要终点是各条件是否存在经证据裁定的必要报告缺陷。同一任务族只有一组无必要缺陷时，该组获胜；两组都有缺陷、两组均无必要缺陷分别保留。缺少报告或必需有效评审时，比较为未决，不算获胜。严重性及五维评分作为次要结果保留；执行完成率单独报告。

运行前根据精度目标和预算选择独立任务族数量。举例说，二元比例约为 50% 时，12 个独立观察的 95% Wilson 区间约为 ±25 个百分点，40 个约为 ±15 个百分点。这是设计计算，不是工具箱结果或统计功效保证。[NIST 区间公式](https://www.itl.nist.gov/div898/handbook/prc/section2/prc241.htm)适用于单个二项比例，不能直接作为配对处理差异的区间。

配对效应用事先约定的配对方法；如使用 bootstrap，应按完整任务族重采样，保留两组及其评审观察的对应关系。四份评审不是四个独立任务。说明抽样总体、语言和模型分层，公布全部任务的结果比例及缺失；仅完成样本的质量差异属于条件性结果，可能受选择性失败影响。方便样本增多不等于已证明泛化。

公开校准对扩容用于调试与评审检查，效果估计使用另外冻结的任务。区间很宽也如实报告；不能为了得到有利区间持续加样本。扩样或序贯设计须在看到研究结果前约定。

首稿与首稿比较。若另测返工效果，两组事先约定相同的外部反馈、返工机会和停止规则，修后结果单列。基线不因缺少工具箱专用台账或凭证而丢语义质量分；正常联网任务不应仅为评测方便改为固定来源测试。12 个独立任务族在一个作者环境中需要 24 次主运行；额外重复用于敏感性分析，不增加独立任务族数。

## 数据与发布

- 不测事实新鲜度的公开确定性检查优先采用合成材料。
- 内部矛盾记录须隔离，不能为保住题数继续使用。
- 联网效果研究先冻结任务输入和时间边界，再保留各条件实际观察的来源、访问时间和失败；不为评测器方便擅自改成固定来源任务。
- 再分发权不明确的私人或许可材料不进入公开包。
- 开发、评审校准和最终留出数据分别保留。

schema v2 与带标签的预发布版本已提供。当前 main 还包含 CHANGELOG 中 Unreleased 的更新，旧发布归档不含这些后续更改。真实任务研究须在运行前冻结，保留首稿与发现；仅在完成运行和证据核查实际支持的范围内发布比较。
