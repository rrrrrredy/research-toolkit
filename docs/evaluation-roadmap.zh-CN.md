# 问题修复与验证路线

[English](evaluation-roadmap.md) | [简体中文](evaluation-roadmap.zh-CN.md)

当前工作是修复已发现的问题并检查结果。使用已有真实任务，Astra 担任独立评审者；无需外部评审人员、外部供题或固定四模型面板。完整规则见[报告检查与修复标准](report-evaluation-standard.zh-CN.md)。

## 当前顺序

1. 从现有报告和执行记录定位问题，区分工具缺陷、方法遗漏、执行不到位与稿件错误。
2. 能复现的软件问题直接修代码、补相关回归、提 PR；方法确有遗漏才修改指令，不把每个模型错误都变成更多规则。
3. 对不合格稿件直接修正事实、推荐、遗漏或篇幅，检查当前文件，交 Astra 核对任务与来源。
4. 必要问题解决、相关检查通过后交付或合并；原失败和修后版本分别保留。

这些任务不等待额外的研究项目。测试用于判断修复是否有效，不用于不断抽取一个好结果。

## 现有材料与检查

[评测现状](evaluation-status.zh-CN.md)保留已有真实研究、开发报告、诊断任务与模型评审。用户题、开发题及参考案例均为真实独立任务；实际执行的测试都是真实测试。同题改名、翻译和换模型不增加题数。

软件回归检查输入、状态、解析、版本绑定与交付规则；Astra 核对报告中的判断和来源。机械检查通过说明相应软件行为通过；报告内容以实际复核结果为准。无需为日常修复建立额外评审队伍、数据保管人或准入项目。

## 可选：比较工具箱前后的结果

以前文档中的“效果研究”指比较使用与不使用工具箱的结果。它是可选比较，不是当前修复、验收或合并的前提，也不要求外部题目或外部人员。需要时使用已有真实任务，事先说明版本、评审和资源，保留首稿与修后结果，Astra 可完成评审。

[配对模板](../evals/templates/paired-study.json)和[任务选择说明](independent-task-design.zh-CN.md)用于整理这类比较，不是等待填写后才能工作的门槛。结果只按实际完成的任务解释；原失败不删除、修改稿不冒充原首稿。

## 历史记录与发布

旧实验按其实际模型、人数、原量表、尝试和失败保存，不倒填新规则；四模型等历史配置不构成今天的默认依赖。仅发布可分享的材料，保留必要的来源与版本信息。已有修复随通过检查的 PR 合并，不等待额外比较。
