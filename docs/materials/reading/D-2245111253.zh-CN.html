大模型推理加速方法研究01期

一、为何 LLM 的简单推理很缓慢？有哪些关键指标？

1.算法层面：

从算法角度看，每个循环需要处理越来越多的 Tokens，因为每个循环都会向上下文添加一个新 Token。随着生成过程的进行，模型的速度会逐渐降低，因为每次生成新 Token 时，都要处理更长的前缀。至少在普通的注意力机制中，算法是二次方的，所有 Token 都关注所有其他 Token，这导致了 N² 级别的复杂度增长，进一步加剧了问题。

2.硬件层面：

3.判断 LLM 的推理速度时，通常关注以下几个关键指标：

① 首个 Token 响应时间：从收到输入到输出第一个 Token 所需的时间有多长；

② 整体生成延迟：从收到输入到完成最终 Token 输出的时间长度是多少；

③ 吞吐量：系统能同时处理多少个独立的生成任务；

④ 硬件利用效率：对计算资源、内存带宽及其他硬件功能的利用程度如何。

二、现阶段，加速 LLM 推理效率方法有哪些分类？

1.算法优化

① 使用批处理（batching）：将多个输入样本一起处理，以减少模型的前向传播次数，提高硬件利用率和推理吞吐量。

③ 优化注意力机制：改进注意力计算的算法，减少计算复杂度，例如使用稀疏注意力机制或近似计算。

2.硬件优化

① 使用更好的硬件：购买更高性能的硬件设备，如 GPU 或 TPU，以提高推理速度。

② 充分利用硬件：优化程序代码，充分利用硬件的计算、内存带宽等能力，提高推理效率。

③ 使用加速器：使用加速器（如 GPU）进行推理，可以获得显著的速度提升，但需要注意 CPU 和加速器之间的数据传输瓶颈。

3.编译器优化

① 使用编译器：使用编译器对模型进行优化，将 Python 代码转换为针对特定硬件优化的内核，提高推理速度。

② 融合操作：将多个操作融合为一个更高效的操作，减少内存分配和数据传输，提高推理效率。

4.模型压缩和量化

① 模型剪枝：通过删除冗余参数和连接来减小模型的大小，从而减少推理时间。

② 模型量化：将模型参数从浮点数转换为低精度表示，减少内存占用和计算量，提高推理速度。

三、LLM 推理加速方法有哪些？

1.批量生成优化

① 批量生成是一种优化技术，用于提高大语言模型在生成文本时的效率。这种方法的核心在于同时处理多个序列，而不是逐个序列处理。

② 通过批量处理，整批序列的处理时间远少于分别处理每个序列的时间。例如，使用 GPT-2 生成 20 个 Token，对于 1 个序列大约需要 70 毫秒，而对于 5 个序列则约为 220 毫秒，远低于线性增长的预期（350 毫秒）。

③ 持续批处理是对批量生成方法的进一步优化，旨在提高资源利用率和处理效率。通过持续批处理，可以确保 GPU 在整个生成过程中始终保持高效运行，不会因为部分序列的早期完成而浪费计算资源；同时，在传统批量生成中，已完成的序列可能会继续生成无关的 Token。持续批处理避免了这种情况，因为一旦序列完成，就会立即用新序列替换，避免生成不必要的 Token。

2.缩减模型权重

① 缩减模型的权重是一种优化技术，旨在减少大语言模型在运行时所需处理的数据量，从而提高推理速度。

② 缩减权重的方法包括参数剪枝和知识蒸馏。

③ 缩减模型权重可以减少计算负担，通过减少模型的参数数量，可以降低在每次推理中所需的计算量；同时，提高处理速度，较小的模型通常意味着更快的处理速度，因为有更少的数据需要在内存和处理器之间传输。

② 多重查询关注机制是一种改进的注意力机制，用于提高模型处理多个查询的效率。传统的注意力机制一次处理一个查询。多重查询关注机制允许模型同时处理多个查询，从而提高效率。此外，优化计算过程，这种机制通过优化计算过程，减少了对资源的需求，特别是在处理大量数据时。

③ PagedAttention 是一种优化技术，旨在处理大型模型中的注意力机制的内存限制问题。在处理大型输入时，PagedAttention 将注意力矩阵分成多个「页面」，每个页面单独处理。这种方法减少了一次性需要的内存量，使得处理大型模型变得更加可行。

4.投机性解码

① 投机性解码是一种优化技术，用于加速语言模型的文本生成过程。这种方法通过并行生成多个潜在的候选 Token 来加快生成速度。

② 传统的自回归生成方法一次生成一个 Token。投机性解码允许模型同时生成多个潜在的候选 Token。一旦生成了多个候选 Token，模型会基于某种标准（如概率）选择最佳的候选继续生成。

③ 阈值解码方法通过设定一个动态的概率阈值来决定是否接受草稿模型生成的 Token。如果累积概率高于阈值，则继续生成；否则，停止并提交给判定系统。

④ 分阶段推测性解码方法采用树状结构的生成过程，而不是单线生成。它适用于处理复杂文本，因为它允许生成多个草稿序列，并使用特定的注意力掩码与预测模型进行核对。

⑤ 引导式生成通过约束模型的输出符合特定的语法规则，来确保输出内容的可靠性。它通过自动插入符合语法规则的 Token 来加快处理速度。

⑥ 预见解码方法在模型的两个分支上运作：预见分支预测并延伸候选的 N-gram，而验证分支用于验证这些候选项。这是一种在单一模型中实现的复杂但有效的解码策略。

⑦ 提示查询解码技术通过在上下文中进行简单的字符串匹配来代替传统的草稿模型生成方法，特别适用于需要大量直接从输入中复制内容的任务，如代码编辑或检索增强生成。

四、还有哪些硬件加速方面工作值得关注？

1.提升推理速度的一个直接方法是采用更高性能的硬件

① 使用加速器可以显著提高处理速度，但需要注意的是，CPU 和加速器之间的数据传输可能会成为瓶颈。如果模型无法完全装入加速器的内存中，那么在前向传递过程中，模型可能需要频繁在内存与加速器之间交换，这会大幅降低运行速度。例如，苹果的 M1/M2/M3 芯片之所以在推理性能上表现出色，部分原因是它们实现了 CPU 与 GPU 的统一内存管理。

② 此外，在使用 CPU 或加速器进行推理时，还需要考虑是否充分发挥了硬件的潜能。经过良好优化的程序能够从性能较低的硬件中挤出更多效能，而未经优化的程序即使在顶级硬件上也可能表现平平。

五、案例：苹果新的大模型推理方法

苹果的研究者提出通过在闪存中存储模型参数来加速大模型推理，该方法在 CPU 和 GPU 上分别实现了 4-5 倍和 20-25 倍的推理速度提升。

近期一些工作表明， LLM 在前馈网络（FFN）层中表现出高度稀疏性，其中 OPT、Falcon 等模型的稀疏性更是超过 90%。苹果的研究者基于利用稀疏性， 有选择地仅从闪存中加载具有非零输入或预测具有非零输出的参数。

研究者在最小化数据传输、最大化闪存吞吐量两个关键领域进行了优化，提出了两种技术，分别为窗口化和行列捆绑。

① 窗口化：仅为前几个 token 加载参数，并重用最近计算的 tokens 的激活。这种滑动窗口方法减少了加载权重的 IO 请求数量；

② 行列捆绑：存储上投影和下投影层的串联行和列，以读取闪存的更大连续块。这将通过读取更大的块来增加吞吐量。

同时，为了进一步最小化从闪存传输到 DRAM 的权重数量，研究者设法预测 FFN 稀疏性并避免加载归零参数。结合使用窗口和稀疏性预测可以为每个推理查询仅加载 2% 的闪存 FFN 层。此外，研究者还提出了静态内存预分配，最大限度减少了 DRAM 内的传输并减少了推理延迟。

实验结果显示，闪存加载成本模型在加载更好数据与读取更大块之间取得了平衡。与 CPU 和 GPU 中的 naive 实现相比，优化该成本模型并有选择地按需加载参数的闪存策略可以运行两倍于 DRAM 容量的模型，并将推理速度分别提升 4-5 倍和 20-25 倍。

大型语言模型（LLM）在实际部署中普遍面临推理速度慢的问题，其根本原因在于自回归解码机制的串行特性、内存带宽瓶颈以及KV Cache的显存占用，核心评估指标通常包括首Token延迟（TTFT）、每Token生成延迟（TPOT）和吞吐量（Throughput）等维度。

当前LLM推理加速方法已形成较为完整的分类体系，主要涵盖模型压缩、高效解码、系统优化与硬件加速四大方向。模型压缩层面包括量化（如INT8、INT4量化）、剪枝与知识蒸馏；高效解码方向涵盖投机解码（Speculative Decoding）、并行解码及非自回归生成方法；系统优化方面则有PagedAttention、FlashAttention、连续批处理（Continuous Batching）等关键技术，显著提升了GPU利用率与服务吞吐能力。

硬件加速层面，针对LLM推理的专项工作同样值得重点关注，包括面向Transformer架构优化的专用芯片设计以及内存计算协同优化方案。

作为典型案例，苹果公司提出了面向设备端部署的大模型推理新方法，通过结合模型分层卸载与动态计算调度策略，在iPhone等边缘设备上实现了高效的本地化推理，为端侧LLM部署提供了重要参考路径。整体来看，LLM推理加速已从单一技术点延伸至算法、系统与硬件的协同优化，是当前AI工程化落地的核心研究课题之一。
