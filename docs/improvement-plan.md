## Executed design and future study boundary

Freeze the protocol, then tasks and call settings, before running. This cycle used four provider APIs as authors and requested `gpt-6-astra` through Codex for development judgments; actual access and returned identities follow connectivity evidence. Connectivity calls are not quality observations. Astra can review in a new context separate from the author. No different vendor or model is required; the blinded context does not receive condition mappings.

Start task design in five areas: numerical definitions and units, decisions under conflicting evidence, causation versus correlation, constrained option comparison, and time-sensitive evidence synthesis. Reuse relevant existing tasks; stratify English/Chinese, and do not count translations or model repeats as independent families. Use each task's supplied provenance and time boundary. Scenario material does not invalidate the actual task or an executed test. Existing user and development tasks retain their real provenance and distinct-question identities; record reuse without excluding them.

Masking uses a fixed report/notes separation rule. Both arms place execution and independent-review status in notes; judge packets contain only the brief, sources, rubric and A/B reports. Do not delete sentences, rewrite reports or relabel after outcomes appear. Record residual tool/model/process clues and disclose masking limits. Presentation reversals diagnose position sensitivity, not additional tasks. Calibrate judges using length-matched valid/defective controls with concrete evidence; model agreement is not factual truth.

The original connectivity phase declared five first attempts. Failures were retained before a separately frozen follow-up: five generations completed across six network requests and one local preflight failure, with no automatic paid retries. The four-family calibration pack separately requires 12 judge calls per model, with its own frozen configuration and budget; those are not included in the five connectivity generations. This Astra calibration round is complete and recorded separately. Before the completed batch development run, a machine-readable plan was saved specifying models, call counts, token/time limits, retries, matched resources, reviewer panel, source hashes and outcomes. Follow the [current standard](report-evaluation-standard.md) for repairs; Astra can provide the review. Any additional comparison is optional and does not block repair or merging.

## Tradeoffs and updates

Do not add mandatory confirmations, infer truthful research from minimum text length or words such as “unread,” force holistic preferences to equal dimension sums, or move/delete assets without checking references. Check installation commands on supported platforms rather than globally replacing `python` with `python3`. Directory repackaging and large-asset migration follow reliability and method work.

Update this page with status, PRs and acceptance evidence at each merge. Report workflow completion, mechanical conformance, manuscript quality and toolkit effects separately. Use API credentials only in local calling processes; study configurations store environment-variable names. Check requests, responses, errors and sources for sensitive content before publication.
