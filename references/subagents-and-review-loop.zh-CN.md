# 子 Agent 与审查

[English](subagents-and-review-loop.md) | [简体中文](subagents-and-review-loop.zh-CN.md)

本页维护研究生产交接、独立内容审阅、审计和最终验收的方法。按当前任务读取相应部分。宿主提供子 Agent 运行能力，Toolkit 提供研究输入、方法和版本明确的成果。

## 实质研究与交接

研究问题存在可独立负责和推进的工作时，使用宿主原生子 Agent。边界和初始输入明确后即可派发，主 Agent 同时继续研究与协调。宿主原生委派无需另行配置 API。

主 Agent 负责原始问题、有效要求、整体提纲和跨部分判断。子 Agent 可以调查来源、计算、比较、检验解释、展开局部论证和写作。明确一位全文统稿者，可以是主 Agent，也可以是专门的生产 Agent；只有这位负责人编辑主稿，其他研究者保存各自成果。委派统稿不转移主 Agent 对最终研究判断的综合责任。

按实际问题和依赖分工，同时保留覆盖维度。例如国内外研究须明确每个地区及必需公司的研究责任，以及谁负责跨地区的机制比较。按机制拆分不能丢掉地域覆盖，按地域拆分也不能让跨公司解释无人承担。派发输入包括当前问题、相关原始要求与补充、提纲上下文、可读来源和已有分析、期望产物及依赖该成果的后续工作。

按研究单元逐步推进，不等到最后才一次生成整篇报告。单元可以是一项比较、计算、案例、机制或相互连贯的论证。负责人将证据和推理发展为可使用的分析或正文。后续单元依赖重要结果前，把前提、依据和当前产物交给相关独立审阅者核查。不相关单元可以并行；新发现改变研究时，由主 Agent 更新提纲和依赖，统稿者持续整合已有成果并保留充分分析。

### 保留实质内容的交接

交回实际成果、原始依据及相关位置、成立条件与假设、未决问题，以及下一位负责人可直接使用或还须处理的事项。完整计算和论证通过原件交接，不能用状态消息替代。修订已保存成果时保留前一版本。

交接包括研究者之间、研究者到统稿者、作者到审阅者、审阅者到修订者，也包括同一 Agent 从已完成阶段进入下一阶段。原上下文继续时可复用已有成果与当前笔记；换上下文时须使这些材料在接收端可访问。新要求和输入变化须明确发送，启动时取得的父上下文快照不会自动包含后续纠正。

压缩或更换上下文前，保留有效要求、提纲、已成立判断及其条件、待决事项、当前成果和原始材料位置。简短交接用于导航，接收者据此读取相关完整成果和来源后再使用；原文与原始评审回复始终可访问。不补造缺失历史，不以摘要覆盖原件。

使用 CLI／MCP 时，通过现有 `status.work` 选择要求、主张、来源和文件，取得 `work_context`，用 `methods` 加载相关方法。`save` 的 `draft.kind="analysis"` 登记成果，`based_on` 绑定取得的输入，`host_task` 保留真实执行者引用；单元、依赖和交接信息随成果保存，不另建任务管理系统。请求格式见[使用说明](../docs/usage-modes.zh-CN.md#研究委派与成果交接)。纯 Skill 在已有宿主对话与文件中保留同样的实质信息。

启动、等待、消息、取消与恢复由宿主负责，保留真实任务／会话引用。分支运行时继续不受影响的工作，消费依赖成果前等待实际结果。保存成果只表示局部进展，不代表已合稿、已独立审阅或整个任务完成。生产上下文不能冒充其产物的独立审阅者。

## 按视角分工

每项完整研究交付均须完成以下七项基础视角，分别使用不同且与所有生产 Agent 分开的上下文；任务涉及专业判断时增加相应领域专审。使用宿主原生子 Agent，作者自检不能替代这些工作。独立性来自上下文与生产职责分离，不要求不同供应商或外部人员。

| 视角 | 方法与必需产物 |
| --- | --- |
| 意图与要求（`requirements`） | 阅读原始要求及有效补充，将重要问题、必需对象和约束对应到实际段落或表格；找出未答问题、范围偏移和修订中丢失的指令。不编造新要求，也不保护被证据推翻的预设论点。 |
| 证据与数据（`evidence`） | 对照原始来源核查重要主张、时间、版本、人群、单位、分母和计算，区分事实、来源说法与推断。说明实际阅读范围；访问元数据和来源摘要不能证明读过原件。 |
| 对抗性质疑（`adversarial_reasoning`） | 用相关反例、竞争解释、选择偏差和遗漏假设检验核心结论，说明对论证的影响；不制造问题，不设发现数量配额。 |
| 结构与深度（`structure_and_depth`） | 检查问题、提纲、章节、证据与综合如何形成答案，定位缺失机制、不可比口径、过度压缩的推理和来源复述。按任务需要的深度判断，不强套结构或篇幅。 |
| 读者用途（`reader_usefulness`） | 按目标用途通读成稿，检查标题与开篇、论证连贯、术语引入、表格、时间线和实际含义，指出具体理解或决策障碍。 |
| 去过程化（`process_language`） | 定位读者正文中的生产日志、内部路径／编号、评审状态和助手对话；保留回答读者问题所需的方法、来源归属、不确定性与操作细节。 |
| 自然表达（`natural_expression`） | 定位空泛抽象、重复免责声明、模糊主体、生硬句法和同义反复，解释阅读问题及合适改法。保留事实、限定、分析深度和用户风格偏好，不设禁词或 AI 检测目标。 |
| 领域专审 | 使用相应领域标准：技术基线与实验条件、财务假设、政策适用、临床人群等；说明检查的领域和主张，由单独的非作者上下文承担。 |

每位评审使用新的任务上下文，读取当前完整报告、原始要求和有效变更，以及其职责所需的原始依据。不向该上下文注入作者自评、其他首次评审的判断、预期分数或偏好的评审结果；相关实质研究分析仍然可读。局部前提审阅说明有限范围，不能代替最终的全文视角。按实际交付格式检查，包括引用能否使用、表格与图示的含义。

## 共同任务说明

提供问题、读者、有效要求、实际稿件和输入版本、原件访问方式、所分视角及产物要求。评审者说明检查范围、可定位观察和判断依据。每条发现注明位置、对应要求、证据、影响和严重程度，区分必要修正与可选偏好；未发现缺陷时说明支持这一判断的检查，不能只返回笼统 PASS。

评审者保持只读。原始回复和可观察的执行身份与结构化提取、作者回复分别保留。纯 Skill 可保存在宿主对话或已有文件中；工具管理任务使用[评审记录接口](../docs/review-completion.zh-CN.md)。不编造缺失的会话身份或来源访问。

## 完成每一路必需评审

完整评审须针对实际范围和版本给出实质观察。空白、截断、错版本或泛泛回复都使任务保持开放。保留失败尝试，修复输入或执行问题后接续该任务。必需材料超过一个上下文时，将原件保持为可读文件，安排范围完整的分段阅读与综合，不能静默用摘要替代。

同一输入与稿件版本保留首个有效结果。负面发现是完成了评审，不是重跑以求好评的理由。个别错误意见应被裁定，不能据此丢弃整份评审。重要无效判定和有争议的不修改决定由审计者据证处理。未收到必需材料的评审仍未完成；实际阅读后证据不能确定答案，可以形成有依据的限定判断。

作者落实必要修正，也可以说明为何不同意某条发现；不能自行批准稿件、取消必要修正或把未完成评审标为完成。保留发现与回复供独立审计。修订后把当前完整成果、相关变化交回受影响的评审者；未变证据继续可读，历史结果仍绑定实际阅读的版本。

## 核查评审者并抽查通过项

每项完整研究任务都明确分配独立审计上下文，与生产者和内容评审者分开。审计者取得完整报告、有效要求、原始来源、研究成果、原始评审和修订／处置依据。评审有效性与报告能否交付分别判断：有效负评可以说明报告仍有必要修正。

逐份检查必需评审的实际执行及输入版本、职责覆盖、可定位观察、判断依据和是否编造要求。核查全部重要发现与分歧，包括决定不修改的意见。依据原件和实际正文裁定，不用多数票或平均分替代。每条原始意见保留有依据的处置：已证缺陷、不修改、未解决或已解决。声称修好后，只有实际检查改文及受影响上下文才能确认已解决。

重要要求、决定性主张、关键数字及引用、重要反证、重大发现和必要修正全部核查。同时检查被判通过或没有发现问题的内容，包括子 Agent 分析进入报告时发生的改写。审计者从完整成果选择样本，不依赖作者挑出的片段。

这部分抽查在现有审计结果中保留总体或报告范围、选中位置、选择理由、来源核对和结果。按相关章节、证据类型及改写关系选择，不默认固定比例或首尾／哈希段落。定向样本明确称为定向，不能声称随机。发现差错后，按同一来源、指标、分支或推理错误扩查影响位置，记录扩查及结果。

审计者可以要求原研究者或评审者补齐工作，在修复后继续同一审计。必要缺陷及依据不足的重要不修改决定保持开放。证据确实无法裁定的问题在相关结论处说明，不以此取消未完成的必读或评审任务。抽查融入审计与最终验收，不另设抽查 Agent、分数或审批流程。

## 阶段安排与验收

1. **提纲与初始前提：** 主 Agent 规划问题、覆盖和依赖；要求与结构评审者在大范围依赖写作前检查提纲；证据／领域评审者核查逐步形成的重要前提和计算。早期局部检查保留局部身份。
2. **研究单元推进：** 研究者逐步形成有依据的论证。可能改变后续工作的前提先解决，再作为已成立依据使用；其他独立单元继续。成果到达或提纲改变时，统稿者持续更新全文论证。
3. **完整报告：** 七项基础视角与适用的领域专审读取完整稿件。落实读者和表达意见时保留事实与深度。独立审计核对评审、重要发现、必要修正，并抽查已通过内容。
4. **最终验收：** 另一个与生产、内容评审及审计分开的上下文，对照有效要求阅读当前完整报告，查看审计、处置和实际现稿，全核重要要求及必要修正，按整合问题补充检查已通过内容，返回验收结果或具体未完成工作。验收 PASS 不能替代缺失的必需评审或审计。

最终验收者核对交付版本、来源与条件保留、完整覆盖、分析展开和读者用途。跨部分矛盾或限定丢失退回对应生产／评审任务，明确受影响范围与输入，保留原发现和旧稿。协调者摘要不能代替这次阅读。

正式交付要求必要修正落实、独立职责完成、当前全文通过验收。阶段成果可以按准确的未完成范围交付。历史与评测原件保留原始缺陷及标签，保留证据不等于获得当前契约的认证。约定成果与必需工作完成后，可选偏好不重启未变内容的评审。
