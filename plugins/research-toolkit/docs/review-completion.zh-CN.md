# 独立审阅、审计与验收

[English](review-completion.md) | [简体中文](review-completion.zh-CN.md)

本页说明现有 `research_review` 与完成检查如何保留独立工作；实质方法以[角色规范](../references/subagents-and-review-loop.zh-CN.md)为准。新研究和继续交付采用当前契约，冻结结果保留原契约与历史。

## 执行独立工作

宿主运行 Agent，Toolkit 准备输入、保存产出并返回仍待完成的工作。Codex／Claude Code 子 Agent 使用宿主已有能力，无需另配 API。

| 任务 | 独立职责 |
| --- | --- |
| 七项内容视角 | 需求、证据、对抗推理、结构与深度、读者用途、过程语言、自然表达，各由一个非作者的新上下文负责；每位都看到完整当前报告及必要原件。 |
| 领域专审 | 核对任务所需的专业知识、计算、术语或技术前提，补充基础视角。 |
| 审计 | 另一位独立 Agent 检查审阅有效性、重要发现及其处置、决定性判断，并抽查已通过内容，指出仍需修正的问题。 |
| 最终验收 | 再由一位独立 Agent 阅读完整当前稿、有效要求、审计及实际修改，再决定是否可交付。 |

作者、研究贡献者和统稿者属于生产参与者，可以解释或修订自己的成果，不能审自己的成果。使用真实宿主任务／会话身份；在作者上下文换一个角色标签不算新 Agent，模型则可以相同。

通过现有 `research_save` 的稿件 `host_task` 登记主稿实际写作者；选择主稿时同时使用 `main: true`。旧保存输入仍可使用，但主稿作者尚未登记时，须先补上身份再准备独立审阅。之前的生产参与者继续保留在活动记录中，不能占用独立席位。

前段可对提纲、假设、计算或论证单元进行独立审阅，检查后续工作所依赖的输入，并绑定该单元的成果和来源。它不替代全稿审阅或最终验收；最终视角读取整合后的完整论证及跨章节一致性。

## 原生调用与原始结果

向 `research_review` 提供当前任务、稿件和证据路径。未选用外部执行器时，返回待完成的宿主原生任务及已保留的完整输入；宿主据此启动各独立 Agent，并给予原件访问能力。

提交形式示例：

```json
{
  "task": "study",
  "artifact": "reports/current.md",
  "evidence_paths": ["sources/primary.md"],
  "host_result": {
    "slot_id": "copy-the-returned-slot-id",
    "host_task": "actual-independent-host-task-id",
    "response_path": "reviews/host/original-response.json",
    "execution_path": "reviews/host/original-execution.json"
  }
}
```

这里是占位值，不是完成记录。将实际原始回复和执行记录保存为任务内非空 UTF-8 文件；返回任务说明所需结果内容。不从作者的理解拼出有利回复，不覆盖负评，不编造宿主标识；失败和不完整尝试也保留。

返回的 `assignments` 每项提供 `slot_id`、`role`、`assignment_ref`、`assignment_version`，本次操作另有 `input_version`。原始 JSON 回复须带回两个版本。原始执行记录包含 `host_task`、`status: "completed"`、`assignment_version` 及实际观察到的宿主事件，必须来自产生该回复的实际执行。

`scope` 默认是 `full_report`；`domains` 指定领域专审名称，新全稿计划默认 `["domain"]`，始终包含七项基础视角。前段单元审阅将已登记 `unit_id` 作为 `scope`，在现有 `perspectives` 中选择相关视角。新单元默认 `domains: []`，省略参数时保留此前已声明的领域专审；单元审阅不减少最终全稿职责。

单元的必要发现或有据不改回应需要独立裁定时，在同一 `research_review` 调用中使用 `audit: true`。该输入已有的内容审阅继续有效，下一项任务是单元审计。开启后，后续调用保留这项责任，不能通过 `audit: false` 撤掉；单元不会因此增加最终验收。全稿始终需要审计。单元审计核对 `applicable_requirements`，包括全局要求、明确分配给本单元或其上游依赖的要求；全部有效要求仍可回读。

同一操作接收内容结果，准备独立审计，再在必要问题解决后准备最终验收。输入未变且已有有效结果时，继续未完成工作，不重复产生一次通过。`include_assignment` 默认 `false`，返回已保留的输入引用，执行者仍须能够读取完整输入及来源原件。

另配命令或端点是可选执行方式，见[使用说明](usage-modes.zh-CN.md#评审后端)，同样履行独立性和当前版本要求。历史 `self` 结果继续可读，但属于作者自检，不是当前独立审阅路径。

## 输入与版本绑定

保留各任务实际使用的需求、有效补充要求、报告、来源与主张记录、相关原始材料及方法指令。支持来源和已登记的反证来源一起进入输入，网址列表或作者摘要不能替代必要原文。

计划与结果绑定稿件及所需输入版本。任务中继续保留输入、指令快照、原始回复和执行记录；文本哈希仅规范换行，不改写原研究记录。文件引用须位于任务内并匹配其哈希。

当前任务使用 `progress.review_contract: 2` 和 `review_plan.contract_version: 2`。已有 `logs/review.jsonl` 保留 `model_review`、`review_audit`，并增加独立的 `final_acceptance` 记录。这些是审阅契约标识，与交付检查器的契约编号分别管理。

实质修改后保存新稿或来源版本，使用 `revision: true` 处理受影响审阅，保留之前的任务和回复。最终全稿验收覆盖交付正文；历史结果表示当时检查过什么，不自动批准后来的文字。

新的修订任务通过 `revision_context` 提供之前的冻结输入、同一视角的原始回复与执行引用、变化和未变材料的输入哈希，以及改稿前后的原文与行号；审计和验收也可回查已保留的内容审阅引用。执行者据此找回已有核查，检查受影响的推理并确认完整当前稿，不自动沿用旧 PASS。已冻结的任务说明保持原样。

## 发现与必要修正

有效审阅包含定位、依据或推理，并实质覆盖所分视角。负面判断也可完成审阅，但必要修正仍未解决。通用 PASS、截断回复或读错材料的回复不能完成任务。

保留原始结论和严重程度。作者可以提出修正或有据不改的回应，由独立裁定核对原意见是否误判、当前正文是否已经解决，或仍待处理。作者不能追加一个处置状态就关闭自己的必改项。可选偏好无需转成修改；重要的不改决定必须对照原稿和证据核查。

不反复运行同一未变版本的有效负评以求通过，继续发生变化或确实缺失的工作。某条意见错误不意味着整份实质审阅无效；保留并裁定具体发现。

## 审计与抽查

审计者读取完整当前稿、要求、审阅结果和相关原件，从这些内容中选择检查项，不只接收作者挑出的片段。

关键要求、决定性结论、关键数字与引用、重要反证、重大问题、重要不改决定，以及会影响成果的已修正主张，都应核查。其他已通过／未报问题的内容按实际研究选择样本，覆盖支线到主稿的转换、必要限定及跨章节判断。

每个选择保留位置、原因、所看证据和结果。不用固定首尾／哈希选段或抽样比例代替判断。发现问题后按原因扩查，例如同一来源、指标、支线或改写方式，直到查清受影响工作并解决必要问题。此工作由已有审计任务承担，不新增抽查角色或评分体系。

审阅有效、报告就绪和最终验收是不同判断。审计可以确认一份负评有效，同时指出报告仍需修订。最终验收读取修订后的完整报告，不能只数通过记录。

## 完成与恢复

`research_finish` 检查当前报告、有效要求和独立职责是否完成，再写最终状态及回执。作者不手写一条全局 PASS 或替代回执关闭缺失工作。

查看工具任务时可运行：

```bash
python3 scripts/check_review_completion.py <task-directory> --artifact reports/current.md
```

命令读取记录和版本绑定，不再启动一位评审者。实际内容判断保存在原始回复和证据中，应保留全文，不只保留解析字段。

宿主取消、依赖不可用或回复格式错误时，保留失败原件，解决实际原因后继续该任务。不因固定执行时长或模型调用次数改变研究责任。同一任务写入复用已有任务锁，不另建协调服务。

## 历史记录

早期 `model_review`、`review_audit`、`sampling_audit`、处置和回执按实际使用的条件保留。1.x 自评、合并视角和可选审计记录不升级为 v2 验收。继续交付时复用原材料，完成当前独立工作，不抹去旧失败或声称这些工作早已发生。见[兼容性](compatibility.zh-CN.md)。

冻结评测和研究对照沿用其原始协议，描述当时研究，不作为新研究的默认要求。软件正负对照明确标注合成，不能代替真实宿主执行。
