# 接续已有研究任务

[English](task-continuity.md) | [简体中文](task-continuity.zh-CN.md)

用户补材料、要求比较、调整范围或继续修改时，沿用已有任务和记录。报告另存文件不代表重新开始研究。以下约定用于恢复、实质修改和交付，不要求每次改字都更新记录。

## 项目入口

项目已有的 Agent 指令可以引用本页，无需复制整套 Toolkit 或新增台账：

> 根据有效的用户要求、当前报告、相关来源和未完成工作继续。复用仍有效的研究，修订时保留原版本，宣布完成前核对实际成果，沿用任务约定的评审要求。

纯 Skill 可以从对话、已提供文件和现有笔记中恢复这些信息。跨会话或交接时，保留否则会丢失的信息，不规定统一登记表、版本日志或回执。新指令替换与其冲突的旧要求，未被取消的目标继续有效；接受反馈不等于已经修好正文。

CLI／MCP 管理的任务按下节使用已有任务 ID 和工作区。`start/status.runtime` 标识本地实现及其可用入口文件，不证明宿主实际加载了该 Skill。怀疑入口过时时，使用现有安装比较与明确版本核对，不增加每轮健康检查，不静默升级在途任务。

## 恢复与保存

本节适用于 CLI／MCP 管理的任务；纯 Skill 按上节复用已有材料。

`research_status` 返回 `current_work`，包含规格和要求路径、未结要求、显式选定的主稿，以及存在时的上次交付引用。读取相关笔记和实际文档；摘要、作者回复不能替代正文。认定附件缺失前，检查用户已提供的本地路径。文件确实不可得时说明实际比较范围，继续不依赖该文件的工作。

通过 `research_save` 更新受影响的字段和记录。可选 `brief` 局部更新六个需求字段，同时更新 `state/task_spec.md` 与 `progress.brief`。可行时在同一请求中保存使用稳定 ID 的要求变化。新指令替换与其冲突的旧要求，未被取消的目标继续有效。豁免要求时保留用户的实际决定。

brief 更新保留规格中手工补充的章节。如果某字段已被直接修改，与保存值不一致，先核对该字段再重试；整批请求不会覆盖其他内容。明确的范围决定可以终止旧阅读要求，无需改写其历史字段；重新开启时须满足有效的阅读要求。保存后利用返回的 `current_work` 查看状态，无需立即重复同一查询。

用 `draft.main=true` 显式登记当前主稿。可选 `draft.kind` 为 `report`、`comparison` 或 `review`，说明本任务交付什么，不代表被评文档已经改完。`complete=true` 只登记完整草稿，不代表完成交付。章节稿和参考稿不会因保存时间较晚自动成为主稿。保存已登记的主稿路径会更新其观察摘要；审阅和交付须指向该路径。未登记主稿的旧任务维持原有行为，不按最新文件猜测。

接受反馈不等于已经修复。检查实际正文与相关上下文后，才能用具体证据更新现有要求或审阅处置；未核验的修改保持开放，不另设反馈台账。交付比较或评阅时，明确完成的是评阅，还是被评文档的修改。

## 选择复核范围

- **全文比较：** 对照两份当前正文，覆盖用户要求的范围。比较说明中的差异只是线索，不能代替全文。吸收互补解释，避免拼接两稿，也不强求双方采用同一种结构。
- **基线有效的局部修订：** 查看完整 diff、修改段落及上下文、受影响来源和要求、未结意见。复用已经读过且未变的证据。工具使用现有 `revision=true` 流程，对冻结输入中的当前完整稿作出真实判断；不能复制旧 PASS、替换摘要，或把局部检查当成全文批准。独立评阅者仍收到完整的必需输入。
- **缺少可靠基线：** 找出未覆盖范围并补足核验，不为中间版本追认通过。最后只改了一小处，不代表此前未经审阅的广泛修改已经合格。

自审不属于独立审阅。明确的独立要求需要单独上下文。通过既有适配器导入审阅时，保留实际执行身份、原始回复和对应输入；`capture.import_only=true` 将导入与模型调用分别统计。该标记不证明独立性，也不放宽版本绑定。不得给历史反馈编造执行身份、耗时和 token 数。

新正文已解决的问题应撤回旧批评。偏好差异使用 optional 或有依据的 no-change。必要问题已解决、所选检查通过后即可结束，不为寻找新问题再次审阅未变输出。

## 删改时保留分析

删除重复解释和过程叙述时，保留时间、预测性质、实验条件及来源能够支持的范围。检查公司、产品代际和研究阶段的归属。术语或章节存在，不能证明机制解释准确，也不能证明其影响已经进入结论。

面向决策的研究保留推荐、理由、替代方案的代价和改判条件。问题需要时，解释技术机制与合作双方的价值；不虚构内部团队、资源和排期。要求不安排他方经营任务，不等于取消生态分析。标题、章节和数量沿用用户当前要求，不套统一报告模板。

## 恢复手工或过期项目

读取已有规格、有效的用户变更、实际稿件和未结反馈。保留原件，根据内容与用户决定处理相互矛盾的引用，不按目录时间判断。显式选定当前稿件。只修复继续工作所需的记录；工具恢复完整记录集合时，`replace` 会留存原件。无需统一全部历史文件，不推断未观察到的阅读，不补造历史执行回执。

已有任务保留完成约定，按[历史任务兼容](../docs/usage-modes.zh-CN.md#历史任务兼容)接续。复用仍有效的材料，不重写历史。

这些做法针对具体遗漏；机械检查和诊断样本不能证明报告质量或耗时普遍改善。
