# AI Agent 市场格局：从模型能力转向可控执行

## 核心判断

**AI Agent 的竞争单位正在从模型转向完整任务系统，但工程化进展不等于通用自主性成熟。** 平台提供推理与入口，工作流产品组织任务，协议连接工具，企业治理决定哪些动作可以真正执行。战略价值在于以可接受的成本和责任边界完成任务，而非增加智能体数量。

第一，平台型玩家与垂直工作流产品不是简单替代关系。OpenAI、Anthropic竞争模型与开发者使用场景，微软、谷歌、阿里等依靠办公、搜索和终端入口分发能力。独立产品若仅包装模型功能，容易被平台吸收；若掌握业务规则、异常处理和结果验收，则仍有差异化空间。

第二，低推理成本与MCP等连接标准可能扩大应用供给，也可能压缩应用溢价。模型更便宜、工具更易接入之后，客户更有理由要求产品证明业务收益。连接数量不能替代可靠性，调用规模也不能替代利润。

第三，近期更合理的投入方向是**有边界、可验收、能接管的自动化**。编程、企业流程和受控跨应用操作具有可见产品进展；完全无人值守的跨系统执行仍受可靠性、权限及责任约束。以下判断对应记录所覆盖时期，不代表截至2026年10月的实时市场状况。

## 范围与证据

本报告比较国内外软件型AI Agent，重点讨论平台、工作流产品、协议生态与商业采用；机器人和自动驾驶仅用于区分边界，不据此估算软件市场。按《AI Agent研究报告》的技术解释，LLM型智能体由规划、记忆、工具使用组成，技术栈还包括平台、编排、执行和应用。这里将“能调用工具并根据反馈推进任务”作为分析重点，不把所有聊天产品都等同于自主代理。

证据为四篇脱敏二手记录，缺少原始链接、作者身份及可复核底表，不能作为公开事实的独立权威。《AI Agent研究报告》《近期 AI Agent 趋势》未注明日期；后者的“近期”“将于11月”等说法不能换算为当前发布状态。两篇月度观察分别覆盖2025年12月和2026年2月，其月份也不等于精确发布日期。

这些记录能够支持产品方向、技术机制和竞争假设，但不足以建立市场份额、最新价格或厂商利润排名。下文保留重要数字的出处；经营建议是分析判断，不是已经观察到的行业共识。

## 竞争格局

### 平台：模型、入口与组织关系构成不同优势

**OpenAI与Anthropic的可见竞争集中在模型能力及开发者工作流。** 《AI Agent研究报告》将基于OpenAI API的AutoGPT作为早期代表，说明基础模型可催生外部应用，但不证明这些应用拥有独立商业壁垒。《近期 AI Agent 趋势》描述Anthropic开放Claude 3.5 Sonnet计算机操控能力，并称OpenAI正在测试Windows操控Agent；这是当时的产品方向记录，而非今天的可用性清单。

《AI行业月度观察202602》进一步记载GPT-5.3-Codex、Claude Opus 4.6及Claude Code的进展，并提到GitHub集成Claude与Codex。其战略含义是：开发者可以在同一工作环境接触不同模型，模型厂商要争取的不只是一次调用，还包括任务发起、执行和审查环节。模型能力能吸引试用，但能否嵌入团队交付流程更影响持续使用。

**微软与谷歌更接近既有工作入口的扩展。** 《近期 AI Agent 趋势》记录Dynamics 365业务Agent及Copilot Studio的自主触发、动态计划、活动概览，目标是企业流程自动化；对Project Jarvis的描述则限于Chrome浏览器，并带有秘密开发性质。《AI行业月度观察202512》记录Google Workspace Studio的零代码Agent构建方向。两者相比，前者更强调业务流程触发与管理，后者把构建能力放入办公环境；不能据此断言任何一方已赢得企业采用。

**国内入口竞争与低成本模型供给并行。** 同一篇2025年12月观察记载千问整合多终端入口、钉钉推出Agent OS，并将DeepSeek-V3.2描述为推理能力的重要进展。2026年2月观察又报告DeepSeek的DualPath和量化探索。DeepSeek在这组证据中首先是模型及效率供给者，不能与掌握办公入口、客户合同的平台按同一指标排名。更便宜的模型可能降低创业门槛，但权限、部署和客户支持成本不会自动消失。

### 工作流产品：谁负责把输出变成结果

编程是证据中较清晰的工作流方向：代码可以通过测试、运行和人工审查形成反馈。《AI行业月度观察202602》把趋势概括为从“人写代码”转向“人审代码”。这不意味着工程师退出，而意味着瓶颈可能转移到需求定义、代码审查、系统集成和故障责任。自动生成越快，验证不足带来的积压也可能越大。

企业流程产品的价值则取决于数据和组织关系。Copilot Studio、Workspace Studio、钉钉Agent OS的共同点，是把自动化嵌入已有工作环境。独立厂商若要竞争，应承担平台通用能力难以覆盖的行业规则、例外处置或跨系统验收，而不是仅提供另一个对话框。

消费者代理面临不同约束。《近期 AI Agent 趋势》描述AutoGLM面向购物、外卖和订酒店等移动操作；《AI行业月度观察202512》则记载豆包手机助手跨App操作引发平台风控。能识别界面，不等于获得平台授权，更不等于交易成功后的退款、争议和责任已解决。因此，消费者入口优势与交易执行能力必须分开评估。

### 协议与多模态：扩大可达范围，不保证执行质量

《AI行业月度观察202512》将MCP协议标准化列为生态趋势，并把竞争焦点概括为标准、工具市场和治理体系的组合。连接标准的潜在价值，是减少应用对每个工具分别集成的重复工作，让工具更容易跨产品复用；但记录没有给出协议覆盖率、兼容性测试或故障率，尚不足以判断生态成熟度。

标准化还可能改变价值分配：如果更换模型与工具变得容易，单纯依靠专有连接维持客户的能力可能下降，权限管理、服务质量和业务数据的重要性反而上升。这是条件性推论，不是已有市场份额结论。MCP接入也不能被视为授权、身份校验和审计的替代品。

多模态使Agent能够理解屏幕并操作缺少接口的系统。《近期 AI Agent 趋势》描述截屏转结构化元素、OmniParser屏幕解析及Ferret-UI移动界面理解，并区分端到端训练与利用现有多模态模型两条路线。其价值是扩展可自动化范围；代价是界面布局、弹窗和状态变化都可能增加执行不确定性。因而，优先使用稳定且获授权的API、以GUI补足覆盖缺口，是比全程模拟点击更审慎的产品选择。

## 商业化路径：从调用收费走向结果核算

现有记录不足以比较实际报价，但可以区分三条商业路径。模型平台可通过API用量或产品订阅获得收入，关键约束是推理成本与留存；工作流厂商可围绕席位、任务或部署服务收费，关键在于融入流程并控制交付成本；入口型平台则可能借Agent提高既有产品使用率或促成交易，但必须区分新增收益与原有业务迁移。上述是商业机制分析，不是对各厂商现行合同的确认。

《AI行业月度观察202512》称部分零售企业已构建数百个智能体，覆盖数万员工、百万级对话，并开始计算ROI。这说明运营指标进入讨论，却没有证明回报为正。智能体数衡量部署广度，对话量衡量使用活动；真正的经济性需要合格结果、人工投入和维护支出共同解释。

建议以“每个合格完成任务的全成本”比较Agent、人工、传统RPA和固定规则流程。成本应包含推理、集成、重试、人工复核、异常处置和维护；收益应扣除未兑现的理论节省时间。结果收费只有在任务边界与验收责任清楚时才有意义，否则双方会把争议集中到“是否完成”。

对产品负责人而言，优先选择输入相对稳定、结果可验收、错误可撤回的流程。先保留人工批准与异常接管，再依据真实运行表现扩大权限，而不是先承诺端到端自治，再补治理。

## 采用阻力与失败模式

**第一，长任务会放大小错误。** 《AI Agent研究报告》指出多智能体存在调用成本高、长上下文需求和可操控性差等瓶颈。规划、检索、调用和状态确认中的偏差可能沿后续步骤传播；增加角色也可能增加协调与纠错开销，而非提高成功率。应记录中间状态、设置停止条件，并将不可逆动作置于审批之后。

**第二，跨系统授权比屏幕理解更难迁移。** 豆包跨App风控案例说明，用户希望完成任务与目标平台允许自动执行不是同一件事；金融App对屏幕共享的敏感性尤其限制通用操作路线。《AI行业月度观察202512》提出系统级权限、动作沙箱和标准化接口作为可能方向，但未证明这些措施已普遍落地。

**第三，工具调用正确不代表业务判断正确。** 按《AI Agent研究报告》的解释，Function Calling将自然语言需求转换为函数参数。即使调用格式有效，收件人、金额或业务对象仍可能选错；长期记忆也可能让过期信息进入后续决策。这些是架构推导的风险，不是来源测得的事故率。相应措施包括数据有效期、最小权限、关键参数确认及操作审计。

**第四，组织收益可能被监督成本抵消。** 当员工必须逐项复查输出，自动化只是把执行劳动变成检查劳动。固定且稳定的任务可能更适合传统规则；只有任务变化带来的灵活性收益足以覆盖模型不确定性时，Agent才有经济理由替代它。采购验收因此应覆盖完整工作周期，而非只观看成功演示。

## 反证与不确定性

“Agent仍停留在早期演示”并非不受挑战。《近期 AI Agent 趋势》记录Claude 3.5 Sonnet在OSWorld的准确率为14.9%，人类约为70%—75%；《AI行业月度观察202602》则报告GPT-5.3-Codex在OSWorld达到64%。后者构成能力进步的重要信号。但模型、时间及测试设置未统一，不能把两组数字直接解释为同条件提升，也不能据此宣称生产系统已接近人类可靠性。

反过来，“已经全面工程化”同样证据不足。2026年2月观察报告千问AI购物六天订单超过1.2亿单、Kimi近二十天收入超过此前全年，但没有给出订单口径、促销影响、退款或利润信息。规模增长不等于独立Agent业务实现可持续盈利，更不能用于推算全行业市场规模。

对安全与替代效应也需克制。该月报关于OpenAI、Anthropic削减安全承诺，以及Claude Code引发IBM股价下跌的叙述，缺少政策原文和因果识别，不能推导出“安全约束已取消”或“软件外包已被取代”。同样，《近期 AI Agent 趋势》转述的Gartner采用比例属于预测，不能充当已实现结果。

**综合结论是有条件投入，而非等待通用自治或押注全面替代。** 平台选择应同时检验模型能力、业务入口、工具授权和退出成本；产品投资应围绕可核算的任务结果。若试点在计入监督及维护后仍持续优于人工或RPA，可逐步扩展；若优势主要来自补贴、演示任务筛选或未计入的人力，则应收缩自治范围。能改变这一判断的关键证据，是可重复的端到端可靠性、清晰的授权关系和持续为正的任务经济性。
