# 中英文评审校准对照

[English](README.md) · [简体中文](README.zh-CN.md)

四个虚构开发题族提供 12 份评审输入：每族各有有效／缺陷配对、精确 A/B 互换，以及同一有效稿件的平局对照。**目前没有模型评审结果。** 这些公开材料由实现者编写，与五个开发任务及未来留出研究分开。v3 是材料包版本，不改变协议 v2 或研究 schema 2。

| 题族 | 已知缺陷 | 每份稿件篇幅 | 主输入的有效标签 |
| --- | --- | --- | --- |
| `cal-relative-rate-en` | 混淆百分点和相对降幅 | 48 个空白分隔词 | A |
| `cal-causal-zh` | 在混杂的温室观测中声称已识别补光因果效果 | 148 个非空白字符 | B |
| `cal-attribution-zh` | 将供应商自报改成获得独立验证 | 134 个非空白字符 | A |
| `cal-constraints-en` | 推荐违反首年硬预算的方案 | 65 个空白分隔词 | B |

算术题族引用三份未改动的 [v2 输入](../judge-calibration-v2/README.zh-CN.md)，新增九份输入覆盖因果、归属及决策约束。每份缺陷稿只改变对应有效稿中的一个关键短语。中文按非空白 Unicode 码点计数，包含标点、数字和引用标记，不是 token 数；英文按 Python 空白分词，包含引用标记。等长只减少一种呈现差异，不能消除风格、位置或模型偏差。不用最小篇幅或维度加总认证正确性。

## 仅供协调者读取

`coordinator-manifest.json` 记录输入路径／哈希、预期偏好、报告及来源定位片段、理由、篇幅和暴露情况。路径相对于 `evals/tasksets/`，无需复制三份 v2 原件。哈希对解析后的 JSON 按键排序、紧凑分隔、`ensure_ascii=false` 和 UTF-8 序列化，再计算 SHA-256。文件格式和检出换行不改变身份，报告字符串及其他 JSON 值的变化会改变身份；它不是原文件字节哈希，也不能防止他人同时改写输入与清单。

协调者按给定来源核对预期；这些是作者提出的、仍需证据核查的判断。每次仅将一份引用的评审输入与另行冻结的评审系统指令交给新上下文。评审不能访问本说明、清单、文件名／题族编号、其他输入、仓库或设计对话。输入仅含 `brief`、`sources`、`rubric`、`reports`；结构检查拒绝额外元数据字段，但不能证明文字中没有线索。校验脚本不启动评审，也不实施上下文隔离。

## 真实采集前

调用前冻结清单、全部引用输入、评审系统指令（试点的 `JUDGE_SYSTEM`）、请求／允许的返回模型名称、上限、返回协议和采集顺序。顺序／随机种子另行冻结，不把同题三个版本放入同一上下文。保留全部首轮判断、原始返回、解析／身份失败、用量和耗时，不重试失败对照或选择有利顺序。[改进计划](../../../docs/improvement-plan.zh-CN.md)中至多五次接入调用单列：**本包每个评审模型另需 12 次评审请求**，无需作者生成，调用预算须独立冻结。本包未提供真实调用适配器或运行配置。

既核对偏好，也按来源核对其定位解释。要求两种标签顺序均识别已知错误，且不在相同有效稿件间编造实质差异。未解决判断、漏检、误报和基于来源的裁定分别保留。猜中 A/B 或模型一致都不足以通过。这些窄范围对照即使通过，也不能验证全部五维量表、证明评审普遍可靠或 Toolkit 有效。四个题族不是 12 个独立观察，复用、翻译和换模型重跑都不增加题族。公开对照用于调参后，泛化检查另需独立设计的新材料及明确暴露记录；不新增人工评审前提。

## 离线检查

```bash
python scripts/check_judge_calibration.py --self-test
```

在仓库根目录运行。只读检查覆盖哈希、共用输入、精确互换、平局、按语言计数及证据片段定位；损坏对照在临时副本中执行。调用模型零次，评审可靠性保持 `not_evaluated`；不能据此证明语义有效、任务独立或盲法成功。
