# 成对语义诊断

[English](README.md) | [简体中文](README.zh-CN.md)

`cases.json` 的原始六组错误／对照覆盖换词式套话、不相关证据绑定、分母偷换、过程痕迹与有效限制的区别、事后自称通过和合同层级遗漏。`additional-cases.json` 增加十四组，形成历史二十组目录，涉及时间与单位不符、过度因果推断、复制证据、遗漏成本、后续纠正、合理正向判断和严重性归并；英文材料也包含有实质细节的对照。原六组及其诊断记录保持不变。

[三组读者样本](reader-cases-2026-09-10.json)将当前视图扩至 23 组，检查开篇优先级、正文持续出现编辑过程口吻、时间线罗列而缺乏解释。每组提供实际读者要求、相近对照与合理不确定性；不建立禁词表、固定导语或洞察数量规则。

三组后来经过四模型独立上下文诊断，[保留修订](reader-revisions-2026-09-11.json)明确了单席位、单月收费口径。私人评审原文未公开，较早八次公开调用没有评过这三组。

## 证据边界

所有商业事实均为虚构。这是开发诊断片段，不是留出任务、完整报告或质量金标准。相关例子共享错误家族，23 组不等于 23 次独立真实任务观察。

标签是作者提出的诊断假设。语义评审由 LLM 承担，没有人工校准前提，判断仍须核对给定证据。[八次实际模型调用原件](reviews/2026-09-08/)保留二十组首轮评审、顺序与上下文敏感、两项更正的单独评审。两模型曾共同漏掉原拟正例的缺陷，标签一致不等于可用性。确定性 evaluator 的研究质量仍为 `not_evaluated`。

## 使用方法

```bash
python scripts/check_semantic_diagnostics.py
```

该命令检查结构及正反数据契约，不验证语义标签正确性。模型意见、分歧和修订单独保存。

1. 随机排列两段文本，向评审者提供证据，隐藏标签与解释，私下保留映射。
2. 要求定位具体主张、缺失条件或推理错误，说明证据真正允许的结论；保留分歧和限制。
3. 初次评审后再揭示拟定解释。模型诊断不等于产品效果测量。
4. 严重事实错误另记，结构和流程分不能抵消。
5. 保留有效对照：合理不确定性、有依据的负面决定、充分展开的正文、准确标注的阶段稿，不能仅因谨慎或未最终完成而判错。

这些例子帮助理解笼统自评通过、读者导航薄弱、过程表达和遗漏可逆转决定的比较等问题，不含私人原日志或真实公司。问句标题、合理限制、“不是……而是……”等句式本身不判错；判断需回到任务与整段表达。不能把评审训练成越谨慎越正确，也不能用 JSON 可解析证明评审能发现问题。
