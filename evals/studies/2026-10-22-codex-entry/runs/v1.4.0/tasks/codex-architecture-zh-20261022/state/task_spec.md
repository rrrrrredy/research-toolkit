# Research brief

## question

Codex 的一次任务如何执行，模型、Harness、客户端、工具、上下文、方法和执行环境如何配合；跨轮接续和长任务如何工作；哪些设计影响能力、成本与体验？

## audience

希望理解并设计 Agent 产品的中文读者

## scope

截至 2026-10-22，仅研究 inputs/sources.json 所列六份给定材料及其指定范围。区分本地 app-server、CLI 和托管 Agents API 的职责，不推广个别入口条件。禁止联网、其他 Agent、独立评审、测试套件；不修改 inputs 或 toolkit。

## output

中文 Markdown 报告，正文约 2000 字，无硬性最低字数，参考文献另列，包含一张有用的比较表。交付 final.md、不可覆盖的 first-draft.md、first-self-check.json 和 first-self-check-report.md，以及简短 revision-notes.md。记录与正文分离，保存真实 CLI 请求返回。

## depth

解释执行机制与产品取舍，以自主综合为主、短引文为辅。提纲：核心判断；单次任务链路；本地与托管职责比较；上下文和方法加载；跨轮与长任务；适用边界。

## evidence_standard

必读六份材料指定范围，登记实际阅读位置与来源支持的判断；文档描述、历史案例结果、作者推断明确区分。重要判断可追溯，不编造性能、可靠性、成本数字或闭源实现。Lite 仅完成一次正常作者自检及确有必要的修订，不追加检查轮次。
