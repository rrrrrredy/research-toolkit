# Codex 如何完成任务：执行架构与产品取舍

截至 2026 年 10 月 22 日的文档快照。

Codex 的能力来自模型、执行循环与产品环境的配合。模型根据上下文生成回答和行动请求；Harness（围绕模型的执行系统）管理会话、工具调用、反馈、权限与进度；客户端提供用户交互和业务上下文。工具连接文件、命令或业务服务，执行环境提供实际计算和文件空间。开放的是 Harness 及集成接口，模型访问与托管服务仍是独立层。[1]

**对 Agent 产品设计者，关键选择是把状态、执行和授权责任放在哪里。**同一模型接入不同工具、反馈与权限边界，能够完成的工作就会不同；这也是只比较模型回答质量不足以评价产品的原因。

以本地 app-server 为例，用户提出“修复导出错误”，客户端先完成连接初始化，再创建或恢复 Thread（会话），通过 `turn/start` 提交请求及工作目录等设置。一个 Turn 是该请求引发的一轮工作，内部包含消息、命令、文件修改等 Item；一轮工作可经历多次模型与工具交互。[2]

模型据上下文选择读取代码、修改文件或调用工具；Harness 组织执行，把输出带回循环，使模型能够根据错误继续修正。[1][5] 需要审批时，app-server 向客户端发送请求，客户端回传决定。消息和工具进度以事件流呈现，用户可追加指导或中断。客户端最终应读取 `turn/completed` 的状态，因为它也可能表示失败或中断。由此，产品界面需要表达“执行中、待授权、已失败”等状态，仅显示生成中的文字不足以说明任务进展。[2]

下面按同一职责维度比较入口；适用判断是基于文档的设计分析，并非性能排名。[1][6]

| 接入方式 | 循环与执行位置 | 应用承担什么、适合什么 |
|---|---|---|
| CLI／SDK | 调用 Codex；工具在配置的环境执行 | `codex exec` 适合有界脚本或 CI；SDK 便于程序化启动、恢复和流式接收任务 |
| 本地 app-server | 本地 Codex 进程提供循环与生命周期接口 | 应用掌握会话、事件和审批界面；适合深度交互，也增加状态处理责任 |
| Agents API，无环境 | OpenAI 托管 Harness；可用远程 MCP、应用函数工具 | 适合服务查询；无需另配工作区计算，但无内置 Bash、补丁工具及工作区文件 |
| Agents API，托管环境 | Harness 与沙箱由 OpenAI 管理 | 应用配置依赖、文件和网络，继续处理业务函数；适合文件与代码任务 |
| Agents API，自有环境 | Harness 仍在 OpenAI；executor 在自有环境执行 | 可接私网和定制软件；应用负责供给、重连、关闭和文件保留 |

托管 Harness 与托管计算是两个选择，`self_hosted` 在此指执行环境。函数工具仍需应用接收调用并返回结果；处理器不可用时，Agent 可能一直等待。事件处理和环境管理故障也会影响进展，因此托管并不消除应用端的可靠性责任。[6]

上下文也有加载取舍。Skill 把方法写成可复用的说明、资源与可选脚本：Codex 先看到名称、描述和路径，选用后再读取完整 `SKILL.md`；既可由用户显式指定，也可按描述匹配。初始目录默认最多占模型窗口的 2%，技能过多时会缩短描述，甚至省略部分条目；这一预算不限制被选中技能的正文。[3] 这种渐进加载减少无关方法的初始占用，却把发现质量交给描述与匹配。对必须执行的流程，产品可显式传入 skill 项，让服务器注入完整说明，减少名称解析的不确定性。[2] 方法说明影响模型行为，技术权限仍由执行控制决定。

沙箱限制“技术上能做什么”，审批策略决定“何时需要授权”。本地 CLI／IDE 的默认命令网络限制，不能推广成整个产品离线：搜索、连接器、MCP 和模型请求使用各自的连接与控制。旧版 Cloud 的两阶段执行及凭据规则也不能直接套用到当前 Cloud。[4] 这意味着产品应分别治理命令和业务工具。更严格的边界减少暴露面，也可能增加中断；自动审批可接手符合条件的请求，但保持沙箱边界，并增加模型调用与用量。文档没有给出它的额外延迟或误判率。[4]

跨轮接续需要区分三种状态。Thread 保存可恢复的会话历史；模型当下可见的历史可经过压缩；工作区文件保存实际产物。app-server 支持恢复、分叉和主动压缩，但 `thread/revert` 只撤销历史中的回合，不改变本地文件。[2] 因而，恢复对话不等于回滚工作，持久会话也不能证明模型一直看得到全部历史。设计上应把目标、约束、进度和验收条件保存为可重读工件，并协调会话与文件状态；压缩保留了哪些细节，给定文档没有证明。

长任务依赖反复执行“计划—修改—验证—观察—修复”，让工具结果纠正后续行动。OpenAI 作者的一次历史实验使用 GPT-5.3-Codex、Extra High 推理和完整访问权限，从空仓库构建设计工具，报告连续约 25 小时、约 1,300 万 token、约 3 万行代码；作者同时明确结果尚非生产就绪。[5] 实验把规格、计划、约束和状态写进 Markdown，按里程碑验证。这支持把持久工件与反馈循环作为设计候选，不能证明这些措施单独造成成功，更不能推成当前所有版本的可靠性承诺。

据此，产品应按工作需要配置自治程度：服务查询可先不配执行环境；文件任务再增加沙箱；需要私网或特殊软件时才承担自有环境的维护责任。长任务则把验收放在可观察的产物和阶段结果上。成本应同时考虑模型循环、自动审批、计算环境、等待与返工。现有材料没有可比账单或成功率，无法判定哪种入口更便宜，也不能从运行时长、token 或代码行数推出交付价值。
