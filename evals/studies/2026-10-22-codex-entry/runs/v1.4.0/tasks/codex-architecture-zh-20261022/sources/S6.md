L1: # Architecture
L2: 
L3: > For the complete documentation index, see [llms.txt](/llms.txt). Markdown versions of documentation pages are available by appending `.md` to the page URL.
L4: 
L5: OpenAI runs the agent harness. Your application sends it work and receives results. Add an environment when the agent needs compute or files.
L6: 
L7: ## The pieces
L8: 
L9: - **Harness:** The OpenAI-hosted Codex instance that runs the model and tool loop and maintains the agent's session.
L10: - **Environment:** Where the agent runs commands, executes code, and works with files. An environment can be a remote sandbox, your laptop, a Docker container, or an AWS Lambda function.
L11: - **Application server:** Your code that connects the agent to your product. It submits tasks, receives events, and handles function tools. When you provide the environment, your code also manages its lifecycle.
L12: 
L13: Start with the pieces your task needs. The harness can work without an environment, and your application can receive progress through streaming or webhooks.
L14: 
L15: ## Start without an environment
L16: 
L17: An agent that answers questions or uses tools to access external services may not need its own compute or files. Set `environment.type` to `none`. This fragment shows the environment setting. Session creation also needs an agent and initial input:
L18: 
L19: ```json
L20: {
L21:   "environment": {
L22:     "type": "none"
L23:   }
L24: }
L25: ```
L26: 
L27: Your application sends input to a session. The harness calls the model, uses the configured tools, and returns results. OpenAI maintains the session for later work.
L28: 
L29: The harness can call remote MCP tools directly. For [function tools](https://developers.openai.com/api/docs/guides/agents-api/tools/functions), your code receives each call, runs the function, and returns its result.
L30: 
L31: Without an environment, the built-in Bash and apply-patch tools, workspace files, and executor MCPs are unavailable.

L50: ## Add an OpenAI-hosted environment
L51: 
L52: When the agent needs to run scripts, edit files, or create artifacts, set `environment.type` to `openai_hosted`. OpenAI creates and manages a sandbox for the session.
L53: 
L54: You configure the packages, files, and network access the agent needs. The harness runs commands in the sandbox directly. Your application continues to send tasks, receive events, and handle any function tools.

L75: ## Connect your own environment
L76: 
L77: Use `environment.type: "self_hosted"` when the agent needs your infrastructure, private network, or custom software.
L78: 
L79: Your code starts the environment and connects an executor to the session. The executor runs the commands and tools that the harness requests. Your application manages the connection and lifecycle without forwarding each command.
L80: 
L81: You own provisioning, reconnection, shutdown, and any files you need to preserve. Your application server or a webhook handler can manage this work.

L102: ## Receive progress and results
L103: 
L104: With any environment choice, you can use either or both of these:
L105: 
L106: - **Streaming:** Receive detailed events as the agent works, such as output to display in your product.
L107: - **Webhooks:** Receive session state changes without keeping a stream open. Your handler can retrieve results, run function tools, or manage a self-hosted environment.
L108: 
L109: Function tools need a handler that receives calls and returns results. If that handler is unavailable, the agent can remain waiting for a result. Failures in your event or lifecycle handlers can also interrupt progress updates or environment management.
L110: 
L111: See [Session events](https://developers.openai.com/api/docs/guides/agents-api/sessions) and [Webhooks](https://developers.openai.com/api/docs/guides/agents-api/sessions/webhooks) for integration details.
