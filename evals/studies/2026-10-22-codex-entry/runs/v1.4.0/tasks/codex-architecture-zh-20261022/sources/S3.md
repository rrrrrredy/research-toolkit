L5: Use agent skills to extend ChatGPT and Codex with task-specific capabilities. A
L6: skill packages instructions, resources, and optional scripts so either product
L7: can follow a workflow reliably. Skills build on the
L8: [open agent skills standard](https://agentskills.io).
L9: 
L10: Skills are the authoring format for reusable workflows. Plugins distribute
L11: reusable skills and connectors through the universal plugin directory shared
L12: by ChatGPT and Codex. Plugins work in Chat and Work across ChatGPT on the web,
L13: desktop, and mobile, in Codex in the ChatGPT desktop app, and through Codex
L14: CLI. Use skills to design the workflow itself, then package it as a
L15: [plugin](https://developers.openai.com/plugins/build/plugins) when you want
L16: other people to install it.
L17: 
L18: Standalone skills are available in the ChatGPT desktop app, Codex CLI, and IDE
L19: extension. Skills bundled in plugins are also available in Chat and Work across
L20: ChatGPT on the web, desktop, and mobile.
L21: 
L22: In the ChatGPT desktop app, open **Skills** in the sidebar to view and explore skills
L23: created across your projects.

L33: Skills use **progressive disclosure** to manage context efficiently. ChatGPT and
L34: Codex start with each skill's name and description, then load the full
L35: `SKILL.md` instructions when they decide to use that skill.
L36: 
L37: In Codex, the initial list also includes each skill's file path. By default,
L38: this list uses at most 2% of the model's
L39: context window, or 8,000 characters when the context window is unknown. If many
L40: skills are installed, Codex shortens skill descriptions first. For large skill
L41: sets, Codex may omit some skills from the initial list and show a warning.
L42: 
L43: Use [`skills.max_context_tokens`](https://learn.chatgpt.com/docs/config-file/config-reference) to set a
L44: different budget, up to 10,000 tokens.
L45: 
L46: This budget applies only to the initial skills list. When Codex selects a skill, it still reads the full SKILL.md instructions for that skill.
L47: 
L48: A skill is a directory with a `SKILL.md` file plus optional scripts and references. The `SKILL.md` file must include `name` and `description`.
L91: ## How ChatGPT and Codex use skills
L92: 
L93: ChatGPT and Codex can activate skills in two ways:
L94: 
L95: 1. **Explicit invocation:** Include the skill directly in your prompt. In
L96:    ChatGPT, type `@` to select a skill. In Codex CLI or the IDE extension, run
L97:    `/skills` or type `$` to mention a skill.
L98: 2. **Implicit invocation:** ChatGPT or Codex can choose a skill when your task
L99:    matches the skill `description`.
L100: 
L101: Because implicit matching depends on `description`, write concise descriptions
L102: with clear scope and boundaries. Front-load the key use case and trigger words
L103: so a host can still match the skill if descriptions are shortened.

L136: ## Where Codex loads local skills
L137: 
L138: Codex reads skills from repository, user, admin, and system locations. For repositories, Codex scans `.agents/skills` in every directory from your current working directory up to the repository root. If two skills share the same `name`, Codex doesn't merge them; both can appear in skill selectors.
L139: 
L140: | Skill Scope | Location                                                                                                  | Suggested use                                                                                                                                                                                        |
L141: | :---------- | :-------------------------------------------------------------------------------------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
L142: | `REPO`      | `$CWD/.agents/skills` <br /> Current working directory: where you launch Codex.                           | If you're in a repository or code environment, teams can check in skills relevant to a working folder. For example, skills only relevant to a microservice or a module.                              |
L143: | `REPO`      | `$CWD/../.agents/skills` <br /> A folder above CWD when you launch Codex inside a Git repository.         | If you're in a repository with nested folders, organizations can check in skills relevant to a shared area in a parent folder.                                                                       |
L144: | `REPO`      | `$REPO_ROOT/.agents/skills` <br /> The topmost root folder when you launch Codex inside a Git repository. | If you're in a repository with nested folders, organizations can check in skills relevant to everyone using the repository. These serve as root skills available to any subfolder in the repository. |
L145: | `USER`      | `$HOME/.agents/skills` <br /> Any skills checked into the user's personal folder.                         | Use to curate skills relevant to a user that apply to any repository the user may work in.                                                                                                           |
L146: | `ADMIN`     | `/etc/codex/skills` <br /> Any skills checked into the machine or container in a shared, system location. | Use for SDK scripts, automation, and for checking in default admin skills available to each user on the machine.                                                                                     |
L147: | `SYSTEM`    | Bundled with Codex by OpenAI.                                                                             | Useful skills relevant to a broad audience such as the skill-creator and plan skills. Available to everyone when they start Codex.                                                                   |
L148: 
L149: Codex supports symlinked skill folders and follows the symlink target when scanning these locations.
L150: 
L151: These locations are for authoring and local discovery. When you want to
L152: distribute reusable skills beyond a single repo, or optionally bundle them with
L153: connectors, use [plugins](https://developers.openai.com/plugins/build/plugins).
L154: 
L155: ## Distribute skills with plugins
L156: 
L157: Direct skill folders are best for local authoring and repo-scoped workflows. If
L158: you want to distribute a reusable skill, bundle two or more skills together, or
L159: ship a skill alongside a connector, package them as a
L160: [plugin](https://developers.openai.com/plugins/build/plugins).
L161: 
L162: Plugins can include one or more skills. They can also optionally bundle
L163: registered MCP server connections, bundled MCP server configuration, and
L164: presentation assets in a single package.

L220: ## Best practices
L221: 
L222: - Keep each skill focused on one job.
L223: - Prefer instructions over scripts unless you need deterministic behavior or external tooling.
L224: - Write imperative steps with explicit inputs and outputs.
L225: - Test prompts against the skill description to confirm the right trigger behavior.
