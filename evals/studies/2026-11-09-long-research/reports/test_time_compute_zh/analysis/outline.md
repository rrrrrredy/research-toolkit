# 推理时计算中文独立研究提纲

资料截止：2026-11-09。仅使用 frozen-alternate-inputs/test_time_compute_zh 的 20 份原件；不读取英文稿或其他任务成果。当前作者为本会话 Codex，未调用 Astra API。

面向需要分配推理预算的模型研究者、推理工程师和 Agent 系统设计者。问题是有限预算应如何换成可交付成功率，增加计算何时失效；不预设扩展规律成立。

1. **决定预算前先区分三个问题**：候选中是否出现正确解、是否能选出正确解、执行能否可靠完成。固定模型推理策略比较与模型/后训练/验证器同时改变的系统比较分组。定义 pass@k 与重复成功的区别。
2. **计算究竟花在哪里**：独立采样、自一致性、best-of-N；顺序修订；中间状态搜索；结果和过程评价；自适应预算；工具 Agent 循环。方法矩阵明确生成者、状态保留、淘汰规则、评价信息、训练前提与成本。主要原件：TTC001、TTC009、TTC011–013、SUP-SELF、SUP-AC、SUP-TREE。
3. **数学任务揭示的扩展条件**：从候选覆盖到真实选择，难度分层与固定模型预算最优；长思考/训练的关系；饱和、过度思考、错误相关与评价器失真。主要原件：TTC001–008、TTC003v2、TTC010、TTC012、SUP-LIMITS。保留版本差异、样本量和不确定性缺口。
4. **代码与多步骤工具任务为何不同**：代码可执行验证的边界；CodeMonkeys 测试生成/编辑/选择成本；WebArena 搜索状态与回退；tau-bench 数据库终态、用户和政策约束与重复可靠性。主要原件：SUP-CM、SUP-TREE、SUP-TAU、TTC010、TTC013。不得把数学收益直接迁移为含糊任务的保证。
5. **可比较预算与实际运行的说明性算例**：候选及丢弃分支、评价器、推理 token、工具执行/重试全部计入；成本、串行关键路径、并发容量、端到端耗时分开。不同模型 token 不直接等价。用明确假设编写并运行纯 Python 算例，比较宽采样、验证加强、顺序修订、强模型；不称复现或新实验。
6. **把证据转为设计决策树**：可验证性、错误后果、时延、状态可回退性和预算依次分流；何时加强模型、增加采样/搜索、改善验证器、减少步骤或停止。已观察结果与本文设计建议分别标明，列出会改变建议的观测。
