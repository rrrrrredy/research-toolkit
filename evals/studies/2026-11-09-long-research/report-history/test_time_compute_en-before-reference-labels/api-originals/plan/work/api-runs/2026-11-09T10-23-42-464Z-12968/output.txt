最终报告使用英文，服务于需要决定模型、推理策略、验证方式和资源预算的模型研究者、推理工程师、agent 系统设计者。研究重点是可实施的计算分配决策，不是论文目录或模型排行榜。\n- 时间范围以首次公开于 2022 年至 2026-11-09 的工作为主；较早研究仅用于必要基础。每项结果绑定论文版本、模型 及其蒸馏模型、OpenAI、Google、Anthropic 和相关 agent 实现；不要求穷举综述参考文献中的全部模型。\n- 建议最终英文正文约 10,000–14,000 words，另配证据矩阵、计算附录和来源说明；这是研究者的篇幅规划，不是用户新增要求。\n\n## 2. 必须回答的问题与候选解释\n### Q1. 更多计算究竟改变了什么？\n区分扩大正确候选覆盖率、提高选择准确率、修正已有轨迹、获取外部信息、改变环境状态和更新模型参数。候选解释 H1：部分看似相互矛盾的 scaling 结果来自不同被测对象和不同反馈权限，而非同一种方法在相同条件下发生冲突。需要逐项控制比较，不能先当作结论。\n\n### Q2. 何时应增加样本，何时应增加深度或验证？\n候选解释 H2：收益取决于基础模型对该任务的可达解概率、错误答案的集中程度和验证器在候选池上端的辨别能力，而不只取决于题目被标成容易或困难。最难任务未必值得最多预算；但有限次采样没有成功也不能证明真实成功概率为零。\n\n### Q3. 顺序推理的提升来自推理分配还是训练？\n候选解释 H3：训练可以改变模型使用额外 token、修订历史和反馈的能力；因此 s1 与其未微调基座之间的差异，不能归因于 sequential scaling 本身。TTC001 的修订模型也经过专项训练。应分别报告同 checkpoint 的预算曲线和跨 checkpoint 的系统比较。参见 TTC001 §§4–6、TTC002 §§2–5。([arxiv.org](https://arxiv.org/html/2408.03314v1))\n\n### Q4. 为什么更多计算可能饱和或倒退？\n并列检验正确解覆盖不足、共同错误、验证器尾部误判、奖励投机、错误剪枝、正确答案被覆盖、上下文上限、强制续写干预、工具故障和环境动作累积错误。不得把所有下降统称为 overthinking，也不得把自然长回答与低准确率的相关性直接解释为长度的因果作用。\n\n### Q5. 自适应是否真的节约预算？\n候选解释 H4：难度识别、预热、验证和停止信号可能耗掉标称节约；离线删除已生成轨迹不等于在线节约生成。TTC001 明确未计入每题 2,048 次采样的难度估计成本；TTC007 的 frontier 使用完整测量曲线，且主要成本只计保留的 thinking tokens。([arxiv.org](https://arxiv.org/html/2408.03314v1))\n\n### Q6. 可检查任务上的收益能否转移到交互式任务？\n候选解释 H5：代码执行、网页观察或检索可能带来新信息，而不是单纯增加内部计算；可重置的沙箱搜索与不可逆真实行动也不是同一决策问题。评估标准能离线判分，并不意味着部署时有可用验证器。工具任务必须覆盖完整执行链，而不能只用数学终局答案选择代替。\n\n### Q7. 所谓 verifier-free 是否意味着没有验证或训练？\nTTC005 不使用目标题验证器训练，但使用合成题执行奖励，并在测试时更新 LoRA 参数。候选解释 H6：其收益来自目标条件化适配，而非固定权重模型在完全无反馈条件下的搜索突破；需要单列预算与指标，而不是并入固定基座推理曲线。([arxiv.org](https://arxiv.org/html/2611.07367v1))\n\n### Q8. 什么情况下不增加推理计算？\n拟比较直接回答、确定性程序、一次执行、升级基础模型、请求澄清、人工接管和弃答。是否停止应由可测的增量效用、错误后果、预算及延迟约束决定；不是默认用满预算，也不是以一次置信度分数替代风险判断。\n\n## 3. 最终英文报告的论证结构\n### 1. Decision context and evidence contract\n解释读者的实际决策、证据截止日、研究选择原则和比较层级。定义五种不同结果：单次正确率、候选覆盖率 pass@N、实际提交答案正确率、重复可靠性 pass^k、包含成本与错误损失的效用。说明 benchmark grading 与 inference-time verification 的权限差异。\n\n### 2. Where additional computation enters the system\n建立机制图：生成 → 状态保留 → 评估 → 选择/剪枝/修订 → 停止 → 提交；工具反馈与权重更新作为独立分支。\n- 独立采样本身不规定最终答案如何产生。\n- Self-consistency 对答案分组投票；best-of-N 按分数选择，weighted best-of-N 另列。\n- 顺序修订、单条长推理、前缀树搜索、环境树搜索不混为一类。\n- Outcome labels、过程正确性标签、continuation value、自然语言批评和程序执行结果分别说明语义。\n- 对每种机制回答：谁产生候选，谁拒绝候选，保留什么状态，评估器看到哪些信息，是否修改权重。\n\n**产物 A：Method-and-evidence matrix。** 每行包括算法、基座与验证器版本、训练前提、候选单位、状态、反馈权限、停止规则、任务与数据版本、比较对象、成本边界、局限和证据等级。\n\n### 3. Sampling and selection: finding an answer is not submitting it\n以 self-consistency、Large Language Monkeys、验证器研究和 SPLIT 为核心，解释覆盖曲线与部署曲线为何分离。推导独立条件下的覆盖公式、任务异质性的影响、有限候选池估计与实际选择的区别。分别处理题间难度相关、模型间共同盲点、题内候选依赖及同一候选的重复判断相关。\n\n### 4. Sequential reasoning, revision, and the training that enables them\n拆分 s1 的 SFT 效果与同一 s1 checkpoint 的 budget forcing 效果；比较训练过的修订、未经训练的自我批评和带外部反馈的修订。分析保留旧答案、重新选择与直接返回最后一稿的差异。将测试时参数更新作为边界案例，与离线后训练和固定权重推理分配区分。\n\n### 5. Search over intermediate states and investment in verification\n比较 best-of-N、beam/best-first、lookahead、MCTS 类方法与过程反馈。解释步骤价值、最终正确性和局部推导正确性为何不可互换。检查搜索改变候选分布、验证器失配与错误剪枝；不把更强优化器或更大搜索树预设为更有效。\n\n### 6. Executable coding and feedback-driven agents\n- 代码生成：公开样例、生成测试、私有测试、扩展测试和形式检查分别列出权限与不完备性。\n- 软件工程：CodeMonkeys 的测试、编辑和选择循环；将并行轨迹数与轨迹内迭代分开。\n- 网页与多步工具任务：环境搜索、状态回退、重置成本和部分可观察性。\n- 用户交互：τ-bench 的重复可靠性与终局判分边界。\n- 检索和深研究：DeepVerifier 作为较弱、间接反馈的转移案例，核查最终评分独立性和全部验证成本。\n- 最新补充：2026-11-06 的 parallel agent teams 工作作为有评分器的长时任务案例，不将其 expected-best continuous score 直接等同于普通任务成功率。([arxiv.org](https://arxiv.org/html/2611.09798v1))\n\n### 7. What reported scaling curves do—and do not—establish\n按可比较的实验族分面展示，而不拼接一条跨模型 token scaling law。\n**产物 B：Reported scaling comparison。** 标记预算轴、基座是否固定、选择成本是否完整、反馈权限、边际增益、饱和/倒退区间、难度分层、样本量与不确定性。\n- 分开预算干预、自然长度分组、固定前缀 probing、oracle 终止和实际在线终止。\n- 不预设幂律、对数律或普遍单调性。\n- 对 TTC006 的数值一致性问题先核对再纳入；不能以其定量阈值制定部署规则。\n\n### 8. A complete budget ledger and a worked allocation example\n**产物 C：成本与调度账本。** 计入生成、废弃分支、prompt/prefill、显式及已披露隐藏推理、验证器输入与生成、工具、重试、环境设置/恢复及控制器。训练、pilot 和部署成本分账，说明摊销范围。\n分别报告 FLOPs 或其有条件代理、货币费用、GPU/CPU 时间、峰值并行资源、串行关键路径和端到端 wall-clock。不能把不同模型的 token 当作公共计算单位。\n**产物 D：Worked allocation example。** 使用明确标为假设的生成成功率、验证器 TPR/FPR、单次费用和并发约束，比较更多样本、较好验证器、较强模型及不追加计算；给出敏感性分析，不称为新实验。\n\n### 9. Synthesis and unresolved boundaries\n由正文证据回答何时选择更强基座、更多样本、更深搜索、更好验证或更简单路径。分开实证发现、条件性推论与研究者提出的部署政策。列出尚不能由公开证据支持的跨域转移和经济比较，不以泛泛免责声明代替答案。\n\n## 4. 证据筛选与决定性前提\n- TTC001–TTC008 的用户提供文本均已通读，包括附录、表格和图注；文本中仅有图像占位符的部分，不声称看过曲线原图或完成了数据数字化。\n- 新补充原件只登记实际打开并阅读的章节。TTC006 的 PDF 第 4、10 页还进行了截图核对。\n- 优先采用同 checkpoint、同任务、明确反馈权限和成本边界的对照；跨模型结果保留，但降低因果归因强度。综述 TTC004 用于检索导航与术语辨析，不代替原始实验证据。\n- 必须先解决的门槛：TTC006 的分母、flip 计数和 utility 算术；TTC005 的 filtered mean@8 与 carry-forward；TTC007 的 oracle 信息与 probe 成本；TTC008 的条件独立假设和成本代理；TTC003 的版本及研究库存/公开发布数量。\n- TTC003 已补读 2026-08-31 的 v2 相关章节。其研究库存与公开发布数量分列，不能继续沿用 v1 摘要中的巨大 trace 数量。([arxiv.org](https://arxiv.org/html/2608.04001v2))\n\n## 5. 分工、依赖和审查安排\n- U1 先给出共享协议、来源版本和争议台账；U2–U6 随后可并行开展完整局部分析。未解决的争议只冻结受影响主张，不阻塞其他分支。\n- U7 消费各机制和任务单元的调用账本；U8 消费实证曲线及 U7 的成本模型；U9 由主研究者统一整合论证、矩阵和决策树。\n- 在大篇幅写作前，分别安排独立 requirements 与 structure_and_depth 会话检查本提纲。决定性统计、成本和环境反馈前提交由非作者的 evidence 与领域审查者核验。\n- 完整报告阶段仍须完成七个独立基础视角：requirements、evidence、adversarial_reasoning、structure_and_depth、reader_usefulness、process_language、natural_expression；另设推理系统/统计评估及 agent 环境领域审查。独立 audit 与最终 acceptance 再分别进行。局部检查不替代整篇审查。\n- 本轮没有启动子代理、完成独立审稿或重跑模型评测；角色与依赖均为执行计划，不是已经完成的会话记录。\n\n## 6. 状态与最终产物安排\n保留 task.json 要求的 state/task_spec.md、state/progress.json、state/requirements.jsonl、data/source_registry.csv、data/claims_registry.csv、logs/review.jsonl、state/final_delivery.json、final.md、delivery_message.md。当前 JSON 是阶段设计记录，未创建这些磁盘文件，未生成 finish 收据，也不将最终交付标为完成。最终验收须将每项要求映射到实际正文或表格、核查关键来源与计算、解决必要修订，并绑定同一最终版本。",
