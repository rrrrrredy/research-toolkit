# 一项真实长任务：原生 Agent 与 Toolkit Full

[English](README.md) | [简体中文](README.zh-CN.md)

**本题没有观察到 Toolkit 的正文质量净增益；Full 增加了实际耗时和操作。** 两组首稿、终稿分别由单独上下文的 Astra 匿名评审，两次均判平局、两篇均通过。额外流程不能算作质量提升。运行也发现了一个实际 Windows CLI 编码错误，已据此修复并针对性复验。

## 任务与运行

沿用已有真实独立任务[“编程智能体的排行榜能支持什么采购判断？”](../2026-10-13-before-after/protocol.json)：比较 SWE-bench Verified、SWE-Bench Pro、SWE-Lancer 的对象、环境、评分和版本，结合 2026 年 7 月质量质疑提出采购与内部试点方案；交付 2500–4000 个非空白字符的完整中文备忘录。此次是同题的新配对运行，不新增两个研究问题。

两组使用相同的 Astra、xhigh、Codex CLI 0.162.0-alpha.17.2、四个起始网址、实时网页检索和本地工具权限；从新会话读取题目，自行检索、打开原始资料、计算、写稿和自查。没有提供预写正文或固定来源摘要，也没有限制原生组正常自查。原生组不读取 Toolkit；另一组从公开 `SKILL.md` 开始，运行 Full、`reviewer=self`，维护自己的任务记录并完成交付。统一的独立盲评在作者阶段之外进行，两组都不冒充已获得独立评审。

Toolkit 固定于 `09c8e7cd5c394eea4972c0ff6fd5fcd78c18db5c`（PR #52）。后续编码修复没有回填这次作者运行。作者会话并发执行，延迟是本次实测，不是重复测量后的性能估计。[冻结协议](protocol.json)、[实际命令和会话记录](execution/)、[执行驱动存档](execution-code/)。

具体差别比满分更有解释力：Toolkit 更充分讨论 Pro V2 的执行协议、HARD-51 选择效应、有效替代解和不完整补丁的双向验证；原生组用具体 OpenLibrary 题号解释评分错误，区分历史回放、封存确认和新增任务随机对照。两篇都查到了 Pro V2 与 Lancer 离线子集变化，都没有把旧版缺陷比例套给新版，或把历史奖金换算为企业收益。Astra 认为优势互有侧重，不构成整体优劣。

原生组自查补全 Diamond 组成、澄清 V2 推荐协议和价格解释，并明确试点分母；Toolkit 自查细化含失败重试的成本指标、分层随机分配及论文定位。这些是实际正文修订，但原生组同样完成了修订，不能全归因于 Toolkit。两次盲评没有必要修正项，因此没有再改稿求胜或重跑求通过。五维量表在本例达到顶端，100 分也不代表所有可能缺陷均已排除。

## 发现如何转成产品修复

Toolkit 作者在输出包含原始网页引用字符的 self 评审材料时，实际遇到 `UnicodeEncodeError: 'gbk' codec can't encode character '\ue200'`，随后通过进程 UTF-8 设置恢复。它还自行处理了 pending 篇幅记录及尚未创建的输出目录；这些真实摩擦均保留，未计成正文质量失败。

共享 CLI 现主动使用 UTF-8 读写 JSON。用本次实际抓取的 Scale 来源，在隔离工作区对旧脚本和修复脚本施加相同 GBK 管道条件：旧版退出 1，修复版退出 0，保留引用字符并返回完整 self 输入。[复现结果](encoding-replay.json)。已有草稿契约测试新增真实 CLI 编码回归；没有改变研究门槛或要求重跑未受影响的正文。

本题两组稿件均使用公开 Markdown 来源链接，未触发需要作者处理的引用残留提示；不能据此声称已观察到“收到提示后修好引用”的分支。此前已合并的 PR #52 覆盖该提示的已知格式与代码示例，并在 Linux、Windows 云端实际执行文件符号链接回归；Windows 17 项构建测试无跳过。

## 结论与复核

就这个完整原生 Agent 对照，不能推荐仅为提高正文质量而增加 Full 步骤。Full 额外留下了来源、主张、评审输入和交付版本记录；它们对后续交接、更新是否节省时间，本题没有测量。这个结果只针对一个任务、当前模型和 Full/self，不代表 Lite、其他模型、任务或后续接续的总体效果，也不成为发布门槛。

公开包包含全文、修订记录、原始判断、用量、命令及检索元数据、准确哈希和输入清单。原始抓取页面、完整送评请求和工具输出保留在本地捕获目录；仓库用来源绑定、访问元数据和原始哈希记录这些输入，不重复分发整页第三方正文。公开事件规范化本机路径，以哈希替代命令长正文及工具输出，省略 reasoning 项；汇总记录导出规则及原始/公开哈希。CLI 型号字段区分请求型号与未返回的型号证明。

`python evals/studies/2026-10-14-native-agent/verify.py` 只复核公开文件、版本绑定、真实事件用量和汇总一致性，不调用模型，也不替代语义评审。驱动是此次执行代码存档，复跑需配置本机运行路径与登录；复跑仍是同题重复执行。
