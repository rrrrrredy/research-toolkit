# 研究取舍示范：两组正文对照

[English](README.md) | [简体中文](README.zh-CN.md)

**新增示范后的正文出现了局部增量，也出现了遗漏；本轮没有观察到整篇全面更好或实质返工减少。** 档案数字化新稿补出了许可议价的价格依据，但另一项节时门槛没有解释可达性，还漏写试用劳动受预算约束。冷链新稿把试验余量与救援时间的关系解释得更清楚；两稿仍须明确“本季可交付”不等于“下周能交车”。具体依据见下表和原始匿名审阅，不设综合分数。

此次保留三组示范，作为现有写作方法中的按需参考。保留的依据是实际正文中出现了有用的成本推导和机制解释；它们的整组加入并没有消除遗漏。对无关营销材料的排除，两版本来都做到了。不能从这两次成对观察分别证明每组示范有效，也不据此继续增添规则或试题。

## 改动与材料

基线：`8e3db9db49aeda63bc9c3b1790da7702f8b66649`，v1.4.8。本次只在中英文 `references/writing-style.*` 中加入三组“问题与材料—原稿不足—正文改写—取舍理由”，并同步插件副本。研究入口、工具、字段、交付门槛、评审配置均未改变。

1. 预测性维护：保留停机减少的观察，补足归因、经济价值与多年预付之间的推理。
2. Scope-3 RFQ：删去重复的写作说教，把正文用于材料是否适合本次买方问题。
3. Maple 存储采购：以明确标注的构造补充要求演示局部改判，保留仍成立的分析。

前两组是公开归档原稿与修订稿的教学改写；第三组的后续要求为本次构造。原案例材料均为合成材料，不是现实企业事实；原报告与历史记录未改动。自由写作允许不同结构和措辞，示范中的结论仍受问题和证据约束。参考帖子、七张图片及既有方法的核对范围见[阅读记录](reference-reading.md)。

## 本次比较实际执行了什么

- 两个新构造任务：县档案馆数字化采购与分工、食品合作社冷链配送决策修订。它们没有出现在示范中，也没有向作者提供目标终稿；冷链输入中的原简报是待修订对象，不是新要求下的答案。
- 固定 `gpt-6-astra`、`high`、`default` 服务层，以及任务、材料和其余方法。CLI 未暴露或指定生成温度与随机种子，均沿用同一服务默认值；不声称逐 token 可重现。
- 每题改动前后各生成一次，共 **4 次作者调用**。顺序分别为前→后、后→前。新上下文中直接提供固定的共同方法和对应写作方法；没有联网、工具调用、追问、作者返修或重试。任务未要求另交自检，因此没有虚构自检记录。
- 每对正文由同一模型在一个新的上下文中审阅，共 **2 次匿名审阅调用**。输入只有任务材料、编号正文及段落比较要求，没有方法、版本、时间或预期胜方；没有追加评审层。
- A/B 标签在运行前按固定种子打乱，两个任务恰好都是 A=改动后、B=改动前。映射保存在[解盲表](coordinator-map.json)，没有进入审阅请求。维护者随后对照原材料核查审阅意见；维护者自己的分析不是盲评。
- 共 **2 个任务、4 份首个输出、2 份首次审阅，6 次 CLI 模型调用**。每次均只返回一份正文/审阅，进程退出码为 0。CLI 事件中未观察到工具调用或生成重试；没有网络层重试遥测，6 不是独立 HTTP 请求的测量值。

这些是对固定材料执行的研究生成与修订任务，不是只选择候选段落。此次观察的是加入整组三个示范后的输出差异；不测量自然任务中的方法加载、不隔离单个示范效果，也不评价整个 Toolkit 的普遍收益。

## 逐段观察

编号来自匿名审阅输入：[档案 A](reviews/archive-digitization/A.md)、[档案 B](reviews/archive-digitization/B.md)、[冷链 A](reviews/cold-chain-revision/A.md)、[冷链 B](reviews/cold-chain-revision/B.md)。A 为改动后，B 为改动前。

| 任务与段落 | 实际差异 | 判断与仍需修改 |
| --- | --- | --- |
| 档案 A08 / B07 | B 说节时须覆盖许可；A 算出当前印刷表节时约 106.7 小时，对应许可费约 1.07 万元才接近持平。 | 有用的议价依据，属于具体推导增量；并未改变暂不采购的建议。 |
| 档案 A08 | A 另说维持 4 万元报价至少要省 400 小时，却未说明仅印刷表全人工也只需约 213.3 小时。 | 算式本身没错，但在当前仅替代印刷表的范围内不可达。须补清适用范围，不能让读者以为仅提高印刷表速度即可达到。 |
| 档案 A08 / B07 | B 明确试用劳动也计入本季预算，并要求可比较的原件与分类错误记录；A 只明确免新增许可费、记录全部工时。 | 新稿遗漏执行限定。须补回验证人工的预算约束及可比较的输入；A05 对熟练度、代表性的限制也比 B04 笼统。 |
| 档案 A07 / B02、B06 | A 用 640 小时作为计划起点、按首批实际工时修正；B 先说两个点估计不是确定区间，后又写按 613—640 小时安排。 | A 的落实办法更清楚；B 应消除区间用法的歧义。两稿都还需落实实际可投入人力。 |
| 档案 A02、A04—A06 / B02—B05 | 两版都补回漏记的 14 小时，按材料类别比较完整成本，区分字符正确率与关键字段页错误率，不把混杂批次当作因果证据。 | 核心选择和主要计算没有增量。表格代替段落也不自动算改善。 |
| 冷链 A02、A04 / B01、B02 | A 更明确旧选择在旧要求下成立，降价没有改变性能；B 也已正确连接新订单、新报价与同配置旧试验。 | 解释更显式，但不能把 B 已有的正确修订判断算成新增能力。 |
| 冷链 A05—A06 / B05—B06 | A 解释试验多出的 1 小时不能直接当作故障救援窗口，等待和转运会消耗温控余量；执行建议中保留转运温控。 | 有具体机制增量。B 没有作出错误保证，但解释较少。 |
| 冷链 A06 / B06 | B 明确提出本路线备用车到场时限及违约处理，A 只笼统要求写清调度与责任。 | 新稿应补回与新宣传附页对应的具体缺口。 |
| 冷链 A01、A06 / B01、B06 | 输入只确认本季可交付，未保证下周到车；A 首段“同时满足这些要求”容易连下周时点也概括进去，B 也未在首段明确分开。 | 两稿应区分可以选型与尚待落实的具体交车日期。无需因此推翻已成立的容量、报价和温控比较。 |
| 冷链 B02；两题营销材料 | B 的“不能接受无限增长订单”无助于当前 76 箱问题，A 未加入这一提醒；两版都排除奖项、语言数等无关卖点。 | 前者是少量删减差异；后者没有新增收益。未见把示范中的公司、数值或结论搬进新任务。 |

原始审阅：[档案](reviews/archive-digitization/output.md)、[冷链](reviews/cold-chain-revision/output.md)。维护者核对后保留上述结论，特别是 400 小时的范围问题和具体交付日期的问题。表中是使用前的实质修改项，不是已经完成的人工修稿；没有计量人工返工时间，也没有把项数相加当作收益评分。四份首稿保持原样，没有按审阅意见改稿后再当作生成成绩。

首次档案基线调用记录了模型目录刷新超时，但生成成功；所有调用保留了 PowerShell 不支持 shell snapshot 和未稳定特性提示。警告不是额外生成次数，也未删除。单次耗时受服务波动影响，不能把两三秒差异归因为方法效果。
